## 3. 执行契约

### 3.1 晚报与新机会发现

标题筛选→阅读理解及必要补查→有价值消息/公司组合→公司整理交付，不把每个业务判断拆成一次调用。标题保留不等于推荐；事件可以正常以背景、放弃、无池内公司收口。晚报30是上限，0合法；晨报保持既有不额外加30家上限的口径。

**B90公司结论**：必要字段为`companyCode`、`recommendation: recommend|pending|exclude`、`analysisText`、`sourceRefs`及既有证据披露；自然正文解释消息价值、公司联系/推断与未知，不要求小标题、固定段落、最少字数。仅召回但没有关系的公司不用逐一填排除表。

- 不再要求模型填写rank、priorityReason、gap、rankChangeConditions、twoDayReason等重复文本换取推荐资格。新契约的解析、结果对象、验证器、持久化和消费一起改，不用空串/复制正文填满旧必填字段，也不只改prompt。
- 程序维护ID、序号、状态，验证池内身份、真实可见引用、事实及关系依据和状态一致性；不从分数、概念词或长度推导推荐。合理间接传导允许，未核实事实仍披露，反证不遗漏。
- 首次无旧机会、精确同催化同阶段身份继续本地判定；歧义旧身份和冻结事实进入同次事件研究，由该轮返回必要identity（kind、需要时relatedOpportunityId、自然理由），取消研究后逐公司串行classify请求。identity不再次审批推荐。
- 新旧催化、实质阶段、反证验证继续遵守固定身份规则；缺必要身份只影响该组合，不新开旧D1/D2窗口，不补造新增事实。旧结果shape只读/精确回执验证，不成为新任务路径。
- 保留本地公司字段、受控原文、问题绑定搜索/核验。资料足够可直接收口，无“必须补查N次”，无新增评分/策略默认值。

**最终整理**：输入一家公司一组所有可考虑催化，带canonicalKey/stageKey、完整analysisText、事实/推断披露、来源及身份；不只传代表摘要。返回有序`choices:[{companyCode,catalystKeys:[{canonicalKey,stageKey}]}]`，可省略公司或其中弱催化，显式`choices:[]`正常完成。

选中公司至少一条有效催化；按choices顺序生成展示rank。重复可折叠，未知引用不能成为事实；非空无效回复不能清洗成“正常零推荐”。未选组合保留研究记录，不形成正式卡片、选择或样本，也不是未执行缺口。整理执行失败不能按字典序/旧rank合成正式排序。

### 3.2 晨报单父任务双通道

真实CLI enqueue→worker→handler入口保留。初始化固定scan/report身份、08:30cutoff/09:20deadline，冻结前一自然日21:00那份已正式发布且cutoff前可读的晚报parentReportId、全部公司卡/催化/机会ID、原正文及来源版本。不能回退更早晚报或用D1/D2活跃集合替代，未选择公司也检查。

昨晚0推荐是合法空清单；昨晚没有正式报告明确parent_report_unavailable，发现仍可运行。任务续跑不重新选父报告或取新修订。

**复核通道**按公司聚合全部原理由，从开始即获取隔夜新事实、风险及对原传导逻辑的反证；不等待新发现筛选/分类/排序。每家公司所有原理由都须覆盖，不能只查第一条。

- 可共享版本化原始资料，但具有独立公司/原理由问题绑定搜索、原文读取及必要核验路径，复用现有Tavily gateway、证据库、计费和回执。风险资料无需先通过新推荐筛选。
- Agent决定必要补查；不规定每公司搜索次数。共享证据可服务多个理由，但实际可见清单和检查范围可追溯。没有发现链路匹配不能自动写“无变化”。
- 已确认变化可读；未知、未取证、执行失败区分。只有符合原证据/身份规则的反证产生risk/withdrawal；固定窗口不改变。

**新发现通道**对固定隔夜输入按3.1处理。复核发现的资料可共享，不自动升格为新机会；不重复收费、不改已发请求冻结输入。历史资料是背景，不能当隔夜新消息。

**实现选择**：父任务内受控并发和现有工作项，不创建新的任务树、timer或Agent服务。两通道独立持久化checkpoint，复核公司工作项内覆盖全部理由，统一父task计费身份与租约。复用显式deepReadConcurrency约束总在途研究，并公平调度，发现不得占满槽使复核饥饿。若旧配置只有一槽，在B90隔离配置显式安排至少两槽并记录，不能运行时默认补值。

禁止跨通道共享可变model/provider上下文、SQLite连接或可见证据集合；各工作项绑定自己的输入/回执键/clock/leaseguard。不可变资料引用可共享。已完成项及时持久化，不等所有Future返回；正常时间片yield不得重跑已结算项。采集也不能成为复核的无限前置门槛，复核可先处理原理由和已有资料、独立工具取证。

### 3.3 窗口、截止与失败隔离

- 新消息业务窗固定北京时间前日21:00至当日08:30，沿用包含两端点规则；等价时区在真实入口一致。旧水位/回看只影响采集维护，不扩大模型候选窗，不把补漏作为早报前置。
- 报道/事项/采集时间分开；未知精度不擅自归窗。背景可辅助解释，转载/新采集不自动等于新机会，证据满足cutoff可用性约束。
- 每次新增外呼（含身份）依据冻结timeout/retry/repair与余量准入，不能留未预留的串行尾巴；复核不为发现排序额外保留一份reserve。本地保存/交付与费用结算分开。
- 09:20前统一原子发布已确认复核、已确认发现及真实缺口，不要求两通道都成功。缺口可定位则限于关联公司/问题/催化；无法定位保留整体警示，不能让已确认事实失语。
- started/running/unknown保护保留；未知结果及其依赖不发布、不盲重试、不记零费用。无依赖且已结算的另一通道可正式partial交付，不再以全部外呼settled无条件扣住整报。依赖隔离必须可证明。
- 晚到回执可真实记账/私有保存，不能追加已发布推荐、改身份/窗口/内容或重复通知。覆盖响应与发布竞争、租约丢失和重启，unknown保护不随重启解除。

## 4. 持久化、DTO与历史

内部SQL Schema10复用`k10_execution_item_checkpoints`、`k10_morning_review_work_items`、report coverage和card content JSON，不新增平行状态表。若确有列约束不能容纳，Builder给主会话具体证据及最小迁移方案后更新同一记录，不暗加DDL/GET迁移。

B90新任务执行包显式绑定`reportContractVersion=k10-report-product-3.6.0-b90`与B90研究结果/prompt契约；用新revision写隔离库，具体revision依现有事实分配，不能改revision2或自动取latest代替活跃绑定。旧任务不自动换绑、重验或恢复。

新报告delivery contract为`k10-report-delivery-3.6.0-b90`，API envelope schemaVersion=10；历史按存储契约保持8/9，新客户端读8/9/10。没有B90字段就标历史未记录，不补造正文/安全结论。GET纯读。

保留现有报告/卡片/document路由，以下为新Schema10契约，历史可缺省：

| 位置 | 字段/行为 |
| --- | --- |
| card.catalysts[] | 新增analysisText:string、sourceRefs:SourceReference[]，正文/引用同一已保存催化；身份/headline/核实状态保留 |
| report.discovery | `{state:complete/partial/unavailable,outcome:recommendations/no_recommendation/not_completed,companyCount,reasonCodes[]}`；只有完整筛选空选择才可no_recommendation |
| report.morningReview | 晨报`{state:complete/partial/unavailable,parentReportId,targetCompanyCount,targetReasonCount,items[]}`；计数由冻结目标推导 |
| morningReview.items[] | `{reviewId,parentCardId,companyCode,companyName,opportunityIds[],unreviewedOpportunityIds[],status:completed/partial/failed/not_started,outcome:changed/no_material_change/uncertain,analysisText,checkedScope,sourceRefs[]}`；每公司一项且全部原理由覆盖 |
| incompleteReviews[] | 保留现有字段；从冻结目标未完成理由投影一理由一项、稳定ID。无work_item也不能消失 |
| document读取 | 按documentId/revision，明确contentKind:original/excerpt/unavailable；来源/URL/时间/分页保留，不能把摘要冒充原件 |

说明：analysisText自然表达；checkedScope是真实检查范围，不是“全网安全”。已完成但判断不确定可completed+uncertain；执行未完成由status区分。unreviewedOpportunityIds是opportunityIds子集，公司与理由全集精确对齐昨晚报告。未完成项系统说明不得冒充Agent已分析。

updatedCards/addedCards仍表示实际新推荐/催化，复核无变化不制造更新卡；风险/理由变化与既有lifecycleUpdates同机会对应。 B90重大变化结论以`affectedOpportunityIds`定位昨晚原理由；单理由可本地推导，多理由必须明确受影响子集且验证属于冻结集合。自然说明仍为一段，不新增逐理由分析模板；只为受影响机会生成既有生命周期记录，其他理由及D1/D2不变。整体status/delivery综合两通道和来源缺口，completed任务不等于完整业务成功。

冻结目标→工作项→结果→coverage→API是一条权威关系。旧B89报告可纯读投影其真实保存的失败占位，不运行新复核、不改历史DB。报告、卡片/机会、已确认生命周期变化、状态和通知待发同一受租约保护事务；重试不能重复发布/通知。
