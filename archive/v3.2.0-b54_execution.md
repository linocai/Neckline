## 3. Schema 8 与历史保护

Schema 8 为只增不改的 v2 命名空间，保留 Schema 7 所有表和数据。新增：

1. `k10_v2_strategy_snapshots` 冻结策略文本哈希、池／资料快照 ID 与哈希、策略和执行配置 ID／修订、导入时间；任务和报告必须绑定此 ID，缺失或校验失败即 `not_configured`，没有默认值。
2. `k10_v2_report_runs` 表示一个晚／晨扫描报告（窗口、消息／查证／可查看截止、晚晨迟到标记、父晚报和状态）；`k10_v2_report_cards` 每报告每公司一条，保存排序、卡片事实／不确定性／来源 DTO 和关联公司窗口。晚报不超过 30；晨报新增不设业务限额，但 API 分页返回。
3. `k10_v2_card_catalysts` 把一张公司卡关联到一个或多个事件修订及可选机会；同公司多催化的理由、阶段和来源独立可追溯，不以标题数提升排序。

既有 `k10_events`／事件修订、原文、任务、外部尝试、机会、公司窗口、选择快照、行情和评价账本继续作为通用证据与固定 D1/D2 账本。v2 卡首次正式发布时，在同一事务内建立或复用其公司窗口和机会：

- 重复／转载／普通进展／旧催化再次显示：关联旧机会和旧窗口，只写本次卡及证据更新，绝不重开样本。
- 同一公司同一首发批次／D1-D2 的多催化：多条 `card_catalyst` 共享一个窗口与一份成绩。
- 实质新阶段或独立新催化：建立关联旧机会的新机会；若与该公司任一已发布窗口重叠，标为 `overlap`，按真实 D1/D2 完成但不计主命中率；不重叠才进入主样本。
- 一张今日卡同时关联旧机会和真正新催化时，卡 DTO 必须给出可操作的目标 `companyWindowId`。新机会总以 `unhandled` 开始，不继承旧窗口的 selected／skipped／unhandled；针对新机会的操作只写该窗口，旧窗口的 D1 冻结组和历史结果不可修改。

旧 v1.4 的已发布推荐、选择冻结和证据必须以明确 `K10-v1.4` 名称保留，不能被 v2 卡、选择或结果重解释。原 D1/D2 的窗口与选择不重置；未来获恢复授权后，既有行情事实与评价账本可追加修订以完成旧样本。删除 80／40 的活跃生产配置、校验器和测试契约，不为旧测试保留可运行兼容路径，历史数据中的旧参数照原样保留。生产回滚仍以已验证的 Schema 7 备份恢复，不能以便利 DDL 丢弃 v2 帐本；隔离迁移测试要证明升级失败时源库字节不变。

## 4. K10-v2 离线运行契约

### 标题、资料与事件

- 每个来源窗口的精确去重标题都进入短批处理。模型输入标题必要字段和按需召回的本地索引，输出事件候选、可能相关池内公司、正文需要与理由；代码、公司名、关键词、新闻分类、题材、涨幅、池外主体或标题长度都不能作程序硬删条件。
- 索引没匹配也必须由模型给出“无合理池内关联”后才跳过；索引命中只是一条线索，完整资料与消息原文才支撑公司关联。不得把 1,089 份完整档案或全文历史塞入每个请求。
- 跨批合并同一事件，优先阅读最完整原文；多公司共享事实与补查结果，各公司影响分开比较。正文、搜索摘录和完整网页仅在事件事实或公司映射的具体缺口需要时取得；没有 80／40、全文、搜索次数、来源数、文章数或 token 配额。
- 有效路径不足时保留未知并结束；正文缺失、模型协议、来源或比较失败是未完成状态，不能报告为“没有机会”。新证据只影响随后卡片／修订，不回填旧推荐。

### 比较、日推荐与晨间衔接

- 研究对象限定在固定池内有合理关联的公司；不把一条行业／海外／宏观线索扩张为全市场尽调。系统按事件完成比较后，合并同公司所有催化并重新选择当天公司；晚报最多 30 张不同公司卡，不凑数。
- 卡片必须包含：事情、公司关联、两日关注理由、当前价格反应（如已有）、未核实或分歧、来源／发布时间／取得与查证截止、事件关联和显式策略版本。不得输出未经校准的涨停概率，也不得以价格上涨当事实确认或新催化。
- `unverified` 是卡片披露，不是 `pending` 自动门槛。删除 `ready_for_comparison` 对发布资格的错误绑定；比较输出必须表达支持、反对、未知和失败的真实状态。核心理由被已核事实推翻时撤回该理由，其他独立理由照常判断，已发布窗口不断。
- 晨报只处理 `[D0 21:00,D1 09:00]` 增量：已有晚报公司的重要反证、事实／论点变化、到期或缺口写为更新；真正新增公司单列“晨间新增”。同公司不会出现第二张可选择卡，也不会替换、清空或重新冻结用户已有选择。晨间新增以稳定顺序分页，不设额外淘汰或正式推荐数量上限；首次可查看时间决定同日或下一交易日 D1，并保留 `morning`／`late` 标记。

### 用户选择、辩论、成绩

- 每张正式卡给出明确的目标公司窗口；选择 API 仍以窗口为原子单位。持久化冻结枚举为 `selected`、`skipped`、`unhandled`；卡 DTO 的 `currentSelectionState` 固定映射为 `kept`、`skipped`、`unhandled`（`selected → kept`），不得混用两套名称。D1 开盘前最后一次明确操作冻结，开盘后操作只作记录。同卡多催化共用选择；真正新机会从未处理开始，不能继承、覆盖或回改旧机会选择。
- 用户留下后才入队正方，再以同一资料截止读取正方全文执行反方；各一轮。任一方失败明确显示，不能删卡、改选择或重开窗口。没有裁判、额外夸大关卡或循环辩论。
- 保持现有 D1/D2、主指标、缺数／停牌／异常、重叠、价格观察和三选择组语义。结果页面按策略版本和窗口分组；总组与子组不相加，重叠结果单列。

## 6. 可靠性、配置与错误语义

- 新的策略／执行配置显式包含 K10-v2、策略快照、资料快照、标题批处理、并发、模型单次选项、任务超时和重试策略。不存在配置或任一必填项无效时显示“今天没跑成 · 参数未配置”，不列推荐，不回退 v1.4 或样例值。
- 将 402 归类 `insufficient_balance`：记录脱敏状态、保留当前检查点、终止该受影响任务和下游依赖，不再把它当网络错误排队重试。将 429 归类 `rate_limited`：尊重可解析的 `Retry-After`，否则使用冻结配置的有限退避；只调度受影响步骤，成功后从检查点继续。其他协议、来源和客户端读失败各自保留原因，不伪装为零结果。
- 任务、报告、卡、机会、窗口和 usage 记录写入必须具有幂等键及中断边界；恢复同一输入不得新增第二张卡、机会、样本、选择冻结或重复计量。保留阶段输入大小、重复资料输入、缓存命中和合成 usage，但不得称为实际 token 节省或日成本。
