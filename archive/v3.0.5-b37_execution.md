# 3.0.5 / Build 37：K10 资讯处理与预算修复

根目录 [PROJECT_PLAN.md](../PROJECT_PLAN.md) 是现行控制面。本记录给 builder 施工契约、边界与验收；代码事实以 Git 和当前文件为准。

## 目标和边界

将 K10 第三、四、六章落实为可限制调用量的生产链路：程序先增量去重、按明确模板筛分并把同事项资料合为资料包，再以小型模型理解选出值得核验的事件，最后才消耗 Tavily、公司比较和全局推荐名额。保留 K10-v1.4 的公司比较、30 家上限、跨日延续与固定 D1/D2；不引入交易计划、收益结算或新的选股信号。

本轮只改代码、迁移、确定性测试、离线冻结资料测量和客户端 QA。生产仍停机：不得启动 worker/timer、恢复历史 scan、启用任何模型/搜索或部署。真实付费小样本、恢复和发布均留待用户明确授权。

## 已确认事实

- B36 的 `documentBatchSize=24`、并发 12、单请求 maxTokens、7200 秒和 Tavily 128 次只限制吞吐或单类请求，不能限制整轮模型 token/调用。当前任务账本保存实际 token，但没有原子总额预留。
- `run_discovery` 对输入资料进行理解后才 `_merge_same_event_sources`；生产入口没有把 document filter 传进来；`understand` 对“请求全文或空 events”均走全文。已有同源稳定版本及 task 内缓存复用，不等同于跨 scan 的事件事实/证据失效控制。
- Tavily 有每任务请求检查点和上限，但按事件遍历；没有在 Tavily 前冻结的事件优先级。来源、文字、否认或更正的变化不得重用过期结论。

## 配置与持久化契约

1. 新执行配置版本（不得改写 B36 已冻结配置）必须显式包含：
   - 模板规则包 ID、revision、规则项及动作；每项的匹配依据可审计。规则只允许明确模板的 `exclude`、`defer` 或 `protect`，未知必须 `defer`，禁止按栏目、利好词、长度、题材或创业板代码命中硬排。`defer` 是可见待处理队列：在显式额度内可进入轻量分诊，预算不足才不调用，不能把全部未知永久跳过。
   - 资料包/轻量理解的最大输入材料、全文许可与全文单独额度；模型仅 `deepseek-v4-pro`。
   - 按整轮及阶段的 `maxModelCalls`、输入/输出/总 token 预算、每次调用的保守预留上限、`maxSearchRequests` 及 Tavily credit 预算、允许的重试次数。缺任一字段的 discovery 配置为 `not_configured`，无调用。
   - 明确事件优先级规则及顺序。至少把已发布/已观察公司的重大反证、会改变既有判断的新事实置于一般新事项之前；规则不足时留队列而非自行添加选股阈值。
2. 新 schema 采用加法迁移，至少持久化：资料的筛分审计和资料包成员/版本；每 task 的预算、预留、实际用量、未知用量与状态；持久运行暂停及原因/时间。冻结 task 仍保存配置哈希，历史 B36 表/数据不可改写。块 1 完成时将新增表/字段、迁移版本和供块 2–4 调用的 config/store 函数签名写回本记录，后续块不得自行另建平行契约。
3. 预算 admission 在外部请求前、同一写事务中检查和预留。每一次模型调用、全文、重试和 Tavily 请求单独占用额度；成功按真实用量结算，提供方缺用量或网络结果未知保留完整预留，缓存命中不占额度。并发 reservation 合计不能超过上限，无法预留的项目按 `pending_budget` 进入待处理队列。
4. 持久暂停开关在 timer、CLI enqueue、worker claim、handler 及 continuation/retry 边界都生效。暂停不得消耗、取消或重置既有冻结预算；返回安全的 `paused` 状态。只有显式运维操作能解除，系统重启或 retry 不得解除。

## 处理、缓存与证据契约

- 原文/版本精确重复在模型前合并；转载/同事项按主体、对象、日期、金额和阶段组成资料包，保留所有来源与版本。取消、否认、更正、重要反证不能被合并丢失，须作为更新与优先级保护对象。每一个排除、延后、合并和待核都有规则 ID 或安全理由和计数。
- 小型理解只读取资料包的标题、时间、来源、可追溯关键段和相对于旧事实的新增内容，输出事件事实、状态、证据缺口与是否明确请求全文。正文不因输出空事件自动送全文；全文仅在其请求、独立额度预留成功且资料包仍有效时读取。
- 建立事件级工作队列后，先按冻结优先级处理，再 Tavily。Tavily 查询围绕证据缺口，同事件/同资料包共享核验材料；无独立核验者保持待核，不进入映射、比较、分类或候选。
- 跨 scan 复用的最小单元为带来源版本、取得/发布时间、模板/模型/提示输入哈希的原始事实。正文/版本、规则、模型或提示输入改变，纠正/否认出现，或资料包成员改变时，失效受影响派生结果；资料在当次 cutoff 前已可见时，后来的 cutoff 本身不使纯事实缓存全失效。价格背景、两日判断、证据时效和事实变化必须重核，普通更新只更新原机会，不重开窗口。所有候选仍以真正 `availableAt` 决定 D1/D2。

## API 与客户端契约

`executionProgress`（或等价明确命名的版本化字段）须安全返回：运行控制状态及原因码、配置状态/缺项、原始接收/精确去重/模板 exclude/defer/protect/资料包/轻量理解/全文/待核计数、各阶段调用/缓存/重试/预算预留/实耗/未知/剩余计数和 `pending_budget` 数。不得返回原文、提示词、模型原答、密钥、私有 URL 或不可验证的费用金额。

Swift 将 paused、未配置、预算耗尽和待核显示为终态或可恢复状态，不能显示“无变化”或“已完成”。保留现有 partial、撤回、重叠、缺数和分析修订展示；参考图的白卡、蓝色强调、节制排版和明确导航仍适用。

## 施工块与顺序

1. **配置/Schema/Store（先行）。** 所有权：`Backend/neckline/k10/config.py`、`schema.py`、`store.py`、执行配置与其测试。实现版本化规则、预算及暂停的验证、加法迁移、事务 admission/结算和安全聚合查询；迁移对 B36 投影保持不变。
2. **筛分、资料包和发现链。** 所有权：`discovery.py`、`pipeline.py` 及其测试。将离线筛分/合并置于理解前，移除空事件全文回退，实施全文/缓存失效/优先级/Tavily 门控。依赖块 1 的持久契约，不改 K10 候选和成绩规则。
3. **入口与运行控制。** 所有权：`cli.py`、`worker.py`、调度/恢复入口、预算调用包装及测试。每一外部边界检查 pause/config/budget，保证 continuation、retry、未知用量和并发不绕过账本。依赖块 1，和块 2 联调。
4. **API/Swift 可读状态。** 所有权：后端 DTO/router 与 `App/` 的模型、store、View、测试。由块 1–3 的安全聚合驱动；不得在客户端推断预算或调用外部服务。凡改 `.swift`，执行三条规定 xcodebuild。
5. **集成与离线规模验收。** 所有权：K10 回归、CLI→worker 确定性 transport、冻结资料只读测量和 native QA。先完成前四块后进行；不以两篇 fixture 替代 2472 篇离线证据，也不作真实付费全量测试。

## 验收标准

- 配置缺模板、缺任一预算、持久暂停、预算耗尽、并发竞争、retry/continuation、提供方未知用量等情形均为零模型/零搜索越界；调用账本、队列和 API 状态可复核。
- 规则审计覆盖精确重复、转载合并、未知保留、取消/否认/更正、重大反证、同事件多来源及跨 scan 来源版本变化；禁止条件不得成为筛选依据。无配置不能把资料全量放行。
- 资料包只调用一次轻量理解；空事件不全文；有效全文请求受单独额度；Tavily 仅在事件优先级后且共享证据；缓存失效后不复用旧结论。
- K10 回归覆盖 30 家不同公司、同股多催化、旧机会延续、撤回、晚/晨/迟到、选择冻结、D2 结束、重叠和缺数，确认这些规则未被成本控制改变。
- 从真实 CLI enqueue 到 worker/handler 用确定性 transport 验证等价时区、来源延迟、不确定发布时间、生产者失败、客户端读取失败与中断后恢复；不在入口前篡改时间。
- 用冻结 2472 篇只读输入完成解析/筛分/资料包/中断恢复测量，报告聚合数量、耗时、缓存与零外部调用证据；任何真实 DeepSeek/Tavily 验收需要用户另批预算与样本。
- 后端完整测试、隔离 DB FastAPI→当前 Swift DTO、macOS/iOS 填充与空态 QA、三条规定 xcodebuild 全部通过。发布前按全局规则建议一次高危区复审；仅在用户明确要求或接受时实施，不构成默认审批门禁。本记录不授权部署、开启 timer 或恢复生产。

## 风险、回滚和交接

- 最大风险是“模板规则/预算未定”被实现成宽松默认，重新形成全量送模。防线是配置缺失硬门禁、持久暂停和 deterministic provider 断言；不能用样例阈值替代用户批准参数。
- 资料包误合并会掩盖反证，预算预留过松会超额，过严会积压；二者均通过可审计规则、保留未知队列、事务 reservation 和 2472 篇离线检查控制。发现错误时禁用新执行绑定、保持暂停、备份后前向迁移；不回滚 B36 生产数据。
- Builder 的第一步：读取本记录、`PROJECT_PLAN.md`、当前 `AGENTS.md` 和 git status；然后为“缺配置/暂停/预算 reservation”写失败回归，确定 schema/API 字段后再接 discovery。

## 施工证据：块 3 入口、逐请求预算与运行时（2026-09-08）

- `enqueue_scan` 与 `recover_scan` 在写任务前读取持久运行控制，并且只接受完整、已批准的 `k10-execution-v2` 绑定；CLI worker 在构造 handler、读取 token 或启动维护前因 closed 返回 paused。`run_once` 在 claim 前、进入 handler 前及安排 continuation/retry 前检查同一控制；`schedule_task_retry` 在自身写事务内再检查，因此 pause race 直接以 `failed / paused` 收口且不安排未来 retry。付费任务还要求有效 V2 配置，因此旧 B36 配置不能作为 live fallback。
- `MeteredProvider` 负责唯一的模型 HTTP 预算入口：每个显式 task/stage/item/attempt 上下文在 socket 前 admission；内部 provider retry 被固定为一次，重试只能由检查点产生新的 reservation。请求按精确 JSON UTF-8 上界加固定传输余量预检，显式 `maxTokens` 不得超过该次输出或总 reservation；不相容内容返回安全 pending，绝不截断后继续请求。成功按实际 token 结算，缺 usage、异常或无法确认的结果保留 unknown 预留。
