# V2.5.1 Build 11 · K9 产品交付层执行计划

> 状态：已完成 Review、修复、发布、macOS 换包与 iOS 签名归档。唯一现行控制面是仓库根目录
> [PROJECT_PLAN.md](../../PROJECT_PLAN.md)；本文件展开其中的施工契约、验收与风险。
> 全程直接在 `main` 工作，未建分支；发布过程未触发正式报告重跑。

## 1. 结果与非目标

K9 不再只是已上线的选股引擎，而是一份能在 macOS/iOS 上十分钟读懂、离线回看、
可复制到聊天框的每日材料：市场正在发生什么、哪些票值得细看、各自的收盘价和明日预案。
它仍只提供材料与条件，不代替用户下单。

本版不改 K9 参数、四通道、硬边界、排序、名额、解释层双盲、预案骨架、D1 两拍、
成绩口径或 B1–B22；不恢复 K8、篮子、持仓、旧校准/概念板块/旧通知；不重做复盘的
解析、装订、结论业务。方向解读是背景旁路，不是第五个策略条件。

## 2. 用户故事与完成定义

| 用户要完成的事 | V2.5.1 成功时的体验 | 不能发生的事 |
| --- | --- | --- |
| 打开当天报告 | 先看报告状态、市场背景、覆盖率和 10–20 只的短画像，再点开任一只 | 把系统故障说成空榜；让用户先读技术账本 |
| 理解市场方向 | 看到 2–3 个“今天市场在关注什么、为什么”的短说明 | 方向文字参与筛选、排序、名额，或暗示买卖建议 |
| 看一只票 | 看见代码、收盘价（截至 D0）、一句话画像、三个明确金额价位和预案 | 刻度条、价格百分比替代、把收盘价伪装为实时行情 |
| 深挖/带去聊天框 | 默认页保持简洁；展开完整资料后可一键复制可读中文 | 把 JSON、Markdown 标记、内部字段名直接铺到界面 |
| 在无网时回看 | 打开同一环境同一账号的最近成功报告，标明离线和缓存时间 | 用旧缓存掩盖鉴权失败、空清单或新的线上结果 |
| 观察真实成本 | 在高级诊断看 3–5 日实际 Token、未回传次数、Tavily credits | 用字符数估 Token、暴露密钥/prompt/完整搜索证据、臆造人民币费用 |

## 3. 绑定产品与接口契约

### 3.1 方向解读：事实层 sidecar

1. 新建 `Backend/neckline/facts/direction_llm.py` 与同层读取/保存模块；它只读取**已冻结**
   的事实包投影，零 import `neckline.k9`、`explain`、`playbook` 或清单表。
2. `report/evening.py` 固定链改为 `facts → direction → k9 → explain → playbook → report`。
   direction 在 facts 冻结失败时标未执行且零外部调用；K9 即使参数缺失，方向与市场事实仍可
   正常进入 `not_run` 报告。
3. 每个 `pack_id` 最多一次常规尝试：一条**逻辑** Tavily Basic 查询（最多 5 条证据）和一条
   DeepSeek 推理。已有 terminal sidecar（成功或失败）直接复用，不因 API 刷新、App 打开或
   当天普通链重启而再花钱；不增加自动“补试”机制。
4. 新 LLM 任务键为 `market_direction`，列入 router 与设置可见任务；它属于
   `DEFAULT_SEARCH_TASKS`，因此复用 Tavily + 纯 OpenAI-compatible 推理封装。不得使用模型
   厂商原生搜索、第二个搜索商或另一个方向 LLM。
5. 输入是冻结 `market` 中可解释的市场级事实和一份固定上限的行业强弱投影；不得含股票
   入选名单、召回通道、rank、tier、候选分或参数包。查询以交易日和市场语境锚定，不能用
   一两个字符的题材名裸搜。
6. 输出闭合为 `ready | unavailable | not_attempted`：`ready` 仅含一段总览和 2–3 个
   `{name, reason, evidenceCount}`；失败写可读原因，报告仍可发布。禁止股票代码、推荐、
   目标价、策略分数或“因此应该买”。模型格式不完整属于 `unavailable`，不许空成功。
7. `fact_direction_briefings` 以 `pack_id` 为主键保存 immutable sidecar：交易日、状态、
   摘要、themes JSON、provider/model、证据数、创建时间、失败原因；不存密钥、prompt、
   搜索原文或机械候选。它是事实包旁路，不能反写/修改事实包。

### 3.2 用量账：每一笔真实调用都可追溯

1. 新增 `llm_usage_events` append-only 表。每个逻辑 LLM 调用写一行：trade/report/pack 关联、
   `market_direction | news_scan | explain | playbook`、provider/model、成功/失败/跳过、
   prompt/completion/total tokens（可空）、`usage_unavailable`、Tavily credits（可空）、
   搜索是否发生、耗时、去敏失败原因和时间。
2. 扩充 `LLMResult`/Tavily wrapper，成功搜索后无论随后的模型调用是否失败都携带真实
   credits；上游未给 usage 时持久化 `null + usage_unavailable=true`，绝不估算。
3. 四个唯一调用点（方向、消息扫描、解释、预案）都经同一个计量入口；加源码/行为门禁，
   防止新增未记账的 `provider.chat`。没有 provider 的跳过可记零外部成本事件，但不能伪装
   成成功调用。
4. 增加经鉴权的只读 `GET /api/v1/usage/summary?days=1…35`，默认 App 看 5 日。返回按日与
   按任务的调用数、真实 tokens、未回传次数、Tavily credits、失败数和耗时；不返回 key、
   prompt、原始搜索结果、请求 ID 或厂商单价。
5. 费用呈现只报 Token/credits 和“未回传”事实，不把可变模型价格硬编码成成本。连续 3–5 个
   交易日再与 DeepSeek/Tavily 控制台对照决定下一步，不在本版新设 Token 截断。

### 3.3 报告和 API：默认可读，完整版可取

1. 保持 `k9_reports.structured_json` 与事实快照冻结。API 由已冻结的 `structured` 生成
   additive `copyText`，不修改旧 `markdown`、旧报告、预案版本或事实包；App 绝不直接把
   `markdown`/JSON 原样画到屏幕。
2. `/selection/latest` 与历史 selection 响应 additive 返回：方向 sidecar 快照、当日市场
   摘要、覆盖率快照、`copyText`，以及每只股票的 `oneLineProfile` 与 `referenceClose`。
   `referenceClose` 从 D0 冻结事实包批量读取，标“收盘价（截至 D0）”，不走实时行情。
3. `oneLineProfile` 只复用解释层现有 `profile.company`/可读位置字段，不新增 LLM 调用。
   解释层未完成时显示“资料暂未生成”，不能凭空组合分析文字。
4. 覆盖率同时出现在当日报告与成绩页：零与 `null` 必须仍区分；`not_run` 当日若事实包已
   冻结，照常呈现市场事实和覆盖率；无覆盖率行时说“暂无法核对前一日清单”，不是 0%。
5. `copyText` 是确定性中文材料，至少含：报告/行情日期、报告状态、方向背景、市场事实、
   覆盖率、逐票短画像/收盘价/三个价位/三分支、资料缺口。它可以复制但不是下单指令。
6. 新字段全是 optional/additive：旧 App 忽略；新 App 遇 V2.5.0 frozen payload 时保留旧事实，
   明确说明“当日未生成/资料未保存”，不补跑/补写历史。

### 3.4 App：信息层次、离线与文案

#### 选股与个股详情

- 默认顺序固定为：状态与人话日期 → 方向背景 → 市场事实/覆盖率 → 清单。清单行只保留
  名称、代码、一句话画像、收盘价和一个易懂形态标签；rank、tier、内部成功状态和长段数据
  移出默认层。
- 点一只后，在 macOS 右侧/iOS sheet 展示该票的完整资料和预案。删除 `PriceLadder` 及所有
  刻度/比例视觉，直接显示“收盘价、失效价、第一压力位、第二压力位”四个金额；不以百分比
  代替价格，不制造实时含义。
- “完整资料与预案”默认折叠，里面使用语义化 SwiftUI 区块而非 Markdown 渲染；提供“复制完整
  资料”按钮，复制 `copyText`。复制失败给本地可读提示，不影响阅读。

#### 离线快照仓

- 新建可注入的 `ReportSnapshotStore`，按 `SHA-256(canonical base URL + access token)` 的不可逆
  namespace 保存已成功解码的 `SelectionSnapshot`；文件在 Application Support，原子临时写入后
  replace，iOS 使用适合离线阅读的文件保护等级。
- 保留同 namespace 最近 30 份 selection 快照；只在成功网络响应、三态合法且可解码时更新。
  同一交易日以更新的 `generatedAt` 替换，绝不拼接两个快照。
- 网络不可达且有缓存 → 显示缓存及“离线浏览 · 缓存于 …”；网络不可达且无缓存 → 可读错误态。
  401/凭据缺失/响应损坏/服务器明确 `not_run` 不可回退旧缓存；切换环境或 token 后删除旧 namespace。
  缓存不含 provider key、Tavily key、HTTP header、请求日志或设备 token。

#### 全 App 文案与设置

- 审计 `SelectionView`、`StockDetailView`、`CheckListView`、`ScoreboardView`、`ReviewView`、
  `SettingsView` 和共享空态。用户可见文本不得含 raw Markdown、`K9 §`、`架构 §`、
  `append-only`、HTTP 状态码、GET 路径、`UserDefaults`、`git`、服务端 reason code 或内部字段名。
- 保留三态、数据缺口、预案冻结等真实语义，但换成人话。例如“只追加新版本”替代
  `append-only`；“连接验证未通过”替代 `401`；日期均经统一格式化为中文日期/时间，API 键仍保留
  原样不改。
- 设置默认只显示连接是否正常、通知、模型/搜索是否已配置、版本与用量摘要。服务地址、访问
  凭据、Provider endpoint/model/key、任务路由和诊断请求移动至 macOS “高级与诊断”；iOS 只显示
  必要的安全状态和桌面端配置指引。高级区可有准确技术输入，但不在普通阅读路径暴露实现术语。
- 复盘的解析/装订/存档业务不变，只改标题、空态、可复制材料和时间格式；不增加系统内对话或
  新 LLM 调用。

## 4. 数据迁移、兼容和安全

| 项目 | 决定 |
| --- | --- |
| Schema | 26 → 28：仅 `fact_direction_briefings`、`llm_usage_events`；更新现行表门禁和 read-only probes |
| 写入时机 | `init_schema()` 仅 API startup、显式写命令、发布迁移；GET 与读取 helper 零 DDL |
| 历史数据 | 不回填方向、不补 Token、不重渲染/重跑历史报告；V2.5.0 快照保持原样 |
| 旧客户端 | 忽略新 response 字段；旧服务与新客户端的 usage/方向字段安全降级 |
| 密钥 | 只在现有服务端设置库；绝不进 telemetry、API 响应、日志、复制文本或离线快照 |
| 失败 | 方向/用量失败不改变 K9 结果；缓存失败不阻断在线报告；全部如实可见 |

## 6. 自动化验证矩阵

### Backend

- direction：事实包未冻结零调用；成功时一 pack 一 logical Tavily/LLM；重复链零新调用；
  provider/Tavily/JSON 失败写 terminal `unavailable` 且报告/K9 状态不变；AST 证明 facts 不 import K9。
- report：方向、市场、coverage、`not_run` 的完整/缺失组合；`null` 不等于 0；close/短画像
  批量读取；旧 structured payload 与新 `copyText` 同时可读且不写回。
- telemetry：四个调用点均落一条；Tavily 成功+模型失败仍保留 credits；usage 缺席为 null；
  API 只读聚合、认证、窗口边界；无 key/prompt/raw evidence 泄漏。
- migration/read：新库 28 表、真实 V2.5.0 副本升级、重复 `init_schema`、读路径零 DDL、
  rollback transaction、临时数据库隔离；绝不触碰 `Backend/data/`。
- K9 regression：四通道、参数缺失、双日期、解释双盲、预案冻结、9:26/10:00、评分/覆盖率
  原有门禁全绿，且新增方向从不影响清单。

### App

- DTO：旧/新 selection、方向缺席、coverage null、收盘价/短画像缺席、未知报告状态的解码。
- 缓存：同配置原子保存、更新替换、网络失败回退、401 不回退、配置切换清理、空缓存、保留上限。
- 文案：建立针对用户可见 View 的禁止术语回归测试；允许的高级输入与用户默认层分开断言。
- 价格：`PriceLadder` 和标尺引用为零；金额格式、D0 收盘标签、三个价位与预案条件正确。
- 用量：诊断 DTO/空态/未回传状态，不显示敏感字段。

| 场景 | macOS | iOS Simulator / 设备 |

## 8. 独立 Review、修复循环与 RC

1. Builder 完成 A–D 和全部自动化门禁后，独立 reviewer 只读审 diff、schema 演练、实际
   LLM 调用追踪、缓存安全、API payload 与双端截图；报告写入 `archive/review报告/`。
2. P0/P1 包括：方向影响策略、重复扣费、用量丢失/估算、缓存跨账号/掩盖 401、历史冻结件被改、
   不见 coverage、价格刻度回归、用户页工程词泄漏、任一平台未构建。Builder 修复确认项并新增
   可行的回归测试，再跑全矩阵。
3. RC 才将 API 改为 `v2.5.1`、App Marketing Version 改为 `2.5.1`、Build 改为 `11`，并运行
   现有版本一致性、签名/归档、数据库备份副本、`integrity_check`、28 表清单与服务 unit 语法门禁。
4. 到此停止，等待用户明确授权部署、发布、commit/push、macOS 换包。不得借验收之名重跑报告。

## 9. 风险、回滚与持续观察

- 方向 sidecar 的唯一不可逆成本是一次外部调用；以 pack 级幂等和无自动重试限制它。Tavily 或
  DeepSeek 不可用时降级文字，不阻断 K9。
- migration 是纯新增两表；旧服务忽略额外表，源代码回滚不需要反向删数据。部署前仍必须备份
  DB/WAL/SHM、验证备份副本、记录 release SHA；若 schema 或服务故障，恢复同一份源码与数据库备份。
- 客户端缓存是本地可删的派生物；出现解码/安全问题时删除缓存、换回旧 App 即可，不触碰生产事实。
- 上线后 3–5 个交易日核对用量账、Tavily/DeepSeek 控制台和实际报告阅读时长；B20 的 9:26
  双源 `open` 观察继续独立记录。它们都是观察项，不授权在本版偷偷调策略或加阈值。
