## 2. 关键决定

- **D1 数据源只读 KX**（KX 的原则「看板只读 KX」）：后端读 KX 总览一份 JSON，严格校验后投影成 Neckline 的看板接口；App 只读 Neckline。
  - 缓存：成功 60 秒、失败 15 秒，同一时刻只读一次；KX 给 `pending` 时按它给的间隔（1～5 秒）最多再读 3 次。
  - 不再读 KX 健康检查。Neckline 不再为 KX 看板调麦蕊或 TuShare。
  - 访问码仍是 `KX_READ_KEY`（NB `/opt/neckline/.env`），`KX_BASE_URL` 不变。
- **D2 校验与缺失**：
  - `schema_version` 不是 4 就整份不用，写明「KX 看板格式变了」，不按旧逻辑读。
  - 结构级不合格（缺 `rooms`、房间不是列表、组没有龙头等）整份不用；字段级不合格（数字不是数、时间解析不了）只把那一项置空，并在 `gaps` 写一行。
  - null 一律显示为缺失，不当 0。
  - KX 读不到或不合格时，用进程里最后一份合格的总览，标「未能核对」和最后读到的时间；进程启动后一次都没读到，就不出看板，如实写原因。不落库。
- **D3 退役删除**（用户 11/04 选定，删除推荐接收）：
  - 推荐接收接口、置顶与高亮、名单同步、Neckline 自己取的 KX 行情与日线统计、热度天数、B128 的竞价时段判定（KX 已在报价里给 `session_phase`）全部删掉，连同测试与夹具。
  - 库结构升到 **v5**：删 `kx_pool`、`kx_picks`、`kx_daily_stats`。往回切到 B130（v4）时，由较新的 release.py 补建这三张空表，再把版本号写回 4；新 release.py 要支持这一步，并有回归测试。
  - health 去掉 `kxPool`、`kxPicks`，改为 `kxBoard`（访问码已配置）；release.py 的就绪检查相应改，切换前看旧名、切换后看新名。
  - 生产配置：`.env` 删 `KX_PICKS_TOKEN`；NPM nk 配置删 `/api/v4/kx/picks` 那段只放行 HZ 的 location。两项都先备份，`nginx -t` 通过再 reload，上线时由用户放行。
  - `ts_code` 移到 `neckline/market/` 下，`evaluation/market.py` 改为从那里取。
- **D4 单票详情这次不做**（用户 11/04）。
- **D5 版面**（KX 定框架与原则，具体设计由 Neckline 定，先出样图请用户确认）：
  - 从上到下：情绪条 → 龙头室 → 等候室 → 淘汰室。组是整体，小弟挂在龙头下面，不拆开排序；各房间按 JSON 给的顺序。
  - 事实（报价、几板、板型、封单）和 DeepSeek 写的内容（结论、依据、高度、带动、承接、组说明、小弟跟的理由、市场一句话）分开显示，DeepSeek 的内容放在有标识的区域里。
  - 板型直接用 `board_type_text`，盘中不写「一字」；`sealed` 不是 true 时不写「封单」，只写「买一挂单」金额，并显示 `order_book.warnings` 里的原因；`seal_change_5m.amount` 为空时不显示增减。
  - `session_phase` 为 `call_auction` 时，价格标「竞价中」，不用来判断涨停。
  - 标明数据时间：KX 读取时间 `checked_at`、报价 `source_time`、涨停池 `fetched_at`、结构写入时间与依据的收盘日。`deepseek_status` 不是 ok、`deepseek_notice` 或 `refresh.notice` 非空、`fact_warnings` 非空、`status` 为 partial 时要明确标出（不堆警告：每类一行）。
  - 不显示能否买入、买卖建议、持仓、收益。
  - 刷新：盘中（交易日 09:15–15:05）每 60 秒；其余时间只在打开和手动刷新时读。
- **D6 版本**：后端与 App 都是 4.3.0 (131)，用 `App/scripts/prepare_release_candidate.sh 4.3.0 131`。

## 3. 接口契约（`GET /api/v4/kx/board`，看板 v2）

- 顶层：`generatedAt`；`source`（`checkedAt`：KX 的读取时间；`stale`；`reason`；`lastReadAt`）；`structure`（`version`、`asOf`、`generatedAt`、`generatedBy`、`deepseekStatus`、`deepseekNotice`、`marketNote`、`membershipLocked`、`refresh`：`date`、`result`、`finishedAt`、`message`、`notice`）；`status`；`errors`、`warnings`、`gaps`；`factWarnings`（`groupId` 可空、`text`）；`session`（`inSession`、`refreshSeconds`）；`sentiment`；`rooms`（`leader`、`waiting`、`eliminated`）。
- `sentiment`：`tradingDay`、`basis`、`boardPhrases`、`limitUpCount`、`brokenCount`、`brokenRate`、`limitDownCount`、`highestBoard`（`boards`、`names`、`codes`）、`yesterdayConsecutive`、`yesterdayContinued`、`yesterdayTradingDay`、`fetchedAt`（四个池各自的时间）。
- 组：`id`、`theme`、`roomSince`、`brokeOn`、`observedTradingDays`、`observedText`、`flags`（每项 `kind`、`code` 可空、`text` 原文）、`judgment`（`verdict`、`reason`、`height`、`drive`、`resilience`，可空）、`note`、`leaders`、`followers`。
- 股票：`code`、`name`、`role`、`reason`、`divergent`、`quote`（`price`、`changePercent`、`previousClose`、`open`、`high`、`low`、`turnoverAmount`、`amplitudePercent`、`turnoverPercent`、`sourceTime`、`quoteStatus`、`sessionPhase`、`warnings`）、`limitUp`（`inLimitUp`、`inBroken`、`inLimitDown`、`consecutiveBoards`、`firstSealTime`、`lastSealTime`、`breakCount`、`sealAmount`、`boardTypeText`、`poolFetchedAt`、`warnings`）、`orderBook`（`status`、`bid1Price`、`bid1Volume`、`bid1Amount`、`asksClear`、`sealed`、`sealAmount`、`sealChange5m`（`amount`、`baselineAmount`、`baselineAgeSeconds`）、`sourceTime`、`warnings`，没有时为 null）。`history` 不投影。金额一律是元（`turnoverAmount`、`sealAmount`、`bid1Amount`、`sealChange5m.*`），比例 `brokenRate` 是 0～1 的小数，由 App 格式化。
- 旧 App（4.2.1 及更早）读不了新接口，会显示「KX 看板暂时读不了」；用户已接受改版期间不可用。
