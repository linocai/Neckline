# Neckline 4.0.0 Build110（B110）执行记录

V4 的第一个上线 build：只上后端（晨报采集、出报、接口、只读网页、推送通道），App 不动（仍是 3.7.0 B109，P3 再改）。线上基线是 v3.7.0-b109（`f533425`）。V4 的整体计划与决定见 [v4.0.0_execution.md](v4.0.0_execution.md)。

## 1. 范围

- **晨报**：每个交易日一份。窗口为上个交易日 15:00 → 当天 08:00；规则用用户 2026-10-16 批准的 `screening-v1.json`（P1 草稿规则：利好草拟清单，不设条数上限与重要程度门槛，持续影响的消息暂不收）。
- **采集**（`neckline/news`，从 k10 移植金十 MCP 与 TuShare major_news 取数）：每天 08:00、20:00；每个来源从上次完整覆盖处减 1 小时回看取到当下，没有覆盖记录的来源必须显式给起点。
- **出报**（`neckline/morning`）：08:00 采集 → 交易日出报 → 推送「晨报已出」；出错退出 75 由 systemd 每分钟重启续跑；09:15 兜底，还没出报就记失败并推「晨报出问题了」，不补跑。
- **库**：新库 `/opt/neckline/data/v4.db`（application_id 1313552704），表：原件与版本、采集记录、模型回执、晨报、推送设备、推送记录。晨报记录是推送、App、网页（以后还有 MCP）共用的唯一来源。
- **计费**：模型回执落库；同样的请求只计费一次；发出后结果不明的调用不重发、也不换请求重做，对应公司记为缺口，名单照常交付并写一行缺口摘要。
- **接口**：`/api/v4/reports/latest`、`/api/v4/reports/{日期}`、`/api/v4/reports`、`/api/v4/documents/{id}`、`POST /api/v4/devices`（Bearer）；`/api/v4/health`（不含任何凭据或内容）。
- **只读网页**：`/read/<访问码>`（最新一期）、`/day/<日期>`、`/history`、`/doc/<id>`，`?format=json` 给 Agent 读；访问码是独立的 `NECKLINE_READ_KEY`，不对或未配置一律 404；禁止索引、缓存和 Referer。
- **配置与凭据**：`/etc/neckline/v4.env`（root:neckline 0640）放库路径、DeepSeek 密钥（从 v3 库 `llm_providers` 移来）、网页访问码；`neckline.service` 增加加载它。App 设置页从此不再管模型密钥。
- **发布工具**：`release.py` 把 V4 库纳入恢复点与还原校验、核对其属主权限，V4 任务在运行时拒绝切换，V4 timer 纳入切换前后状态一致检查。
- **顺带**：`test_b56` 的版本一致性用例改为 V4 口径（后端版本即对外版本，App 在 P3 升到同一版本前可以不同；它对旧 README 的断言在 10/14 重写 README 后本已失效）。
