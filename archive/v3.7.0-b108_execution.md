# Neckline 3.7.0 Build108（B108）执行记录

## 1. 范围与根因

B107 部署后按真实入口恢复 2026-10-11 晚报任务 `task_194cafa3c466bd115642eda7105aae55`。受控恢复授权和冻结资料哈希校验均通过，但 worker 在重新进入同一 `scan_id` 时，扫描仍是 `failed`，第一处运行扫描 coverage 检查抛出“扫描不是当前 running 状态”，任务被错误落成 `not_configured`，仍未产生新外呼。

这是恢复状态转换缺口：同一不可变任务已获恢复授权，却没有在 handler 重建 scan 时原子地清除终态。它与 B107 的正文重复引用问题相邻，但原因独立。

## 2. 实施

- `Backend/neckline/k10/store.py` 的 `create_scan()` 在同一冻结身份以 `running` 重入时，将 `queued`、`failed`、`not_configured` 投影重新打开并清除 `completed_at`；覆盖内容仍保留原冻结输入，不接受 cutoff、配置或身份变化。
- `Backend/tests/test_k10_v306_storage.py` 增加终态 scan 重入回归，断言原冻结 coverage 不丢失。
- 对外版本保持 3.7.0，Build 升至 108；同步 App 图标、API release set 与发布记录。
