# Neckline 4.0.0 Build111（B111）执行记录

B110 上线后发现的采集问题的修复，只改后端，App 不动。线上基线 `v4.0.0-b110`（`412ec3d`）。

## 1. 起因

- TuShare `major_news` 每个账号每天最多调用 40 次（超限返回 code 40203「频率超限(40次/天)」）。B110 对整段窗口发一次请求、满 400 条就对半切再取，33 小时的首次采集层层切分用了十几次请求，叠加前一天彩排的用量后被拒。
- B110 的来源水位只认「完整覆盖」：首次采集里没取完整的来源（生产上的 TuShare），之后定时采集不带起点就记「没有采集起点」，永远补不回来。

## 2. 范围（Cursor grok-4.7-xhigh 施工，主会话验收）

- `neckline/news/tushare.py`：先把窗口切成首尾相接、互不重叠、每片不超过 `sliceSeconds` 的整秒片，按时间先后逐片请求；某片满 400 条只把这一片对半切再取。`code == 40203` 或提示含「频率超限」记 `quota_exceeded`，立即停止、保留已取到的文档，不记响应原文。
- `neckline/morning/collect.py` + `db.py`：起点依次取「完整覆盖水位减回看」→「该来源首次真正尝试的起点」（新增 `db.source_attempt_start`，跳过「没有采集起点」的空记录）→「显式给的起点」；三者都没有才记 `bootstrap_start_missing`。
- `config/collection-v4.json`：TuShare `sliceSeconds` 10800、`maxRequests` 30，并注明每日 40 次的上限。
- `report.py`：缺口摘要认识 `quota_exceeded`（「达到每日调用上限」）。
- `api/app.py`：`RELEASE_SET` 升为 `v4.0.0-b111`。
- 测试：`tests/test_morning.py` 新增 6 项（切片、只细分满额片、额度中断保留已取、首次不完整后从首次起点续采、无尝试记录仍要求起点且不发请求等）。
