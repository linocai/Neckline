# 金十 MCP：Neckline 资讯适配实测

2026-09-26，用户提供 Token 并授权真实接口测试。结论：**适合优先增加短快讯入口；可补充行业、政策、宏观和风险线索；不能作为唯一公告来源、早报排雷依据或通用核验搜索。** 尚未接入生产。

本轮仅做独立来源测试，未运行正式报告、调用模型/Tavily/APNs、写生产库、恢复报告开关或修改运行代码。B91 未发布状态与此前生产暂停约束不变；本次金十测试授权不扩大其他供应商权限。

## 1. 测了什么

- 北京时间 13:07–13:18，标准 `initialize → notifications/initialized → tools/list / resources/list → tools/call`，另读取 `quote://codes`。协议 `2025-11-25`，Bearer 仅发送至金十 MCP 域名；业务读取 `structuredContent`。
- 8 个工具全部调用；268 次 `tools/call` 均返回结构化业务状态 200，无 HTTP、JSON-RPC 或工具业务错误。本次正常读取通过不等于长期稳定性、并发/故障恢复或费用验证。
- 82 页快讯、1,633 个不同原网页 URL；3 页文章目录、47 个不同 URL；10 篇文章正文；30 家真实池内公司名称检索；事件、行业、风险、宏观、供应链关键词及反例检索。
- 固定股票池 1,089 家，原文件 SHA-256 `161c1dbbf7119a3ce5bf9d6aa183635eb0af05eee7b77d9e962ede5f54eb3b48`。抽样由 7 家指定池内公司加剩余有序池等距抽取的 23 家组成，**不是昨晚真实报告名单，也不是全市场召回率研究**。
- 机器证据：[查询清单、调用指纹与统计](2026-09-26_jin10_probe/evidence.json)。原始批量响应仅供本轮分析，收尾回收；不把全部新闻正文存进项目。

## 2. 能承担哪些需求

| Neckline 需要的资讯/动作 | 实测 | 适用位置与限制 |
|---|---|---|
| 从大量短消息发现变化 | 快讯正文、时间、链接可直接取得；中位正文长度 44 字 | 最值得优先接入晚报与隔夜发现入口。短消息不必再寻找“更长的全文” |
| 订单、中标、扩产、停产、涨价、并购、重组 | 相关快讯检索均有结果 | 能发现变化；是否重大、是否关联池内公司仍需理解 |
| 临床进展、药品获批、入组 | 能找到对应类别；但未找到用户指定的广生堂事件 | 有用但不完整，不等于临床/药监公告全量库 |
| 业绩、增减持、回购 | 快讯能查，文章也有公告摘要集合 | 适合线索与复核辅助；摘要不等于公告原文 |
| 立案、澄清、终止、诉讼、冻结、处罚、退市、违约 | 相应快讯均有结果；长文有些类别为空 | 能提示风险，不能以空结果宣告公司安全 |
| 储能、算力、半导体、创新药、出口管制、政策 | 快讯与部分文章可查 | 可发现间接催化；不能把板块关键词当作公司关系证明 |
| 原油、美联储、关税、欧佩克等外部变化 | 快讯与文章均较丰富 | 可补充成本、需求和政策传导信息 |
| 互动易、问询函、调研、客户、供应商 | 能搜到部分报道 | 不是互动平台、投资者关系记录或供应链资料的完整检索 |
| 已选文章深读 | 10/10 返回正文，1,374–19,749 字符，明显区别于简介 | `get_news` 适合取金十文章文本，不支持任意外部网页/PDF提取 |
| 消息原件与引用 | 列表和正文带金十原网页链接；抽查 3 个页面 HTTP 200 且含对应内容 | 能交付金十消息/文章页面；真正交易所公告 PDF、监管原件需另找 |
| 财经日历 | 返回当周 158 项 | 宏观事件辅助；不是上市公司专用事件日历，返回时间未显式标时区 |
| 行情、K线 | 黄金和创业板指数报价、黄金 3 根分钟线读取成功 | 品种表 97 项，含主要指数/商品/外汇，不能替代股票池个股行情与 D1/D2 数据 |

上述有结果表示存在该类资讯，不表示每条有用、每家公司覆盖完整，也不构成选股结论。

## 3. 实测的关键证据

### 3.1 确实有我们要的短消息

- [华康洁净中标并签署医疗专项合同](https://flash.jin10.com/detail/20260924183942506800)：9 月 24 日 18:39，消息主体直接为池内公司；短文给出合同对象和金额，属于值得交给 Agent 判断的具体经营变化。不能因此直接裁定该股应上榜。
- [联合化学控股股东等拟减持](https://flash.jin10.com/detail/20260924215144518800)：9 月 24 日 21:51，能够进入对应晚间之后的风险复核窗口。
- [亚虹医药临床试验首例入组](https://flash.jin10.com/detail/20260922174256881800)：证明“入组”类短讯存在；这是类别能力样本，**不是池内推荐**。

### 3.2 用户举的广生堂事件仍未找到

`search_flash("广生堂")` 返回 7 条，最新为 9 月 17 日增资消息；`search_news("广生堂")` 返回 0 条。补测 `GST-Peak-Triple`、`广生中霖`、`首例试验参与者`、`入组`，仍未取得用户 9 月 4 日所举事件。

可确认的是“这组接口与查询在本次测试中没有检出”。不能据此证明金十全站从未刊载，更不能否认事件发生。产品上已足够说明：只用这个入口，不能保证抓住用户关心的这种变化。

### 3.3 公司搜索存在确定的漏检，不只是内容少

30 家池内公司以名称检索：快讯 25 家非空、5 家为空，共 116 条历史结果；文章搜索 30 家全部为空。这些是跨历史结果，不能说成 25 家当日有新闻。

进一步对照：[9 月 16 日文章](https://xnews.jin10.com/details/230277)的正文确实包含赛意信息合同变化，`get_news` 也取得该段；但 `search_news("赛意信息")` 为 0，按文章标题中的“昔日半导体龙头”可找到。同样，另一篇正文含安靠智电，按公司名搜不到，按“CRO巨头”能找到。

**不能把 `search_news` 当作全文公司搜索。** 表现与偏向标题等字段检索一致，但服务端未公开具体索引规则，不能断言它严格只搜标题。公告精选类集合文章应读正文并辨认其中不同事件，不可只看主标题。

### 3.4 搜索词不能照搬通用搜索引擎

- `search_flash("联合化学")` 返回包含减持的消息；`search_flash("联合化学 减持")` 却返回 0。其他“公司名＋事件词”组合也出现空结果。
- “广生堂”有结果，“300436”为空；另外测试的 300750、300308、601727 代码均为空。不能把股票代码视为稳定的搜索键。
- 优先用明确实体名称/单独事件词，按问题需要使用别名，再在本地判断关系；不要把已有 Tavily 长查询字符串直接塞给金十。
- `search_flash` 明确最多 150 条、不能翻页。热门主题常达到 150 条，截断后不能声称历史搜索完整。`search_news` 支持分页；原油、半导体的第二页均取得 10 条且不与第一页重复。

### 3.5 关键词匹配不能证明与公司相关

本次快讯里的“叙利亚德拉省”会机械匹配池内“利亚德”。这是确定的错误关联，不能计为公司覆盖，更不能变成推荐。统计证据中的名称子串命中仅是排查线索。

消息→真实主体→经营关系/有依据的传导→池内公司，仍然需要 Agent 理解与证据核验。更换资讯源不会自动修复弱关联问题。

## 4. 时间窗、覆盖和历史边界

| 本次模拟窗口（北京时间，左闭右开） | 快讯 | 文章目录 |
|---|---:|---:|
| 9/24 21:00 → 9/25 21:00，24 小时 | 732 | 20 |
| 9/25 21:00 → 9/26 08:30，11.5 小时 | 273 | 1 |

这是按产品窗口形状截取的自然日样本，包含假期/周末，**没有运行对应正式报告，不代表交易日常态流量或全市场覆盖率**。另看已取到的 9/24 13:45–21:00，可看到 A 股公司合同、减持等消息；不能拿假期样本中公司新闻较少证明它平日也少。

列表翻页无时间倒序异常、缺 URL 或跨页重复 URL；重复读取同一个已返回游标，本次结果完全相同。这证明本次分页遍历成立，不证明上游没有漏发、迟发或事后修订。

**翻到 `has_more=false` 后，快讯最早为 9/24 13:08，文章最早为 9/24 13:33；读取发生在 9/26 13:16 左右。** 本次列表可见范围约 48 小时，未能继续覆盖 9/23 21:00。服务端工具说明未承诺保留期限，所以这是一项实测边界，不写成永久“48 小时规则”。关键词搜索可以返回更老资料，但不等于可全量回补历史。

实际接入应按返回的 `cursor`、`next_cursor`、`has_more` 遍历，记录明确覆盖窗口与缺口；恢复时不能用旧新闻填补当期，更不能因为列表见底就声明任意业务窗口完整。若需要跨停机/假期保留，应正常增量采集并本地保存已授权材料，而非依赖事后回补。

## 5. 给工程的接入建议（尚未实施）

1. **先增加快讯流。** `list_flash` 进入现有多来源采集边界，与 TuShare 独立记录窗口、失败和来源。1,633 条中有 1,602 条没有独立 `title` 字段，但全部有正文；不能按“标题为空”丢弃。短快讯本身即可给 Agent 阅读，无需强制另找长文或编造标题。
2. **文章作为补充。** `list_news` 提供目录，按需要用 `get_news` 读正文。公告精选在正文里包含多家公司，不要把主标题主体当成整篇唯一公司，也不把集合文章中的旧事自动当成当期变化。
3. **搜索用于补线索。** 公司名称、必要别名和事件词分别检索；按固定业务窗口筛新消息，保留历史背景的真实时间。不要遍历 1,089 家公司再把零结果写成“无风险”。
4. **早报继续双通道。** 隔夜发现读取窗口快讯；昨晚公司复核读原理由，再取得相关消息/公告证据。金十搜不到、结果截断或覆盖不足都保留缺口，不能判安全；不能让回补阻塞两条通道。
5. **保留原公告与针对性核验来源。** 金十不是全量交易所/公司公告库，也不提供通用网站、年报、合同、监管文件或供应链关系验证接口。保留现有核验能力；按具体缺口决定下一种来源。
6. **不改选股标准。** 快讯多不等于推荐多。仍由 Agent 判断变化是否有意义、公司关系是否成立，允许自由解释和零推荐，不能以消息数量或“关键词命中”替代判断。
