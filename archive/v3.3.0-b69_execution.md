## 3. 生产模块契约与关键决定

### 3.1 事件问题和材料准入

- 沿用`Question`的claimIds／companyCodes／supportCondition／refuteCondition及`QueryPath`的intent／newPathReason／expectedInformationGain／expectedJudgmentChange。系统绑定当前event、冻结claim和问题含义；不能通过更换questionId或把公司背景写得更宽来重开同一问题。新增查询必须说明能改变哪项当前判断、与已查路径相比有何新材料线索。
- 语义判断放在已有plan_gaps／plan_queries／assess_evidence回复中，程序验证引用、身份、类型、状态和可证明重复；不以关键词命中伪造语义相关性，也不额外造付费分类器。普通公司简介、历年客户列表、客户的客户、供应链无限延伸不自动成为必要调查。必要关系仍可查直接合同、公告、事件原始报道及直接反证。
- 新增一个共用生产材料准入函数／数据契约，由`verification.py`、`research_runtime.py`和初始正文／局部读取调用。输入包含真实sourceRef、文档标题／元数据／正文结构、当前question scope和两类时间；输出为`admit／excluded／needs_locator`及稳定原因、适用性、来源版本。分类依据持久化来源，模型传入的任意URL／“官方”标签不能自行获得准入。
- 招股书在搜索已保存标题／摘要识别时即阻止Extract；伪装标题而正文后来才识别，则保留已花费用但不发送正文，不再重复提取。已缓存招股书、全文原文回读、initial understand和contextResults同样受限。拒绝是局部材料结果，不让同批其他有效资料失败；正文中的指令不执行。
- 初始标题继续全量短筛和记账，实际文档被排除时记录可解释的资料处置，不能篡改原冻结输入或把未读正文说成已读。报道某企业招股／上市事件不等于其文档本体就是招股书；保留相关正常新闻和直接公告。
- 年报不是一律拒绝：已有资料够用则不再取；确有当前事件必要问题、直接适用章节且有明确定位时可取必要片段。不得用旧客户名单证明新订单，不得把草稿公司资料升为独立已核事实。

### 3.2 结构化局部读取及可见证据

- 完整来源仍保存在当前本地版本库；新增轻量确定性文档索引，按标题层级／段落／句子／表格结构定位，绑定`documentId + revision + contentSha256 + indexVersion`。复用现有读取协议，增加目录／区段定位和必要的分页续读；不是引入向量库或全文件LLM摘要流水线。
- 片段至少含sourceRef、sourceContentSha256、locator／原始偏移、section标题、原文text、publishedAt／precision、fetchedAt、contentVersionAtCutoff、eligibleAtNewsCutoff及question关联；表格片段保留表题、列头、单位、期间、相关行和适用脚注。跨段否认／限定语必须随所选事实保留。
- `_assess_due`改为传新增且必要的片段／已确认事实，不能再将`analysis_text or original_text`整体作为默认text。只有实际显示并审读的片段才记为已读；不能因为读过一段就把整篇标记完成。片段读状态跨切片和重启保持，新增区段可继续读取，不通过改写请求理由再读同区段。
- `read_context(source)`不能用`splitlines()`的一整条超长行规避局部读取。段落／单字段过大时先给定位信息和继续读取入口，按结构分解；不可`text[:N]`、任意首中尾抽样或删掉脚注来凑尺寸。必要的完整结构确实超出单请求可承受范围时分步读取，汇总带引用的事实，不发送全量分块拼接。
- `allowedEvidenceRefs`继续只允许本请求实际可见且适用的证据；新增片段manifest和公司字段manifest共同参与验证及请求指纹。模型引用的locator必须落在本次可见片段，数据库中有全文不等于模型已经读到全文。未知locator返回无证据及必要纠正，不能自动补成事实。
- 对时间未知材料，允许只读必要的日期／版本定位片段以辨别适用性，不可绕过时间检查整文载入；明确在截止后发布的材料不为该报告提供当前事实。真正的直接反证、迟到但已准入来源及报告期 caveat不得被缩短过程误删。

### 3.3 同任务来源事实共享

- `research_store._eligible_prior_source`显式区分同任务冻结版本和历史来源，不简单删除`fetched > news_cutoff`检查。同任务claim只有其准确source版本已经属于接收事件合法冻结输入、来源适用性成立、提供方事实快照在本次verification cutoff之前时才共享；允许正常采集在名义21:00之后结束。
- 冻结准入须从持久化任务／事件引用和真实版本核实，不能只相信调用方传入allowed。另一任务／另一版本、未准入来源、未来发表／修订、未知时间／未知版本仍隔离，记录理由。用UTC瞬时比较带时区值，保留原始时间字符串。
- 共享的是有定位和provenance的来源事实，保留原verificationStatus、限定语和证据；不共享比较／排名／机会身份，不把其他事件的公司推断当事实。修复不能把207项全放开，尤其非接收冻结输入的那一项须单独判断。
- `_freeze_prior_evidence`目前只读一次；本轮使相关已持久化事实增量在下一个必要业务动作前可见，避免并发事件先读到空集后永久失去共享。按相关事实版本水位追加manifest，只有实际新增／撤回／修订事实才改变输入；本地时间、观察顺序、无关事件不得改变请求身份。
- 跨事件可复用同源片段的已读事实，但新的问题确实需要未读片段或新的反证时仍可读。不能把“有同源缓存”当作其他事件已完成分析。旧的runtimePriorEvidence／付费结果不覆盖修改，按当前协议追加可追踪派生记录。

### 3.4 全动作公司资料投影

| 动作 | 默认可见内容 | 需要时局部读取 |
| --- | --- | --- |
| titleBatch／titleReconcile | 维持完整标题覆盖与已有候选线索，不带全公司档案 | 按现有短筛／固定池规则 |
| understand | 当前来源内容、候选公司身份／短业务摘要／草稿状态 | 提取事实所必需的具体业务字段，不重新尽调 |
| plan_gaps | 当前事件claims、相关公司摘要、已知关联事实和缺口 | 决定必要问题的具体字段及其来源 |
| plan_queries／assess_evidence | 当前开放／受影响问题、必要公司身份、已显示事实、新资料片段 | 当前问题直接所需的字段／片段 |
| close_research | 当前判断所需事实、剩余缺口、路径结果和简明公司关联 | 影响收口但尚未显示的具体字段 |

- `company_search`先返回候选身份／相关匹配字段目录和定位，不返回完整profiles；`company_fields`只取请求的必要字段及其引用，超长列表按条目／结构读取。禁止通过请求`sources`全表、超长summary或把全部字段塞进一个value绕过守卫。

### 3.5 最终请求守卫、付费重用与无进展停止

- 在`pipeline._request_json`形成真实system/user messages、输出契约、contextResults、修正反馈后统一测量；`MeteredProvider`在HTTP／付费attempt启动前作最终断言，避免其他生产模型路径旁路。覆盖原文、研究、归并／排序、晨报、正反分析；不改变各路径的业务职责。
- 使用实际冻结端点／模型能力和本地官方编码方法；锁定编码实现及能力资料版本／hash，优先复用轻量官方tokenizer资产，不下载权重；依赖／词表随发布物提供，生产运行时不得下载或联网计数。计算实际模型输入token或明确标识的保守上界，加上现有maxTokens输出预留及已核实的消息封装开销，必须满足物理上下文边界。未知兼容模型能力不可猜值，返回可读的能力配置问题且无付费请求；保持BYOK能力扩展可显式配置。
- 主要约束仍是必要片段／字段投影，不能把靠近1M当正常目标，也不能用全档案分块全部读一遍抵消禁读规则。守卫发现过大时先由本地装配器确定性缩小为可继续定位的结构或分步必要工作；不把大原请求加一段“请压缩”再发模型。不可缩减的契约／必需原子结构明确记录执行阻塞，不虚构成功。
- 保留真实HTTP请求指纹：task作用域、operation／语义契约、冻结证据／公司资料依赖、实际端点／模型、messages、response_format、实际model_options。Key和内部item／checkpoint ID不是语义差异；反证、新来源版本、资料变更或输出选项改变则必须失效。只可证明无语义差异的身份变化才复用，不做模糊相似prompt缓存。
- 优先重用现有完成检查点；补上同task跨内部ID的精确已付回复重用。将付费响应和原attempt关联耐久保存，再做解析／业务校验；成功、格式失败、语义被拒分别标记，当前校验通过才成为可消费结果。来源／scope／contract变了不能用旧回复顶替，旧拒绝记录不覆盖。既有B68私有拒绝回复尽量本地重验，找不到足够指纹证据就不假称可复用。
- 保证并发相同请求只有一个实际派发，原attempt账本和实际用量不改。接收响应→保存回复→结算账本→完成检查点各处中断都要测试；本地确定回复可据回执幂等补写，真实started／unknown且无可靠回复不能再外呼。不得为重用把历史token清零，新的本地重验记录与实际付费记录分开。
- 沿用现有network／JSON修正次数，不新增总token／搜索／文章／公司上限。局部可推导字段、池外可选线索和重复引用先确定性整理，再重验原回复。无新增证据、字段或实质纠正的同输入循环，在发下一次请求之前终止；规范错误重复时保留具体失败，不包装成研究完成。
- 搜索无结果／明确排除材料／无新增线索，可回到已有close_research按既有规则披露未核实并比较；真正429／额度／网络未知／存储故障继续真实执行状态。不能为“顺利出报”把技术失败转成无证据，也不能因局部无用线索让整批有效结果失败。

### 3.6 定时暂停、接口和旧状态

- `cli`为scheduled触发显式区分正常不执行与错误。closed且原因可读时输出结构化`skipped`／`paused`及reason、无taskId，退出0，不创建scan／task／失败通知；手动enqueue／recover仍拒绝暂停状态。非交易日按现有正常跳过规则，未知日历／配置不合法／数据库不可读不能吞成暂停成功。
- 捕获必须限于明确的暂停信号，不用广泛`except RuntimeError`吞所有失败。验证开关读取与真正入队之间的竞态：若期间关闭，scheduled仍可识别为暂停，不能漏入队；恢复开关只能由已授权运营动作执行。

### 3.7 Schema9私有响应回执：必要性、原子性和回退契约（2026-09-14补充裁定）

**决定：实施Schema9，仅新增付费模型响应回执及必要索引，不重建旧业务表。** 此项为P07所需的内部持久化修复，主会话认可；不是新增策略、收费额度或用户可见协议。生产在实际迁移前仍Schema8。

窄核对结论：

- `k10_external_attempts`只有请求hash、状态和用量，没有模型响应；`MeteredProvider.chat`在返回后、业务解析前就结算attempt，之后才可能保存业务结果，存在“已付且已结算、尚无可消费回复”的中断窗口。
- `k10_execution_item_checkpoints`以task／item／stage定位、保留校验后的业务结果；失败重试可更新行，running在`model_execution._reserve`被解释为unknown。将未校验原回复塞进completed会破坏现有成功语义，塞进running／failed又无法自然完成跨item去重和不可变回执归属。
- `k10_research_stage_results`受snapshot／revision及研究动作外键约束，只覆盖研究、写在业务动作之后；不能作为understand／标题／晨报／正反分析的统一provider回执。
- `model-diagnostics`仅在解析出Mapping且被拒时保存，依赖item和旧语义恢复标识；写文件失败只warning，且文件与SQLite账本无法同事务。完整重建文件锁、全阶段索引、结算对账与恢复协议比一个同库小表更复杂，也不能借“文件存在”证明账本已一致。保留旧文件的只读重验能力，不批量迁移或伪造旧响应。

表和归属合同：

- 新表建议名`k10_model_response_receipts`，**每个真实external attempt至多一份不可变provider回执**。最小字段：attempt_id（主键／外键）、task_id、stage／operation、request_sha256（实际wire指纹）、reuse_scope_sha256（冻结语义依赖）、payload_json、payload_sha256、received_at、receipt_version及provider_result_state。字段名可在不改变含义下由builder统一。
- attempt/task双重归属必须受校验；可给原attempt表只增加`UNIQUE(task_id, attempt_id)`索引并用复合外键，或用同一事务的`INSERT ... SELECT`从attempt读task和hash并严格校验。两种均不得重写原attempt_id／item_key／attempt_key／input_sha256；禁止以调用方任意taskId关联别人的响应。原账本只有正常started→最终状态结算，已结算行仍不可改。
- 建索引`(task_id, request_sha256, reuse_scope_sha256, received_at, attempt_id)`用于精确候选读取；**不对task＋request hash设置单一唯一约束**，确定失败后的合法同请求重试可产生另一attempt／receipt。并发派发互斥在BEGIN IMMEDIATE中检查实际请求的started／unknown／已有成功回执，再保留原attempt身份建立唯一派发者，不靠进程内锁。
- payload只保存恢复LLMResult所必需的模型content、返回模型／finish_reason／实际usage和安全错误字段，不存完整prompt、Key、请求Headers或credentials。响应文本属于私有运行数据，和生产DB同权限、仅后端store可读；公开API／状态／日志只允许hash、长度、计数和安全原因，不返回payload。
- provider返回成功不等于业务校验通过。回执原payload／hash／来源attempt／时间不可UPDATE；初始状态只描述provider结果。当前caller的解析、证据scope及contract校验结果继续写原业务checkpoint／追加研究记录并关联receipt；不能把一个全局validated标志当成任何任务／版本都可直接采信。后续本地重验不覆盖历史拒绝。
- 回执payload以版本化规范JSON编码并校验hash；同attempt再次保存必须逐项相同才幂等，内容不同视作存储冲突并停在本地，不外呼“修复”。实际HTTP费用只属于原attempt；local reuse不生成新的已付attempt、不再写一份供应商usage假装新调用。

写入和中断合同：

1. 在任何网络派发前，先由既有spend guard／lease／closed及额度检查准入；同库事务按实际输入和scope查已有回执或正在派发attempt，再登记这一次派发。不同内部checkpoint ID不能绕过，新的语义输入不能被旧回执挡掉。
2. 收到可确定响应后，**保存回执和结算原attempt使用同一SQLite事务**，事务提交后才把结果交还业务解析。无响应／运输结果未知保持unknown，不能凭缺回执重发。响应已经在内存却本地提交失败时不得再次请求供应商；保持可辨识的未决状态并报告本地持久化故障。
3. 若中断发生在该事务提交之前，则账本仍started／unknown、业务未完成且无已提交回执，恢复拒绝盲重试；提交之后、业务检查点之前中断，恢复从回执本地解析／校验／补写，不再次付费。业务校验失败仍保留该真实响应供确定性整理或授权重验。
4. 同一已知回执的幂等读取／补写可在生产暂停时用于离线核验，但不会由读取自动推进正式任务、开放开关或通知。任务控制和原过期时限继续生效。

Schema8→9迁移合同：

- `initialize_schema`在已有BEGIN IMMEDIATE内逐条执行DDL／必要索引、最后追加版本9记录；失败整体回滚，重复初始化幂等。覆盖空库及支持的历史版本升级路径，生产本次只从已确认Schema8前滚。GET／只读helper只校验版本，无DDL。
- 迁移本身回执表为空，不扫描导入旧私有文件、不改任务／报告／配置／来源／paid usage／通知内容；旧外呼计数、所有主键、原冻结hash和Schema8业务表逐行hash必须不变。若新索引建在旧attempt表，仅允许索引结构变化。Schema迁移表只追加9，通知Schema2不变。
- 内部`schema.SCHEMA_VERSION=9`与公开协议分开。`V2ReportEnvelope.schemaVersion`继续整数8，现有字符串k10-api-v2／v3保留；真实Schema9库的零scan四scope、空态、失败／成功报告必须被当前Swift解码，receipt字段不得漏进DTO。
