# Neckline 4.0.0 更新计划与执行记录

2026-10-14 用户决定：v3（K10-v2 选股器，最后版本 3.7.0 Build109）当天退役，改做轻量的 V4。V4 由专门的工程 Agent 负责。本文是 V4 的计划，也是 V4 执行证据的记录处；PROJECT_PLAN 只保留现状与未完成块。

## 1. 为什么重做

- v3 的流水线按「研究报告」设计：标题筛选、逐篇深读、多轮联网调研、排序、D1/D2 观察窗口、晨报复核昨晚推荐，用户操作后还会触发正反分析。10/13 一期晚报要调 1,574 次模型、跑约 1 小时、用掉一千多万 token，而且各环节频繁卡住，B105–B109 修的都是这套流水线自身的问题。
- 用户真正要的是「每天定时给我一份能看的消息名单」。看中某条后，用户会直接去问 ChatGPT 或 Claude，不会在 App 里继续操作。
- v3 的选取规则与用户偏好相反：方向中性、没有时效约束，导致立案、复牌、一个月前的旧事、风险汇总专栏都进了名单。案例见 [2026-10-14_消息偏好讨论](2026-10-14_消息偏好讨论.md)。

## 2. V4 是什么

**创业板消息筛选器。** 每天两次，服务器用 DeepSeek 从新采集的消息里筛出与固定创业板公司池相关、新近发生的利好，生成一份名单；iPhone 收到推送后点开 App 阅读。需要深入时，用户在 ChatGPT 或 Claude 的对话里通过 MCP 读取同一份名单与原文，再结合 Agent 自己的搜索与思考讨论。盘中如需看股价反应，Agent 调用 KX 的行情接口。

用户的使用节奏：
1. 21:00 收到「晚报已出」，打开 App 看名单，然后分别和 ChatGPT、Claude 聊（兼听则明）。
2. 交易日 09:10 前收到「早报已出」，同样先看再聊。
3. 盘中可以问「消息有了但股价没上去，要不要换标的」，Agent 用 KX 行情结合名单回答。

## 3. 已定的决定（2026-10-14，用户）

- **版本**：对外版本 4.0.0。
- **组成**：iOS、macOS 两端 App 加 MCP 服务，后端和 MCP 都部署在 NB 云。
- **筛选**：仍由服务器调用 DeepSeek 接口，定时运行。
- **用户偏好**：一是利好，二是时效性。负面消息不进名单；复牌之类的程序性公告不进；回顾稿、专栏汇总里的旧事件不算新消息。
- **推送**：只推 iPhone，内容只有「晚报已出」或「早报已出」，点开进 App 看；Mac 不推送。
- **时间**：晚报 21:00 推送（交易日前一自然日）；早报在交易日 09:10 前拿到。
- **App**：在现有代码基础上改，只剩看名单。删除正方/反方分析、留下观察/略过、关注、选股表现；不做「复制给 AI」，因为 Agent 直接读 MCP。
- **MCP**：只读，参考 KX 的做法（工具设计、OAuth、只读网页兜底、数据时间标注），ChatGPT 和 Claude 都要能接入。
- **行情**：用 KX 已有的行情接口，不在 Neckline 里另做一套。V4 和 KX 不同的是始终以消息面驱动。
- **公司池**：沿用已批准的固定 1,089 家创业板公司与资料。
- **v3 退役**：采集、晚报、早报、两个行情 timer 和 worker 已于 2026-10-14 19:50 停用（stop + disable），API 保留只读历史，数据库原样保留。

## 4. 目标架构

```
采集（金十 MCP、TuShare 新闻）── 出报前采一次
  → 规则粗筛：匹配公司池、去重、拦回顾稿/汇总专栏/程序性公告
  → DeepSeek 批量分类：公司、事件类型、利好/利空、事件发生时间、重要程度、一句话理由
  → 按配置规则选择：利好、事件在上一期之后发生、重要程度够、条数上限
  → 名单记录（编号、种类、截止与生成时间、条目、缺口摘要）
      ├─ APNs 推送 iPhone「晚报/早报已出」
      ├─ App（iOS/macOS）阅读：最新名单、条目原文、历史名单
      └─ MCP（只读）→ ChatGPT / Claude；盘中行情走 KX
```

### 4.1 服务器流水线

- 一期名单的模型调用应在几十次量级、几分钟内完成；不做逐篇深读、多轮调研和 Tavily 搜索。
- 选择规则写进配置并由用户确认，策略层不设默认值。规则包括方向、时效窗口、排除类别和条数上限。
- 名单条目字段：公司代码与名称、事件标题、一句话利好理由、事件发生时间、原件来源与链接、发布时间。
- 局部失败只剔除相关条目并在名单里如实写一行缺口摘要；不再出现 v3 那种成墙的警告。
- 可复用的 v3 模块（复用前先审，不要整包搬）：
  - 采集：`k10/jin10_mcp.py`、`k10/jin10_normalize.py`、`k10/tushare_news.py`、`k10/collection_gateway.py`、`k10/collection_runtime.py`、`k10/sources.py`；
  - 模型调用：`llm/openai_compat.py`、`k10/providers.py`、`k10/metering.py`（回执与计费）；
  - 推送：`k10/notifications.py`、`k10/notification_runtime.py`；
  - 其他：`settings_store.py`、`k10/v2_profiles.py`（公司池与资料）、`calendar/`（交易日历）、`k10/worker.py`（任务租约）、`scripts/release.py`（发布）。

### 4.2 MCP 服务（NB）

- 工具（只读）：
  - 读取最新或指定日期的晚报/早报；
  - 读取单条消息的全文与原链接；
  - 按公司或关键词、时间范围查消息；
  - 读取公司池；
  - 检查服务状态。
- 返回数据都带名单编号、数据时间和缺口说明，确保两个 Agent 读到的是同一份名单。
- 认证：OAuth 同时允许 ChatGPT 和 Claude 的回调（KX 目前只放行 ChatGPT，见 `KXMarketTool/AGENTS.md`）；另提供只读网页链接作兜底（参考 KX 的 `/kx/read/<key>`）。
- 写一份 Agent 用的策略说明（参考 `whynotme/KX.md` 的写法），ChatGPT 和 Claude 共用：怎么读名单、用户偏好、盘中怎么结合 KX 行情判断、回答格式。
- 验收必须在 ChatGPT 和 Claude 的手机端与电脑端实际调用工具；服务器冒烟测试不能代替。

## 5. 阶段与验收

1. **P1 服务器名单**：采集时间贴着出报、规则粗筛、DeepSeek 分类与选择、名单记录与 API。先拿 10/13 真实采到的 2,184 条离线跑，用户逐条点评并调参，直到满意再上线。验收：名单只含新近利好；每期几十次调用、几分钟完成；中断能续跑，且不重复计费。
2. **P2 MCP 服务**：工具、OAuth（ChatGPT + Claude）、只读网页兜底、Agent 策略说明，部署到 NB。验收：两个 Agent 在手机端与电脑端都读到同一份名单，内容和推送对应的名单一致。
3. **P3 App**：按 4.4 改造。验收：三条 Apple 构建通过，样图经用户确认，iPhone 真机收到推送并能点开看到名单。
4. **P4 KX 行情**：核实套餐后按 4.3 改 KX。验收：盘中 Agent 能取到名单内创业板公司的分时并标明时间。
5. **P5 发布 4.0.0 与清理 v3**：一条龙发布；按「退役功能直接删除」移除 v3 的代码、配置、测试、timer 与存量数据（删除前先备份并确认）；清理 NB 上约 5 GB 的旧恢复集。
