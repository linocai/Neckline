# Neckline 4.0.0 更新计划与执行记录

2026-10-14 用户决定：v3（K10-v2 选股器，最后版本 3.7.0 Build109）当天退役，改做轻量的 V4。V4 由专门的工程 Agent 负责。本文是 V4 的计划，也是 V4 执行证据的记录处；PROJECT_PLAN 只保留现状与未完成块。

## 1. 为什么重做

- v3 的流水线按「研究报告」设计：标题筛选、逐篇深读、多轮联网调研、排序、D1/D2 观察窗口、晨报复核昨晚推荐，用户操作后还会触发正反分析。10/13 一期晚报要调 1,574 次模型、跑约 1 小时、用掉一千多万 token，而且各环节频繁卡住，B105–B109 修的都是这套流水线自身的问题。
- 用户真正要的是「每天定时给我一份能看的消息名单」。看中某条后，用户会直接去问 ChatGPT 或 Claude，不会在 App 里继续操作。
- v3 的选取规则与用户偏好相反：方向中性、没有时效约束，导致立案、复牌、一个月前的旧事、风险汇总专栏都进了名单。案例见 [2026-10-14_消息偏好讨论](2026-10-14_消息偏好讨论.md)。

## 2. V4 是什么

**创业板消息筛选器。** 每个交易日早上一份晨报（2026-10-16 起不再有晚报，见 §6），服务器用 DeepSeek 从上个交易日收盘到当天 08:00 新出的消息里，筛出与固定创业板公司池相关、这段时间首次公开的利好，生成一份名单；iPhone 收到推送后点开 App 阅读。需要深入时，用户在 ChatGPT 或 Claude 的对话里通过 Neckline 的 MCP（2026-10-18 起是对话 Agent 唯一的入口，见 §6）读取同一份名单与原文、查股票池、看单票的技术面概览，再结合 Agent 自己的搜索与思考讨论。

用户的使用节奏：
1. 交易日早上名单一出来（约 08:05–08:10）收到「晨报已出」，打开 App 看名单，然后分别和 ChatGPT、Claude 聊（兼听则明），开盘前决定。
2. 盘中可以问「消息有了但股价没上去，要不要换标的」，Agent 用 MCP 的技术面概览结合名单回答；比较只在当天名单内进行。

## 4. 目标架构

```
采集（金十 MCP、TuShare 新闻）── 每天 08:00、20:00；08:00 那次之后出晨报
  → 规则粗筛：窗口（上个交易日 15:00 → 当天 08:00）内发布、匹配公司池、去重
  → DeepSeek 按公司分组分类：同一公司的窗口内消息一起判断，附窗口开始前的相关消息供核对；
    输出事件、关系、类型、方向、首次公开时间、新/旧/不确定、重要程度、一句话理由
  → 按配置规则选择：公司是主体、利好、窗口内首次公开、类型在收录清单、重要程度与条数（待定）
  → 晨报记录（编号、窗口、生成时间、条目、缺口摘要）
      ├─ APNs 推送 iPhone：出来就推「晨报已出」；出问题推「晨报出问题了」
      ├─ App（iOS/macOS）阅读：最新晨报、条目原文、历史
      └─ MCP（只读，唯一入口）→ ChatGPT / Claude
           技术面概览：麦蕊、TuShare 都由 Neckline 自己取
```

### 4.1 服务器流水线

- 一期名单的模型调用应在几十次量级、几分钟内完成；不做逐篇深读、多轮调研和 Tavily 搜索。
- 选择规则写进配置并由用户确认，策略层不设默认值。规则包括方向、时效窗口、排除类别和条数上限。
- 名单条目字段：公司代码与名称、事件标题、一句话利好理由、事件发生时间、原件来源与链接、发布时间。
- 局部失败只剔除相关条目并在名单里如实写一行缺口摘要；不再出现 v3 那种成墙的警告。
- 可复用的 v3 模块（复用前先审，不要整包搬）：
  - 采集：`k10/jin10_mcp.py`、`k10/jin10_normalize.py`、`k10/tushare_news.py`、`k10/collection_gateway.py`、`k10/collection_runtime.py`、`k10/sources.py`；
  - 模型调用：`llm/openai_compat.py`、`k10/providers.py`、`k10/metering.py`（回执与计费）；
  - 推送：`k10/notifications.py`、`k10/notification_runtime.py`；
  - 其他：`settings_store.py`、`k10/v2_profiles.py`（公司池与资料）、`calendar/`（交易日历）、`k10/worker.py`（任务租约）、`scripts/release.py`（发布）。

### 4.2 MCP 服务（NB，对话 Agent 的唯一入口）

2026-10-18 用户决定（见 §6）：K10 的对话 Agent 只接这一个 MCP，不另接 KX 的 MCP。

- 工具（只读），只有四样：
  - **晨报**：最新或指定日期的名单（编号、窗口、生成时间、缺口摘要），单条消息的全文与原链接；与推送、App 是同一份记录。
  - **股票池**：查某只股票（代码或名称）在不在 1,089 家池内；不提供一次返回整份名单的工具。
  - **技术面概览**：按单票随问随取，只限池内，池外返回「不在 K10 股票池」。麦蕊与 TuShare 数据都由 Neckline 自己取（麦蕊见 4.3）。TuShare 部分用户 10/18 选加强版：最近一个完整交易日的收盘价、涨跌幅、成交额、换手率；近 20 个交易日的累计涨跌幅、日均成交额、振幅；收盘价在 5、10、20 日均线的上方还是下方；总市值、流通市值、市盈率、市净率；资金净流入只用 TuShare 自带口径（`moneyflow` 的净流入额）并注明口径。每项标明是哪一天收盘的数据。该股在当天晨报里的，结果标出对应条目，方便单票分析带上那条消息。
  - **简要提示词**（即原计划的「Agent 策略说明」）：ChatGPT 和 Claude 共用，写明两个模板。一是单票分析：只限池内，池外直接回复「不在 K10 股票池」；不要求当天上过晨报，上过的带上那条消息；具体结构以后和用户定。二是自由回答：比较类问题只在当天晨报名单内比较，不扩大到全池。同一份文字也放在只读网页上，用户的前置词只用一句话给出网页地址（仿 KX，10/18 用户提议）。
- 不做：推荐几家、返回整份股票池、全池简表或全池扫描。原计划的「按公司或关键词查消息」「检查服务状态」不再单列工具，数据时间与缺口随每个返回给出。
- 返回数据都带名单编号、数据时间和缺口说明，技术面数据另标来源，确保两个 Agent 读到的是同一份。
- 认证：OAuth 同时允许 ChatGPT 和 Claude 的回调（参考 KX 的做法）；10/19 用户要求加 Grok，B119 放行 Grok 连接器回调。
- 只读网页（仿 KX 的 `/kx/read/<key>`，兼做兜底）：`/read/<访问码>` 写明简要提示词与当天晨报；单票页 `/read/<访问码>/stock/<代码>` 给池内查询与技术面概览，池外写「不在 K10 股票池」；`?format=json` 给结构化数据。不需要插件、OAuth 或 JavaScript，但客户端要能真正打开网页。
- 凭据：麦蕊证书与 TuShare token 只放服务器环境，不进 Git、日志与回复。
- TuShare 行情权限（10/18 在 NB 用现有 token 实测，300750.SZ、10/16）：`daily`、`daily_basic`（换手率、量比、市盈率、市净率、市值）、`moneyflow`、`moneyflow_dc`、`moneyflow_ths`、`stk_limit` 都能取到。资金流口径不一：同一天，`moneyflow` 的「净流入额」与同花顺口径都是约 +1.5 亿元，东财的主力（超大单加大单）净额是约 −2.5 亿元，用 `moneyflow` 分档自算的主力净额也是约 −2.5 亿元。用户 10/18 定：只用 TuShare 自带口径。新闻接口每天 40 次的上限与这些无关；行情接口的频率上限未单独查到。
- 验收必须在 ChatGPT 和 Claude 的手机端与电脑端实际调用工具；服务器冒烟测试不能代替。

### 2026-10-16 修订：只出晨报（用户）

起因：10/13 离线第一轮的 17 家里，8 家属于 10/13 早盘前窗口，6 家是 10/13 收盘后才出（属于 10/14 晨报），3 家是 10/13 盘中出的、市场已经交易过。按原设计，晚报会把早报用过的、盘中已消化的和真正新的混在一起。用户判断：能据消息做决定的是次日开盘，盘中的消息当天就被交易掉了。

- **出报**：每个交易日只出一份晨报，不再有晚报；周末、节假日不出。
- **窗口**：上个交易日 15:00 收盘 → 当天 08:00。周一从上周五 15:00 起；长假后从节前最后一个交易日 15:00 起。相邻两期不重叠，不重复抽取。当天 08:00 到 15:00 之间出的消息不进任何一期；08:00 之后才采到的也不补收（用户接受这个代价）。
- **时效**：只收窗口内首次公开的事件，并核验它确实是这段时间爆出来的：模型把同一公司的消息放在一起判断首次公开时间，再用自己的采集记录核对，窗口开始前（如前一天盘中）出现过的不算新。
- **推送**：名单一出来就推「晨报已出」（预计 08:05–08:10）；出问题就推「晨报出问题了」，App 写明原因，不补跑。
- **采集**：每天 08:00、20:00 两次，周末节假日也采；晚上那次只为翻页上限和留下盘中消息供第二天核对，不计算、不推送、不出预览。
- **持续影响的消息**：先搭框架，口径以后再定；框架留一个可加的位置，现在不收。
- **不变**：版本 4.0.0、build 从 B110 起、新库从零开始、MCP 在 `nk.linotsai.top/mcp` 与 API 同服务、利好清单暂用草拟口径、条数上限与重要程度门槛在 P1 点评时定。

### 2026-10-18 修订：MCP 单一入口与两个模板（用户）

依据 `whynotme/K10.md` 第四、五节与 `交易系统总纲.md` 板块 1（whynotme 提交 `2e24bb5`、`8e22702`）。这两份是指导文档，不直接授权工程改动；落到 4.2、4.3 与 §5 的 P2、P4。

- **单一入口**：K10 的对话 Agent 只接 Neckline 的只读 MCP（`nk.linotsai.top/mcp`），不另接 KX 的 MCP。
