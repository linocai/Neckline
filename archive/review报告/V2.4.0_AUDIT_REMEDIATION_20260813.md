> 状态：独立审计后的工程实施建议  
> 基线产品版本：v2.3.3  
> 目标产品版本：v2.4.0

## 一、v2.4.0 总目标

v2.4.0 不是功能扩展版，而是“可信度与减法版”：

1. 先退役至少 80% 的“盘中动态判决”和“退潮刹车”功能，撤销其交易判断权。
2. 修正违反 K8 的选股闸门语义。
3. 修正竞价数据可能过期、数据质量域过严的问题。
4. 清理已经退役但仍在前端、推送和 LLM 中出现的持仓纪律。
5. 精简前端默认字段，保留完整审计能力但下沉展示。
6. 补齐客户端测试、开发环境和发布版本治理。

### 明确不做

- 不增加自动下单、自动卖出或自动调仓能力。
- 不把 P0 改造成另一套更复杂的盘中状态机、风险评分或动态择时系统。
- 不发明新的价格、涨跌幅、样本量、证据数量阈值。
- 不重算或覆盖 v2.3.3 的历史篮子、Tier、卡片、OUT 和复盘记录。
- 不删除服务端历史字段；前端精简优先采用隐藏、折叠和懒加载。
- 不修改现役持仓章程中的数值。
- 不把本次整改包装成“策略已验证有效”。

# P0：退役盘中判决与退潮刹车

## P0 定位

P0 是 v2.4.0 的发布阻断项，必须在 P1—P4 之前完成。

本项不继续优化当前“盘中动态”和“退潮刹车”的算法，也不以增加持续时间、增加阈值或增加状态数量的方式修补。产品决定是：

> 用户自行观察盘中分时。Neckline 保留 D0 冻结预案和必要的持仓纪律提示，不再根据普通盘中波动生成“证伪”判决，也不再根据代理关注池生成全局“退潮刹车”或“禁止开新仓”。

“至少删除 80%”指删除这两项功能的生产判断、用户界面、推送和交易动作语义，不以仅改文案、改颜色或调松阈值冒充完成。

## P0.1 审计结论与必须撤销的权限

当前个股盘中证伪存在以下结构问题：

- 所有 T1/T2 成员使用同一套全局常量，而不是每只股票 D0 冻结的独立失效条件；
- 当前价瞬时低于 VWAP、低开后暂未翻红、折算量比过高或过低中的任一项即可形成“剔除勿进”；
- 量能放大既可能是出货，也可能是启动或换手；量能缩小既可能是无人关注，也可能是抛压衰减，不能脱离结构直接判负；
- 事件一旦进入 `sentinel_events`，当天按固定 `event_key` 去重，后续重新站回 VWAP、翻红或修复均不会改变前端结论；
- 前端名为“盘中动态”，实际展示的是当天累积的静态事件账本，不是当前状态。

当前退潮刹车存在以下结构问题：

- 统计样本是持仓、T1/T2、主线切片和昨日涨停等策略关注对象，不是全市场；
- 今日与昨日的关注池成员会变化，“昨日同时段”不等于同一批股票的可比样本；
- 只读取上一交易日一个基线，昨日异常稳定或异常波动会显著改变今日触发概率；
- 后端约 60 秒一拍，“连续两拍”只代表约两分钟；
- 红色事件一旦落库即全天闩锁，不再根据后续修复重新判定；
- “代理样本局部走弱”却被升级为“今日计划作废、禁止开新仓”，测量范围与动作权限不匹配；
- 没有 brake 事件就显示“运行正常”，无法区分真正正常、行情过期、服务停摆和本拍无数据。

因此 v2.4.0 撤销以下权限：

| 现有功能 | v2.4.0 正式处理 |
|---|---|
| 瞬时跌破 VWAP → “证伪” | 删除 |
| 低开暂未翻红 → “证伪” | 删除 |
| 通用折算量比异常 → “证伪” | 删除 |
| 个股“剔除勿进”盘中事件 | 删除 |
| 代理关注池 → “大盘退潮” | 删除 |
| “今日计划作废、禁止开新仓” | 删除 |
| 退潮 APNs/Bark/系统推送 | 删除 |
| 全 App 顶部退潮红条 | 删除 |
| 独立“盘中动态”页面与事件列表 | 删除 |
| “运行正常·无退潮刹车”绿灯 | 删除 |
| 60 秒客户端 `/board` 专用轮询 | 删除 |

## P0.2 唯一保留的小提示

新客户端只保留一条低强调、无状态、无跳转、无动态判定的小提示。建议固定文案：

> 盘中请自行结合分时判断；系统保留 D0 预案，不作盘中证伪或全局刹车。

展示规则：

- 在“今日篮子”页面的 D0 预案区域上方或下方只出现一次；
- 不在每张篮子卡、每只股票和每个 Tab 重复；
- 使用普通辅助文字，不用红色、黄色、警告图标或强提醒卡；
- 不显示事件数量，不显示“运行正常”，不显示倒计时；
- 不依赖实时行情，不增加新的网络请求或定时轮询；
- 不可点击，不展开新的审计字段；
- 文案是产品边界说明，不是免责话术，也不暗示系统仍在后台判定。

施工不得把“小提示”扩成以下任一形态：

- 盘中风险分数；
- 正常/观察/恶化/恢复状态机；
- 红黄绿交通灯；
- 关注池涨跌统计；
- VWAP/量比/低开事件摘要；
- 另一种名称的“大盘退潮”；
- 另一种名称的“建议暂停开仓”。

## P0.3 明确保留且不得误删的能力

P0 只退役“非持仓 T1/T2 的通用盘中证伪”和“代理池全局退潮刹车”。以下能力属于 K8 的其他职责，必须保留：

1. **D0 冻结预案**：上涨判断、入场区间、目标离场区间、判断失效位置继续展示。
2. **D1 集合竞价小报告**：9:26—9:29 冻结后结束，不与盘中动态混合。
3. **持仓 5% 亏损警戒**：使用 K8 的 `loss_warning_pct=0.05`、`action=review` 语义，只提醒用户复核，不自动卖出。
4. **持仓离场参考提醒**：触达目标离场参考区间时提醒，不触发机械止盈。
5. **真实持仓状态与交易时钟**：继续在持仓卡或持仓详情展示。
6. **用户创建的临时提醒**：继续走独立的提醒入口，不并入已删除的盘中动态页。
7. **D1 收盘选股时钟和盘中原始存拍**：可继续为收盘复盘和研究积累原始数据，但不得在盘中转换成新交易判决。
8. **历史审计数据**：旧 `sentinel_events`、`retreat_metrics` 和旧报告保持只读，不删除、不改写。

原“盘中动态”页面若同时承载持仓事件，施工时必须先迁移再删除页面：

- 持仓亏损警戒和离场参考进入对应持仓卡/持仓详情；
- D1 竞价信息回到竞价报告；
- 临时提醒留在现有独立提醒入口；
- 旧个股证伪和退潮历史不进入 v2.4.0 默认界面。

不得因为删除聚合页面而误删仍然有效的持仓提醒。

# P1：修正选股关口与 Tier 语义

## P1 目标

解决“闸门过严”的根因：

- 不再要求 leader/core/elastic 都证明自己是行业龙头。
- 不再因为一只备选成员不合格而让整个篮子 OUT。
- 不再让尚待校准的 `T2 最大降级数=1` 间接产生正式 OUT。
- 缺失、模型漏答和明确反证必须是不同状态。

主要文件：

- `neckline/selection/aggregate.py`
- `neckline/selection/gates.py`
- `neckline/selection/tier.py`
- `neckline/selection/core_metrics.py`
- `neckline/selection/pack.py`
- `neckline/selection/basket_store.py`
- `packs/K8-skeleton.json`
- `packs/C2.json`
- `packs/Z2.json`
- `packs/Y2.json`

## P1.1 重新定义三类闸门结果

施工后必须严格区分：

| 状态 | 含义 | 正式后果 |
|---|---|---|
| `pass/ok` | 证据完整且判断通过 | 可参与 T1 |
| `weak` | 有疑点或证据较弱 | 阻断 T1，保留 T2 |
| `unknown/unavailable` | 数据缺失、模型漏答、无法判断 | 阻断 T1，保留 T2 并披露缺失 |
| `unfit` | 有明确反证，逻辑不适合 | 成员级或篮子级 OUT |
| `reject` | 用户确认的机械硬边界未过 | 正式 OUT |

禁止继续把“模型没有回答”兜底成 `weak` 后再计入降级总数。缺失不是负面证据。

实现上可以继续使用 `GateCheck.available=False` 表达 unknown，不必强行扩大所有外部枚举；但 Tier 层必须能够区分：

- 明确 `weak`；
- `available=False`；
- 明确 `unfit`。

## P1.2 核心关改为角色感知

LLM 先确定成员角色，再按角色采用不同判据。

### `leader`

要求：

- 在同一主要驱动中率先转强；
- 强度、辨识度和资金关注度居前；
- 能解释为什么由它领，而不是跟随。

### `core`

允许：

- 容量核心；
- 最能代表资金态度的成员；
- 承接稳定、成交容量和方向代表性较强；
- 不要求必须是最高弹性或最先涨停的股票。

### `elastic`

要求：

- 与主要驱动直接相关；
- 位置和结构合理；
- 弹性、强度或赔率突出；
- 不要求证明自己是龙头。

禁止再出现“所有角色的 `ok` 都等于同行业龙头”。

## P1.3 核心比较域按 K8 恢复

比较域必须按以下优先级选择：

1. 同一主要驱动的候选成员域；
2. 同一题材/方向的相关成员域；
3. 传统行业分类。

`core_metrics` 应增加审计字段：

- `comparison_domain`：`driver | theme | industry`
- `comparison_domain_key`
- `peer_codes`
- `peer_count`
- `domain_fallback_reason`
- 现有强度、辨识度和排名读数

不增加机械及格线。这些仍是供 LLM 判断的原始读数。

“同一驱动域”不能只取最终入篮的 1—3 只，否则比较会形成自证循环。应使用该篮子合并前各 seed 的 presented member universe。

## P1.4 成员级 OUT，不再整篮连坐

当前 `_evaluate_under_engine()` 虽然保留 `removed_members`，实际却把所有成员都放进 `kept`。v2.4.0 应启用这条已有通路：

- 成员 `core_unfit`：该成员移出正式篮子并写入股票级 OUT。
- 成员 `position_unfit`：同上。
- 同一成员同时命中多个 unfit：按固定 `GATE_ORDER` 选择主 OUT 原因；全部理由继续保存在 `gate_evaluations`。
- 移除后仍有至少一名有效成员：篮子继续定档。
- 全部成员移除：篮子退出正式候选。
- 移除 primary 后必须调用确定性主成员修复逻辑。
- `basket_key` 不变，因为共同驱动身份没有变化。

复用现有：

- `BasketGateSummary.removed_members`
- `kept_member_codes`
- `gate_evaluations`
- `out_candidates`
- `out_shadow_daily`

不需要另建一套 OUT 表。

## P1.5 篮子级 OUT 边界

只有以下情况允许整篮 OUT：

1. 基础股票池硬边界或已审计机械硬门失败；
2. 共同驱动不成立；
3. 市场关/板块关存在明确、完整的反证；
4. 所有成员均被成员级核心关或位置关移除；
5. 引擎无法归属，并且不是单纯的系统缺席。

市场/板块 LLM 给 `unfit` 时，必须同时满足：

- 判定所需数据可用；
- `counter_evidence` 非空；
- `reason` 非空；
- 不是因为 missing/unknown 导致模型保守输出。

否则夹成 `weak` 或 `unknown`，不得 OUT。

LLM 输出建议升级为结构化检查：

```json
{
  "verdict": "ok|weak|unfit",
  "support": ["..."],
  "counter_evidence": ["..."],
  "missing": ["..."],
  "reason": "..."
}
```

成员的核心关和位置关、篮子的市场关和板块关统一采用该结构。解析器可继续兼容旧扁平字段，但 v2.4 新 prompt 必须输出新结构。

## P1.6 T1/T2 新规则

### T1

必须同时满足：

- 无硬拒绝；
- 无明确 unfit；
- 六关均 `pass/ok`；
- 没有 unavailable；
- 行情状态可用；
- 交易预案四件套完整。

T1 不需要再依赖一个数字型 `max_evidence_degrades=0`，因为“六关全过”本身已经是结构条件。

### T2

必须满足：

- 无基础硬边界违规；
- 无篮子级明确 unfit；
- 至少保留一个有效成员；
- 共同驱动仍成立；
- 所有 weak/unknown 均被明确披露。

允许存在多个 weak 或 unknown。不得再使用尚待校准的“最多一个降级”将篮子送进 OUT。

### 原 `max_evidence_degrades=1`

在 C2/Z2/Y2 中保留为影子规则，不参与正式定档：

```json
"tier_evidence": {
  "t2": {
    "formal_policy": "no_hard_fail",
    "max_evidence_degrades": {
      "value": 1,
      "provenance": {
        "source": "engineering_v1",
        "calibration": "pending"
      }
    }
  }
}
```

约定：

- 旧 C1/Z1/Y1 没有 `formal_policy`，继续使用 v2.3.3 旧行为，保证回滚可复现。
- 新 C2/Z2/Y2 明确使用 `no_hard_fail`。
- `max_evidence_degrades` 继续写入阈值影子账本，统计“若按旧规则会不会 OUT”。
- 因为是可选配置扩展且旧包行为不变，Engine API 可保持 2。

## P1.7 容量溢出不属于 OUT

保持现有语义：

- T1 因计划不完整降为 T2；
- T2 满额后发生 `capacity_overflow`；
- `capacity_overflow` 继续作为未定档篮子，不得写入 OUT；
- 不得进入 OUT 误杀研究样本。

## P1 验收用例

至少增加以下测试：

1. `leader=ok + elastic=unfit`：只移除 elastic，leader 篮子保留。
2. `core` 容量中军不是龙头：可判 `ok`，不因非龙头 OUT。
3. `elastic` 非龙头但相关、位置合理：可保留。
4. 某成员核心关和位置关同时 unfit：一条股票级 OUT，全部理由可追溯。
5. 所有成员 unfit：整篮 OUT。
6. core/position 字段缺失：T1 被阻断，T2 保留，不 OUT。
7. 两个以上 weak：C2/Z2/Y2 下仍可 T2，影子台账记录旧规则会失败。
8. 明确 market/sector unfit 且有反证：整篮 OUT。
9. market/sector 数据缺失但模型给 unfit：夹成 unknown/weak，不 OUT。
10. C1/Z1/Y1 旧包在兼容测试中保持 v2.3.3 行为。
11. `capacity_overflow` 不写 `out_candidates`。
12. 历史 `gate_evaluations`、`out_candidates` 不被更新或删除。

# P2：竞价数据可靠性与 LLM 降级语义

## P2 目标

解决：

- 上一交易日缓存行情可能被当作今天竞价数据；
- 一只无关指数缺失导致整个篮子强制中性；
- “跨源冲突为空”实际上没有进行过交叉核验；
- 晚间 LLM 故障被表现成“今天没有篮子”。

主要文件：

- `neckline/sentinel/quotes.py`
- `neckline/auction/collect.py`
- `neckline/auction/mech.py`
- `neckline/auction/llm.py`
- `neckline/auction/store.py`
- `neckline/report/evening.py`

## P2.1 行情时间戳标准化

为 `Quote.ts` 增加统一解析函数，原始字符串继续保留。

每条竞价行情必须验证：

1. 代码和市场映射正确；
2. 源日期等于 D1 交易日；
3. 源时间不晚于本地 `captured_at`；
4. 源时间属于当日集合竞价结果可接受区间；
5. `open/price/pre_close` 的必要字段有效；
6. 涨跌幅与价格关系数值一致；
7. 单位转换后 volume/amount 非异常负数。

不得发明任意“5 分钟新鲜度”之类的新阈值。时间判据使用 K8 已规定的交易日和 9:25/9:26—9:29 边界。

建议新增内部状态：

- `fresh`
- `wrong_trade_date`
- `before_final_auction`
- `future_timestamp`
- `timestamp_unparseable`
- `required_field_missing`
- `malformed`

## P2.2 主备源处理

继续以新浪为主、腾讯为备，但改为：

- 普通上下文股票仍走“主源失败才降备源”。
- T1/T2 成员及其关键基准采用有界双源核验。
- 双源批量并行，不允许逐票网络请求。
- 主源过期、备源新鲜：使用备源，记录降级来源。
- 双源都无效：该代码 `insufficient`。
- 双源均新鲜但结论性冲突：标记 conflict。

冲突不使用新百分比阈值。至少识别：

- 两源涨跌方向相反；
- 一源触发 D0 失效位、另一源不触发；
- 一源进入/突破预案区间、另一源不进入；
- 股票代码、前收盘或交易日不一致。

原始两源读数都必须留痕，不允许只保存胜出的一个值。

## P2.3 数据质量拆成关键域和上下文域

### 关键域 `critical_quality`

包含：

- 篮子成员自身竞价数据；
- 每只成员实际使用的市场基准；
- 实际用于相对板块计算的板块基准；
- D0 失效判断所需的冻结锚。

关键域非 `ok`：

- confirm/veto 必须夹成 neutral；
- 机械失效警报仍可在相关字段足够时独立输出；
- 不允许用无关字段缺失掩盖已有的失效事实。

### 上下文域 `context_quality`

包含：

- 其他市场指数；
- 未实际用于当前成员计算的对照股；
- 市场锚点；
- 历史比较；
- 前五日量能背景。

上下文降级：

- 不夹逼篮子结论；
- 降低置信度；
- 在理由或风险中披露缺失项。

原来的 `data_quality` 对外字段继续保留，兼容含义改为关键域质量。新增可选字段：

- `criticalDataQuality`
- `contextDataQuality`
- `qualityDetails`
- `quoteSource`
- `quoteTimestamp`
- `quoteFreshness`
- `validationErrors`

旧报告没有这些字段时显示“旧版本未细分”，不得默认成正常。

## P2.4 数据库迁移

建议仅做可空的增量列。

`auction_reports`：

- `quote_quality_json TEXT`

`auction_verdicts`：

- `critical_data_quality TEXT`
- `context_data_quality TEXT`
- `quality_detail_json TEXT`

规则：

- 旧行保持 NULL；
- 新行第一次机械落库时写入；
- 上述字段属于机械冻结列，不得加入 LLM UPDATE 白名单；
- 不重写 v2.3.3 历史竞价报告。

## P2.5 晚间 LLM 故障不等于无候选

必须区分：

### 合法空结果

- 扫描和 LLM 都成功；
- `reason_stage=ok`；
- 模型明确返回 `baskets=[]`。

此时可以显示“今天没有形成正式篮子”。

### 系统缺席

- provider 不存在；
- 预算耗尽；
- 调用失败；
- JSON 解析失败；
- 超时。

此时：

- 不生成正式 T1/T2；
- 不生成正式 OUT；
- 不进入 gates/tier；
- 保留机械 seed 数量和简短摘要；
- 报告明确显示“选股解释未完成”，不能显示“今天没有机会”。

建议给 `BasketDailyOut` 增加可选字段：

- `selectionStage`
- `selectionUnavailableReason`
- `unexplainedSeedCount`
- `unexplainedSeedSummary`

未解释 seed 不是第四种候选状态，不得冒充 T2 或 OUT。

## P2 验收用例

1. 新浪返回昨日行情、腾讯返回今日行情：使用腾讯，记录主源过期。
2. 两源都返回昨日行情：critical insufficient。
3. 时间戳无法解析：不得判 `ok`。
4. 成员数据完整、无关指数缺失：critical ok、context degraded，不夹中性。
5. 成员对应指数缺失：critical degraded，confirm/veto 被夹中性。
6. 双源一边触发失效位、一边不触发：conflict，不能高置信输出。
7. LLM provider 缺席：报告显示“未解释”，不是“零篮子”。
8. LLM 成功返回空数组：合法显示零篮子。
9. 竞价 LLM 缺席：机械数据和失效警报仍正常落库。
10. v2.3.3 历史竞价记录可正常解码。

# P4：测试、复现、版本发布与回滚

## P4 目标
