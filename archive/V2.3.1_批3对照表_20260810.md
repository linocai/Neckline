## 🔴 本轮独立复核的订正(**推翻了首版实拍看起来"干净"的两处**)

### ① 服务端英文机器码被当中文正文印上屏 —— 硬伤 2 的**第八处**,且首版实拍**看不出来**

- **现象**:`PositionExtras.swift` 旧写法 `Text(clamp.isEmpty ? "本次不可用" : "本次不可用(\(clamp))")`。
  `plan_json` 的 `entry_zone_clamp` / `max_chase_clamp` / `exit_reference_clamp` 取值域是
  **英文机器码** —— `absent` / `rejected_out_of_limit` / `rejected_malformed` / `rejected_no_limit` /
  `rejected_not_above_close` / `rejected_no_close`(唯一源 `neckline/selection/basket_card.py:115-128`)。
  **生产数据上这一格会印成「本次不可用(rejected_not_above_close)」**。
- 🔴 **为什么首版实拍逮不到**:上一轮的演示种子 `seed_b3.py:89` 把这一格喂成了**中文**
  「夹逼拒收」——**演示数据把真 bug 盖住了**。本轮把种子改成生产真值 `rejected_not_above_close`
  后一拍即现(`b3r_01` / `b3r_02` / `b3r_06`)。
  ⚠ **通用教训**:演示库里凡是「服务端枚举码」字段,**必须喂真词表里的值**,喂中文等于把
  展示层换算这一整类 bug 全部屏蔽掉。

  ⛔ **不藏掉**:藏掉就查不出是被哪一关夹的。
