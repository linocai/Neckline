# Neckline 3.7.0 Build106 · 标题审计批量持久化快修与发布

## 范围与结论

B105 已解决标题批次续跑反复重放，但昨晚任务继续卡在标题选择落库：约 22,000 条标题结果逐条开启 SQLite 写事务，数分钟内耗尽每个续跑切片；选择 manifest 始终未冻结，报告仍显示`DISCOVERY_SLICE`。这是本轮确认的第二个“局部慢操作扩大成整报阻断”问题。

B106 保留 B105 的已完成标题批次恢复，并新增批量标题审计写入：先在一个事务内完成同一冻结输入的校验、幂等比对和批量插入，再冻结选择 manifest。单条存储入口保留给小型 API/fixture 使用；模型、策略、预算、报告窗口及局部缺口契约不变。

## 实施

- `store.record_title_triage_items`一次读取 manifest 和已有条目，拒绝越界、重复或静默改写，使用单次`executemany`提交。
- `title_runtime.select_title_documents`把直接正文、标题结果和精确重复整理成批量记录后统一落库。
- 新增批量存储幂等回归；保留 B105 308/341 批次续跑回归及坏引用局部缺口回归。

## 验证

- macOS build、iOS Simulator build、iOS build-for-testing、macOS/iOS Release archive均需记录成功；归档严格验签，最低OS27。
- 线上验收重点：选择 manifest落库、任务离开`DISCOVERY_SLICE`，以及报告最终状态/可读内容/缺口均从数据库和API后置核对。

目标为`v3.7.0-b106`，生产主机`ser657204219523`。切换前停 timer 与 API/worker，临时 mask 防止 systemd 自动重启，保存并压缩当前B92新起点数据库；原子替换139个运行文件、安装107个wheel文件后恢复服务。数据库从未覆盖，B105代码包与Mac副本作为回退。

昨晚任务不重跑、不新建窗口，沿已完成标题批次和已写入标题审计继续；只有最终可读报告与真实缺口完成后才宣称本轮业务闭环。
