## 一、总架构

```text
┌─ 选股板块(D0 盘后主链) ────────────────────────────┐

│ → ③Tier分层引擎 → ④篮子卡冻结 → ⑤D+1验证与复盘   │
└──────────────────────────────────────────────────┘
┌─ 持仓板块 ───────────────────────────────────────┐
```

## 二、选股板块(五层)

> ①扫描层的种子生成规则与 ③Tier 引擎的机械分维度/权重,其可配部分由**现役策略包**驱动(裁定 #11,机制见 §十二);②④⑤ 是引擎本体,不进包。

### 2.1 ①市场扫描层(纯机械,16:05 数据更新后批算)

**改造现有**。继承:全市场特征面板、行业强度表(`industry_strength_daily`)、概念板块强度、资金流、涨停梯队(`limit_derived`+`top_list`)、个股卫生线、K4 红黄牌镜像、行业闸(lift 富集度)。

**新造三张预计算表**(全部 EOD 批算落表、在线只读——P0-23 纪律;新机器上仍须实测计时):

| 表 | 内容 | 用途 |
|---|---|---|
| `corr_matrix_daily` | 板内/簇内滚动 20 日相关性 | 共振证据、重复暴露识别 |
| `limit_cluster_daily` | 涨停共振簇(同日/连日共涨停聚类) | 驱动种子 |
| `leader_structure_daily` | 簇内 RS 排名/连板高度/成交额占比 | 龙头结构判定、角色对拍 |

产出:**驱动种子集**(热点行业、暴起概念、涨停簇、异动簇)→ 交②。

### 2.2 ②驱动聚合层(LLM + 机械闸)——V2 心脏,全新

- LLM 输入:驱动种子 + 成员机械数据 + 联网检索(日期锚与时效纪律走 `prompt_context` 唯一实现)。
- LLM 产出:合并同驱动异名题材、命名共同驱动 + 证据链(来源+日期)、"为什么是现在"、成员选择 + 角色标注(龙头/中军/弹性)。
- **两道机械闸**:
  1. **成员白名单闸**:LLM 只能从扫描层给出的簇/板块成员集合选票,凭空造票直接拒收;
  2. **角色对拍闸**:LLM 标注的龙头与机械头名(RS/连板/成交额)冲突时,标注分歧入卡,不静默采信任何一方。
- 篮子规则照蓝图 4.1/4.2:1–3 只/篮、必须说明共同驱动与"为何是这几只"、仅历史相关性不足以成篮;主归属规则复用行业闸 lift 先例(防挂靠票占位重演)。

### 2.3 ③Tier 分层引擎

- **机械分定档**,初版维度收敛为五项(全部是已审计方向的量):板块强度/驱动新鲜度(persist_days 反用)/龙头结构清晰度/可交易性(一字与涨停占比)/红黄牌密度。
- **LLM 只能在同档内微调排序并留痕,不得跨档**(第〇原则 Tier 变体);"为什么这篮 T1 那篮 T2"的理由由 LLM 生成、落卡。
- 容量:T1≤2 / T2≤5 / T3≤10,全部是上限非配额,允许 T1 为空。
- 排序键白名单 + 运行期访问锁(`_SORT_KEY_INPUTS` 体例)原样平移。
- 权重公式初版从简,校准走 §2.5 评价引擎的周度报告,调参过策略进化门禁(不许顺手改)。

### 2.4 ④篮子卡冻结

- 新表 `baskets` / `basket_members` / `basket_cards`(冻结 JSON,写入即不可改,追加版本制)。
- 卡内容 = 蓝图 4.6 全项;工程体例继承 v1.5 参考件:建仓观察区间 + 最高追价**夹逼在次日涨跌停内**(`compute_intraday_limit_prices` 同源)、止损价系统算不由 LLM 给、口径指纹(stop_pct/take_profit_retrace)落行、disclaimer 恒带。
- **验证/失效条件双份**:结构化(哨兵机器消费)+ 人话剧本(LLM 生成)——V1 证伪条件体例平移。
- D+1 新信息只能追加,不改 D0 原判(冻结快照 + append-only,既有体例)。

### 2.5 ⑤D+1 验证与复盘

**哨兵改造**(骨架保留):
- 关注池改为:持仓 + T1/T2 篮子成员 + 相关板块 ETF/指数 + 昨日涨停(容量与现状同量级);
- **盘中存拍(新)**:关注池分钟报价 + 09:25 竞价快照落 `intraday_ticks` 分区(`write_table_day` 铁律 + `_VALID_TABLES` 声明);V2 的分时自给从上线日开始,外源方案(用户自寻)接入后走同一张表回补;
- 篮子验证状态机:已验证/部分验证/尚不明确/已证伪,按结构化条件盘中+EOD 判,状态追加不回写。

**盘后复盘引擎(新)**:
- 机械判:竞价 vs 剧本、开盘首方向、分时 MFE/MAE(有存拍才有,缺则 EOD 近似 + 如实标注)、成员同向率、龙头带动、可买性(一字/涨停排除)、验证与证伪时点、收盘 RS;
- LLM:吃机械判 + 分时摘要,解释哪里对哪里错;
- **评价引擎**(选股能力的审计者,与篮子引擎同日上线):Tier 单调性(T1>T2>T3)、篮子共振率/验证率、龙头 vs 同篮成员、可交易收益(**判分复用考官线成交层 + h9 退出模拟器,判分引擎唯一源不另写**)、用户已选 vs 未选对照;
- T1/T2 每日必复盘,T3 留量化全量 + 简评(防错杀检验);周度出校准报告。

## 三、持仓板块(六件)

### 3.1 极简台账
- 买入 = 票 + 价 + 量(买入日默认今天可改,保留 v1.4 契约);自动关联:来源篮子/Tier/角色、时间、市场快照,计划继承(建仓区间/最高追价/离场参考/验证失效/风险)写入 `position_plans`(版本化,新版本不改原始篮子卡)。
- 卖出 = 价 + 量 + 可选快捷标签(止损/逻辑证伪/板块转弱/达到参考区间/主动切换/临时决定)。
- **决策日志强制表单退役** → 自动快照表(系统冻结机器可知的一切),用户字段全部可选(含语音一句话);计划 vs 实际成交偏离时提示"盈亏结构已变",不质问不阻断。

### 3.2 监控 80/15/5
- 现役纪律分支**原样保留**:-5% 止损、回落止盈、时间退出、证伪四哨兵、熔断;
- 新增四监测:同篮子成员集体转弱、板块 ETF/指数承接消失、持仓从跟随转独立弱势、大盘突变;
- **同篮子多持仓按同题材合并敞口**展示与提醒(蓝图 6.2)。

### 3.3 通知三级
现有 APNs 白名单机制重构为「立即 / 重要不紧急 / 盘后汇总」三级;冷却、去重、防重沿用 `sentinel_events` 台账;通知只说"发生了什么、碰了哪条计划、要不要打开 APP"。

### 3.4 自然语言临时提醒
- 新表 `custom_alerts`;LLM 只做解析(自然语言 → 结构化规则),展示确认卡(标的/条件/生效窗/冷却/到期/**行情延迟披露为必选项**/只通知不交易);
- **执行归确定性哨兵**;相同提醒去重、首次命中不轰炸、收盘自动失效(除非显式长期);
- 首批条件集:价格、涨跌幅、相对成本、相对日内高点、量能、大盘/篮子条件组合(蓝图 5.6)。

### 3.5 对账与画像
- 周度交割单对账引擎**原样保留**(追加修正制、交割单为费用与成交最终权威);资金流水四分类(转入转出/分红/税费/交易盈亏)扩展;
- 偏好画像 / 能力画像两张账分开(新引擎):偏好答"喜欢什么",能力答"什么真有效";每项带样本量/时间范围/置信度;单笔不成偏好;**初期不得反向影响客观 Tier**。

### 3.6 纪律外壳(一行不动)
章程、`strategy_versions` + append-only 激活历史、四道闸、逐笔章程判定、熔断、券商条件单核查提醒、周对账。红黄牌降格为风险信息与模型特征,不等同禁买(蓝图 7.2)。

## 五、LLM 层改造:Provider 自填制 + 双 Agent 分工

### 5.1 Provider 自填制(用户裁定 #2)
- 退役「GLM/Kimi 枚举」;`app_settings` 扩为 **Provider 注册表**:每条 = 名称 + base_url + model + api_key + 能力标记(是否带联网检索/结构化输出习性),任意 OpenAI 兼容端点可配,App 设置屏增删改;
- `openai_compat` 传输层保留为唯一底座;**任务→Provider 路由表**可配(哪类任务走哪个 Provider),缺路由回退默认 Provider。

### 5.2 双 Agent 分工(DeepSeek + GLM,用户裁定的报告协作方式)
- **约束事实**:联网检索目前只有 GLM 通道实现(web_search);DeepSeek 走纯推理。
- 默认分工(路由表可改):**GLM = 检索型任务**(驱动证据检索、消息面、"为什么是现在"取证);**DeepSeek = 推理型任务**(篮子逻辑与角色比较、Tier 同档排序理由、剧本生成、复盘解释、画像总结)。
- 检索产物(带来源+日期)作为上下文喂给推理 Agent——两段式流水,检索与推理解耦,单侧故障单侧降级(诚实披露哪一段缺席)。
- 预算多本账(检索账/推理账/复盘账分立),降级次序定死:先丢 T3 简评 → 再丢 T2 复盘细节 → 绝不牺牲篮子卡冻结与纪律外壳;`prompt_context`(日期锚+时效纪律)对所有 Provider 一律注入。

## 十二、选股策略包机制(裁定 #11,2026-08-02 用户批准定稿)

> 需求:选股策略由策略线迭代轮替——策略线完成研究后打包交付,系统线校验入库、激活换包,选股主链不因换策略而施工。

### 12.1 形态裁定:声明式配置包,不是代码插件

策略包里装**参数与规则声明**,不装可执行代码;执行引擎永远住在系统线仓库里。理由(定案,勿重开):代码插件与全部既有工程纪律相抵触——守门单测罩不住外来代码、「三态同码」会被绕开、P0-23(判据类扫描必须预计算落表)无法对未知代码强制执行、事故无法归责引擎还是包。现有体系已是声明式雏形(`strategy_versions` 现役行 config 读表跟随、K4 advisory 落库规则报告侧只消费),策略包只是把该体例扩展到 V2 选股板块。

### 12.2 插槽边界(包只管两处)

- **①市场扫描层的驱动种子生成规则**(用哪些过滤器、什么阈值);
- **③Tier 分层引擎的机械分维度选择与权重**。

②驱动聚合的两道机械闸、④篮子卡冻结体例、⑤复盘与评价引擎是**引擎本体,不进包**;**纪律章程不进包**——章程(`strategy_versions` + `activate_charter.py` 四道闸)与策略包是两条版本线、两张表、两套激活流程,防双权威漂移。

### 12.3 包格式

一个 JSON(或目录),两部分,全部可 JSON schema 校验:

- **manifest**:K 版本号、名称、日期、证据链指针(`research/*.md`)、**`engine_api_version` 兼容声明**(引擎校验,不兼容拒绝激活、fail loud);
- **config**:对引擎**原语**的引用 + 参数 + 权重。

**原语** = 系统线实现好、带守门单测的积木(过滤器、特征、排序键);**特征只能来自预计算表、白名单制**(`_SORT_KEY_INPUTS` 体例平移)。策略线需要引擎没有的新原语时,走既有跨线协议:**系统线先把原语做进引擎(一次小版本施工,带单测),下一个包才能引用——代码永远不随包传输。**

### 12.4 入库与激活

新表 **`selection_packs`**(append-only + 单现役 `is_active` + 激活日志),激活走独立切换脚本,复刻 `activate_charter.py` 四道闸体例:schema 校验 → 原语/白名单核对 → 默认演练模式 → `--confirm` 才写。选股主链每晚从**现役包行**读配置。

### 12.5 轮替、回滚与归因

- 换策略 = 一次激活动作(新包行激活、旧行留档);回滚 = 激活旧版本行;
- 评价引擎(§2.5)按 `pack_version` 归因——每个包自动攒出自己的成绩单(「实盘表现按版本归因」原则的自然延伸),喂给策略线下一轮迭代;
- **版本号沿用 K 字头**:包就是策略线 K 版本的交付物形态,不另起第三条版本线。

### 12.6 初版落法

V2 施工时把「现成选股代码」的可配部分抽出,整理成第一个包(如 `K4-pack`)灌入 `selection_packs` 作现役——**主链从上线日起就走「读现役包」路径**,插槽从第一天就在被真实消费,不是空架子。

### 12.7 已知代价(如实登记)

声明式的表达力受限于引擎原语集:策略线每想用全新玩法,须先等系统线加原语(一次小版本施工)。此代价刻意接受——它把「策略变更必须过门禁」从流程约束变成**结构约束**,复刻现行「策略过门 + 用户批准 → 系统线激活」跨线协议。
