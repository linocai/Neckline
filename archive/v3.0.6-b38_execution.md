# 3.0.6 / Build 38：全量标题初筛与 80/40 正文深读

根目录 [PROJECT_PLAN.md](../PROJECT_PLAN.md) 是当前控制面。本记录给 builder 明确的施工、接口与验收契约；Git 和当前文件是代码事实。

## 目标与范围

将 K10 的“增量采集 → 去重 → 规则初筛 → 轻量理解 → 核验 → 候选”改成一条可复核链路：程序只做精确重复消除；DeepSeek V4 Pro 对每条标题作语义判断；所有批次完成后，全局合并事项、选择真实文章，再按晚间 80 / 晨间 40 的文章数上限深读正文。标题优先、深读限额和错误停止优先于吞吐。

不改 K10-v1.4 的公司比较、30 家、跨日、D1/D2、重叠和成绩规则。本轮不部署、不恢复生产 worker/timer、不恢复 2472 篇旧任务，也不作全量付费回放。完成后允许一次独立数据库的最新时窗真实验证；它必须先通过标题审计质量检查，且不能触碰生产数据库或定时服务。

## 已定产品契约

1. 每一条精确去重后的来源文章都进入标题初筛。模型输入序列化时只能有 `documentId`、`revision`、`sourceKey`、`publishedAt`、`title`；构造专用不可扩展 DTO，禁止传 `DiscoveryDocument`、正文、excerpt、URL 正文或开放 `metadata`。
   可信任务上下文单列 `knownSubjects`，只含当前仍在两日观察窗口内正式候选的 `companyCode/headline`，帮助识别已有论点反证；不传旧正文、facts、正反分析或任意 metadata。该白名单与单条资讯 DTO 的五字段边界分别验证。
2. 每个标题返回简短、结构化的事项判断、事项/阶段指纹、价值状态和去向。价值状态至少区分 `candidate`、`uncertain`、`same_matter`、`no_value`、`correction_or_denial`；后两类不是基于栏目、题材、利好词、长度、海外/上游或代码命中硬删。每条标题必须恰有一个真实输入 ID 的结果。
3. 分批只产生逐条语义结果，不能从每批预先拿 Top N。所有批次成功后，全球协调步骤仅用标题 DTO 和批次结果合并同事项、比较来源质量/完整性并生成排序；它为每个候选组选择一篇真实文章，或说明未入选/被合并的真实 ID。更正、取消、否认和已发布候选的重大反证不能被普通转载合并掉。
4. 全局选择结果先持久冻结，再触发任一正文模型调用。选择数是实际来源文章数，不是资料包数：晚间最多 80、晨间最多 40；不够不凑。选中且正文不可得、全文解析失败或模型深读失败都占该名额、展示原因，不以更低排序文章替补。
5. 入选文章才可把原正文交给深读模型。随后可以按正文把入选文章形成同事项资料包，但资料包成员总数仍不得超过冻结的 80/40；它不能把多篇正文折成一条额度。正文以原始可读文章为准，不能把全文叫“关键段”规避计数。
6. Tavily 只处理已入选事件的具体证据缺口，默认只用搜索摘录。若核验向模型提供新的外部文章全文，该文章也必须作为独立 article admission 写入本轮 80/40；达限则留待核，不能继续读。仅提取发布时间的页面元数据请求不提供正文给模型，不计深读。每个事项保留有限核验和有限 retry，不设整轮搜索额度。
7. V3 不设总 token、费用、模型调用或搜索请求上限。保留 append-only 的真实 usage/attempt 账，成功记录实际 usage，未知结果保留 unknown，缓存命中不新建调用；该账不得拒绝调用。每个外部调用仍有 task/stage/item/attempt/input digest，上下文与单次 `maxTokens` 协议边界必须明确。
8. 任一标题批次漏 ID、重 ID、陌生 ID、JSON 截断、结果与输入数不等、跨批协调漏掉应参与的 candidate/uncertain/protected 标题，均不得默认为未入选或开始正文。有限重试耗尽后 scan 为 `partial`，保留原因，零正文深读。全局冻结后的中断可从同一 manifest/idempotency key 恢复，不能重复外部调用或另取名额。

## 配置、Schema 和 Store

### V3 执行配置

只接受 `k10-execution-v3`，绑定已批准、不可变的 `titleTriagePolicy`（ID、revision、content SHA-256、approvalState）和 `articleLimits` `{evening:80,morning:40}`。它继续显式绑定 DeepSeek V4 Pro、有限网络/JSON retry、slice/deadline/continuation、标题批大小/并发和各操作的单次 model options；这些是工程请求边界，不是整轮预算。policy 内容必须覆盖上节的保留、合并和禁止硬排原则，配置绑定必须和 store 中同 SHA 的 approved revision 一致。

删掉未发布的 V2 `screeningTemplate`、`budgets`、reservation、`pending_budget`、`budgetExhausted` 与用量剩余 UI/API。`taskPolicies.discovery.maxVerificationRequests` 若是扫描总量阈值也删除；保留每个事项的有限核验/retry 语义。V1/V2 均不能作为付费任务回退。

Schema 升至 6。B36 生产是 Schema 4，故 4→6 不应创建 B37 预算表；开发机既有 Schema 5 前向迁移时删除 B37 预算/模板运行表及其 runtime consumers，保留 B36 历史和冻结事故审计。新增最小持久对象：

- 标题 policy revisions；标题 run manifest（窗口、policy binding、上限、所有输入 refs hash、批次/全局冻结状态）；每标题的 batch、事项/去向、合并对象、入选 rank 和可审计简短理由；全局 selection manifest。
- 通用外部 attempt/usage ledger，按 task/stage/item/attempt/input digest 幂等，含 started/succeeded/failed/unknown 与真实 usage；没有总量列、没有 admission 拒绝分支。
- discovery retirement 记录。`retire_interrupted_discovery` 原子取消目标 task、清 lease/retry、将 scan 留为终态并写 `retired_by_user` 原因；`recover_scan`、reopen、enqueue 同一旧窗口和 worker claim 都查此记录并拒绝。保留事件、候选、成绩和历史用量。

现有 run control 和事实缓存继续使用。事实缓存绑定文章版本、正文内容、policy、提示及模型参数；纯来源事实不因后续扫描截止时间或候选上下文变化而失效。标题审计保存受限的结构化结果和 refs，不公开正文、提示词、模型原答、密钥或私有 URL。
