# Neckline 4.0.0 Build112（B112）执行记录：P3 App 改造

正式工作流（2026-10-17 用户进入）。基线：后端现役 `v4.0.0-b111`（`798d3cb`），App 3.7.0 Build109。计划由 Cursor（grok-4.7-xhigh）只读起草、主会话审定；施工交 Cursor，主会话验收、删除文件、提交与发布。

## 1. 用户要求（2026-10-17）

- 比较现代化；不要多余功能；**不让后端接口空着**——每个 `/api/v4` 接口在 App 里都有实际用途，每个界面背后都是真实接口，不留占位、不调任何 `/api/v1`。
- 推送不做验收，但 iOS 照常注册并 `POST /api/v4/devices`；点开推送进最新一期。macOS 不推送。
- 名单页不先出样图确认，直接一条龙发布 4.0.0 B112。P1 规则调参以后再做。

## 2. 关键决定

- **导航**：iOS 三个标签：晨报、历史、设置；晨报栈为名单 → 条目详情 → 原文，系统返回手势、下拉刷新；历史点进复用名单页。macOS 用 `NavigationSplitView` 铺满窗口：左栏当期名单独立滚动，右栏详情固定，右栏里再进原文；日期在左栏顶部菜单（「最新」走 `/reports/latest`，某一天走 `/reports/{tradeDate}`，列表来自 `/reports?limit=60`），不另开历史页；设置用系统设置窗口（⌘,），工具栏齿轮也打开它。
- **状态**：新 `MorningModel`（`@Observable`）只在内存留本次会话打开过的期与历史列表；晨报页出现、下拉、点推送时重新请求最新一期；换服务地址或令牌即清空重载；不写磁盘缓存，启动时删掉 `neckline.k10.` 前缀的旧缓存键。整份解码失败显示「这份晨报暂时读不了」并可重试。
- **网络**：只请求 `/api/v4`，时间字段保留字符串、展示时格式化；401 的 `detail` 可能是字符串（`deps.py`）也可能是对象，一律「令牌不正确」；404 认 `no_report` / `no_document`；503 认 `v4_not_configured` / `v4_db_not_ready`。检查连接先 `GET /health`，有令牌再 `GET /reports/latest`（404 `no_report` 也算令牌可用）。日志与夹具不出现令牌。保留 Debug 回环地址开关与现有 `AppConfig`（Keychain 令牌、正式/本地开发、手填地址、`NK_DISABLE_PERSISTENT_CREDENTIALS`）。后端接口不改。
- **推送**：iOS 请求通知权限、注册 APNs，设备令牌十六进制 `POST /api/v4/devices`（`platform: ios`）；结果只在设置里显示；任意远程通知（冷启动或点按）切到晨报标签并重载最新一期。entitlement 保持 `development`（Xcode 直装）。
- **展示取舍**：不展示 `rank`、`relation`、`fresh`、`configVersion`、`stats`、`kind`、`reportId`；每条都是利好，行上不再加方向色标；重要程度「高」用主色。待定四段默认折叠在「待定与旧事」下，空段不出现，分类名：类型不在收录清单、受益方、看不出是否这段时间首次公开、判为旧事。原文页有 `url` 时给「原始链接」（系统浏览器）；`others` 只展示。
- **版本**：功能完成后 `App/scripts/prepare_release_candidate.sh 4.0.0 112`，恢复 `test_client_version_governance.py` 的两端一致断言（五处同为 4.0.0），后端随之发布 B112。

## 3. 设计规范（写进 `DesignTokens.swift`，浅色与暗色都完整）

- **颜色**：页面 `#F5F6F8` / 暗 `#1C1C1E`；卡片白 / 暗 `#2C2C2E`；主文字 `#1C1C1E` / `#F5F5F7`；次文字 `#6E6E73` / `#98989D`；三级 `#8E8E93` / `#636366`；描边 `#E5E5EA` / `#38383A`；主色 `#0754E9` / 暗 `#4C8DFF`（`AccentColor` 同一套）；问题色 `#D70015` / `#FF453A`，只用于「晨报出问题了」等问题项。去掉渐变与琥珀色；选中行主色 12% 底。
- **字**：系统字体（中文 PingFang SC）。页标题 28pt semibold；说明 13pt 次文字；公司名 16pt semibold；代码与时间 `.monospacedDigit()`；标题行 15pt 限一行；标签 11pt medium；理由 15pt；原文 16pt。
- **间距与形**：页边 20（macOS 详情 28）；行内上下 10、左右 16；卡片圆角 12，标签圆角 4；1pt 细描边或系统分组底，无阴影；动画只用系统导航与 0.2 秒展开（只动 opacity / offset / scale）。
- **列表行**：第一行公司名 + 代码，右侧标签「业绩向好 · 高」；第二行事件标题，过长截断。macOS 左栏用这种行，不用大卡。
- **页眉**：`晨报 10/19 周一`；`窗口 10/16 15:00 → 10/19 08:00 · 08:03 生成`（北京时间）；失败且没有 `content` 时用信封上的 UTC 窗口换算成同样格式。
- **文案**：正在读取；还没有晨报 / 每个交易日 08:00 截止后出报；今天没有符合条件的利好；晨报出问题了 + 后端原因（只有这句用问题色）；正在出报 / 完成后下拉刷新；连不上服务；还没有填写令牌；令牌不正确；服务还没配好；数据库还没就绪；这份晨报暂时读不了；找不到这篇原文。缺口摘要原样一行、次文字。历史行 `10/19 周一`，副行 `已出 · 3 条` / `出问题` / `正在生成`。
- **设置分组**：连接（正式 / 本地开发、手填地址、生效主机、令牌、检查连接）；通知（仅 iOS：未询问 / 已允许 / 已拒绝，已登记 / 没能登记）；关于（`Neckline 4.0.0 (112)`，全 App 只出现这一次）。检查结果用人话：服务正常，库已就绪；最新一期 10/19，已出；只读网页可用 / 未配置；模型已配置 / 未配置。
