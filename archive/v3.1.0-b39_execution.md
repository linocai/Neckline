# Neckline 3.1.0 / 双端 Build 39 / Schema 7 执行记录

## 目标与边界

将 K10-v1.4 的冻结文章调查落为可恢复的工程流程：文章正文先拆关键命题，复用适用的已核来源事实与公司关系，再围绕具体问题执行 Tavily 搜索和受控全文，审读支持、反驳、冲突和缺口后有据收口，最后完整比较公司并派生发布结果。它不恢复交易计划、持仓／退出、收益结算、K9 或 K8。

施工基线是本地 `0c8a143`（B38 未发布），实际部署基线是 `v3.0.4-b36 / Schema 4`。初始施工仅授权本地验证；随后用户明确要求“一条龙发布”，授权部署、迁移和客户端换装，完成证据见本记录末尾。worker、晚间与晨间 timer 继续保持 disabled，不恢复被用户作废的任务，也不重跑 B38 的付费全量窗口。B38 的比较失败响应没有保存，任何实现或测试不得声称已经定位或修复它。

用户本轮已经定案：

- 未核传闻可正常形成推荐并进入 30 家、D1/D2 与成绩。它不是 verified，必须保留传闻性质、源头已知／未知、未证实环节、关键反证及条件化判断；不能编造来源、公司代码、事实或唯一排序。是否推荐仍遵从完整 K10 判断，不能把每条传闻都自动推入候选。
- 不为未来核验全文保留固定名额。冻结文章和获准的额外全文都按实际可用的 80／40 admission 处理；不能另设数字、预算或审批。

策略资料中仍写作“待决定”的两项以上述最新用户决定为准。本记录不修改研究仓，也不使生产 import `whynotme`。

## 公共契约

### 研究与执行状态

研究状态只能为：`ready_for_comparison`、`continue_research`、`pending_verification`、`abandon_recommendation`、`background_only`、`comparison_complete`。执行状态只能为：`ok`、`paused`、`failed`。两者由程序和持久化检查点共同投影；模型不能自报工具成功。

`comparison_complete` 表示输入范围内的每家公司已有结果，允许其中有 `pending` 或 `excluded`。它不等于已发布。执行失败时保留可复用证据和研究快照，但状态必须是 `failed`，发布不可进行；task 的 worker 终态不能覆盖这个事实。

每个公司评估使用：`primary`、`alternative`、`tied`、`pending`、`excluded`。前 3 个是可发布派生集，需有事件内 rank；`tied` 可共享 rank，`pending`／`excluded` 没有 rank。所有输入公司必须出现一次，不能删除错误对象使校验通过。比较发现某个竞争对象的未解问题足以改变唯一主推时，保留为 `pending_verification`／`continue_research`，不强排。

### 最小持久化模型

继续使用 `k10_source_document_versions` 作为真实来源版本，`k10_execution_item_checkpoints` 与 external attempt ledger 作为模型／网络恢复账，`k10_article_admissions` 作为正文准入账，候选／发布表及其 `comparison_json` 作为正式发布历史。Schema 7 新增的对象只覆盖以下关系：

| 对象 | 最少内容与键 | 作用 |
|---|---|---|
| 研究快照 | task、event/revision、消息 cutoff、实际查证 cutoff、上下文／Prompt／模型版本摘要、research/execution status、递增 revision | 一个事件当前调查状态与可恢复边界 |
| 命题 | snapshot、claim ID、原文陈述、主体／说话者／对象／动作、性质、增量、阶段／条件／时间、验证状态、决策影响 | 分开事实、预测、观点、宣传和传闻；不把原文称述直接升级为事实 |
| 命题—证据关系 | claim ID、真实 document/revision、支持／部分支持／反驳、定位／适用范围、来源／时间状态 | 可核对引用，不复制正文或伪造编号 |
| 问题与路径 | snapshot、question ID、关联命题／公司、支持和反驳条件、判断影响、目标来源、answer state、恢复条件；每条路径的查询、差异理由、预期增量与实际结果 | 防止 headline 一搜和同义词／转载循环 |
| 全文申请 | question、真实 source ref、摘录不足原因、预期判断变化、admission ref、requested/admitted/rejected/fulfilled 状态 | Extract／全文只在程序批准后供模型使用 |

这些对象可由少量关系表加结构化 payload 实现，但不能只保存模型散文，也不能为 A–G 每阶段建立独立表。写入使用 task lease 与版本比较；同一输入 digest 恢复时读取 checkpoint／快照，绝不重复外呼或领取第二个名额。读 helper 只能 read connection，`init_schema()` 仍只能出现在启动、显式写命令或受控迁移。

来源事实缓存键必须含 document ID/revision、内容哈希、调查契约／Prompt 版本和模型参数摘要。它只缓存稳定的原始来源事实。事件判断、公司关系适用性、市场上下文和比较结果另绑定 news cutoff、verification cutoff、公司池／市场时点；后取得的旧资料可支持新报告，不能回填历史报告。证据记录保留 publisher、标准化 URL、真实 origin／`unknown_origin`、转载关系、定位、发布时间及精度、fetched／first-seen 时间与 after-cutoff 状态；未知时间保持未知。

### 研究模型与管线接口

在 `discovery.py`／`pipeline.py` 增加单一 typed investigator adapter，而不是把七个阶段变成七个 agent 或固定七次调用：

```text
advance_research(snapshot, *, action, evidence_packet) -> ResearchStageResult
action = extract_claims | plan_gaps | plan_queries | assess_evidence | close_research | compare_companies
ResearchStageResult = claims | questions | query_paths | evidence_updates |
                      fulltext_requests | conclusion | company_assessments
```

管线仅在当前快照确实需要该 action 时调用它：已有证据足够可直接收口；无有效路径则待核；无公司映射可结束为背景／放弃；研究失败不继续伪造后续阶段。每一次模型请求经现有 checkpoint／attempt 账以 `task + stage + item + input digest` 幂等记录。执行配置新增明确的 investigation model option／Prompt contract revision，不使用默认模型参数。

阶段语义如下：

1. `extract_claims` 是一次原文理解产生的结构化结果：已合并进既有 `understand` 请求，再由程序记录此阶段，绝不为每个事件重新调用模型读原文。它拆出命题的性质、增量、说话者、条件和定位；综合报道的旧背景／无关分支不发现新选题。
2. `plan_gaps` 读取命题和适用的事件事实／公司关系缓存，提出能改变真实性、阶段、映射、最强反证、两日理由或比较的问题。确定公司映射后冻结该公司范围的市场／历史上下文，比较可明确待核；上下文加载本身不暗中启动旧 headline 搜索。
3. `plan_queries` 为每个开放问题给出中性查询、反驳路径、目标来源、预期信息增量与判断改变；程序拒绝越出已选事件／公司范围、没有新路径或已做过的意图。
4. 程序用 Tavily Search 执行获准路径。结果成为带查询路径和真实 metadata 的 source-document version；默认只给模型摘录。需要全文时 `assess_evidence` 返回全文申请，程序先以现有 `admit_article` 检查实际剩余、冻结名单和来源身份，再用 Tavily Extract／受控全文取得并记录。全文不可用或超限是待核理由，绝不是事实反证。
5. `assess_evidence` 以真实 evidence ref 更新支持、部分支持、反驳、同源重复、无关或冲突；可回到新路径。`close_research` 分别给事件／公司收口状态、缺口和恢复条件。`compare_companies` 只在可比较范围内完成全体评估，输出共同事实、五问、反证、未知和改变顺序条件。

`_event_evidence` 不再把整篇冻结原文在 verify、mapping、compare 中反复传递。阶段 A 和获准全文阶段可读取正文；后续 evidence packet 只装实际引用的证据卡、定位摘录、结构化命题／问题和所需市场／历史资料。程序从 refs 组装 packet，禁止模型引用未传入、伪造或 after-cutoff 的资料。

`TavilyEvidenceGateway`／checkpoint 的粒度改为问题和路径（而非 `event.headline`）。Search 保持 `include_answer=false`、`include_raw_content=false`，且每个请求保存问题、意图、新路径理由和真实结果；不以搜索次数、相关性或转载数判断证据充分性。Tavily Extract 不得绕过上述全文申请和 article admission。

### 未核传闻与发布 DTO

为评估、候选比较和公开投影增加显式 `EvidenceDisclosure`：

```text
verificationStatus: verified | partially_supported | unverified | contradicted
isRumor: bool
originStatus: identified | unknown
originEvidenceRef: optional real ref
unverifiedReasons: non-empty when status is unverified
conditionalAnalysis: non-empty when isRumor
```

`unverified + isRumor` 可以随 `primary`／`alternative`／`tied` 进入发布，条件是：公司代码通过真实股票池／硬排校验，比较覆盖完成，原始传闻来源或其“来源未知”的记录真实存在，且 `EvidenceDisclosure` 完整。它不能变成 `verified`，也不能因为有卡片或 D1/D2 结果反向升级。`pending` 的理由必须是会影响当前判断的缺口、冲突、时间／全文约束或有效路径，而不是“传闻未核”这一个标签。模型没有给出所需传闻标记时，程序从 claim kind／证据关系派生；无法安全派生则拒绝该输出为协议错误，绝不默默标成 verified。

扩展 `EventComparison` 为完整 assessment 集并提供 `publishable_assessments` 派生视图；现有 candidate creation、`OpportunityPublicationInput`、晚间 30 家、跨日关联、重叠样本、实际 availableAt 与 D1/D2 只消费该派生视图。完整 assessment 另保存在研究快照，正式 `comparison_json` 冻结当时 disclosure；历史 B36/B38 没有该字段时为 absent，不倒推或伪造历史标签。

### API、Swift、晨报、通知与分析

保持既有 K10 DTO 兼容性，新增字段均为可选／可加性投影，使新客户端读取 B36 时安全降级。新增 scan research summary（总事件、问题 answered/open、公司 `comparable/pending/excluded`、comparison state、execution failure）以及按 scan 查询完整 assessment 的 API；不返回全文、Prompt、原始模型答复、私有 URL 或凭据。

在发布 sample、机会详情、分析链、晨报条目和通知 payload 使用同一 `EvidenceDisclosure`。若已发布推荐以未核传闻为依据，所有可见路径都显示“未核实”，呈现源头已知／未知、条件和缺口；不能只在当前卡片补一个字而让晨报、推送或详情声称“已核验”。`analysis.py` 的 `_core_context` 与正反双方的 `prompts.pro_messages`／`con_messages` 必须传入冻结的 disclosure、引用和不确定性；后来的核验只形成新分析／证据版本，不回写旧分析或其结论。Swift 在 `K10Models`、client、presentation 和相关 views 解码并显示这些字段；策略标签明确为 `K10-v1.4`，分析修订明确为“分析第 N 版”。

执行进度新增研究计数和 research/execution status。`failed` 显示“执行失败，比较未完成”及安全错误码；`partial` 只能描述覆盖状态，不得显示为“已完成比较”或“没有机会”。`completed` 技术任务与 `comparison_complete` 分列。现有空态和填充态均须测试。

## 隔离验证边界

本轮可执行的真实资料边界只有既有 B38 一次隔离窗口的历史证据：服务器 `/tmp/neckline-v306-validation-20260908/private/validation-final.sqlite` 已关闭、去凭据，且只能在先确认主机、路径、只读模式和临时 DB 的前提下用于离线、确定性回归。它不得启动 task、worker、timer、Tavily／DeepSeek 或向生产写入，也不能重放 1,430 条标题的付费请求。报告将标题输入、冻结文章、实际正文、事件、问题、公司状态、比较、发布和执行失败分开，不能把 B38 的 37 篇已读或 9 次搜索叫作新流程真实质量。

本 Plan 不授权任何新的最新窗口真实外呼，故 builder 不复制密钥、不自行试跑。若后续用户授权，计划必须先固定：一个最新有效窗口、临时数据库／进程凭据、标题全量审计、晚≤80或晨≤40的实际正文上限、质量／协议错误时在正文前或后立即停止、最终安全回执位置；仍不启动生产 worker／timer、不写生产库、不恢复旧任务，也不做全量付费 replay。

## 风险、回滚与交接

最大产品风险是把未核传闻的“允许推荐”错误实现为“允许当事实”，或反过来被旧 verified gate 隐性阻断。防线是独立 disclosure、真实引用／股票池校验、条件化文案、发布派生集和跨 surface 契约测试。第二风险是多问题搜索或 Extract 绕开正文上限；防线是每次外部调用的问题路径和任何全文的 article admission。第三风险是迁移损害 B36／B38 审计；防线是受控备份、临时 migration／restore 和生产不在本轮范围。

本地问题回滚到 `0c8a143` 前先保存可复现的临时测试 receipt；生产未来迁移只能由已验证备份恢复，不能用 Schema 7 的 destructive down migration。无需用户网页操作。
