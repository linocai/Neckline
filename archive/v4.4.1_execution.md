**读法**：
- 在这 14 天、598 个事件上，**按辨识度取前 3 并不比原来按业务对口选的好**：平均差在 ±0.5pp 内，中位差多数为负，辨识度更好的事件不到一半。辨识度挑出的票波动更大：平均有时略高，中位更低。

- 11/10 那一天的例子成立：AIGC 40 天 A3 的前几名是中信出版、凡拓数创、芒果超媒、果麦文化、利亚德，比万兴、拓尔思好。但放到 14 天里看，这种情况和反例差不多一样多。
- 这一步没有算「模型在名单里跳过无关的票」和「对到更窄的板块」，这两点要看完整回放（§5）。

## 3. 方案

### 3.1 题材辨识度（B11，纯代码）

- **数据**：
  - 涨停：TuShare `limit_list_d`（`limit_type=U`），按交易日取，存全 A 的代码。新表 `limit_ups(trade_date, ts_code)` 与 `limit_up_days(trade_date, count, fetched_at)`，后者记某天已取全。
  - 全 A 成分：同花顺 `ths_member` 本来就是全量拉的，现在只存了创业板。新表 `sector_members_all(ts_code, code)`，在每周刷新概念时同一事务里整表替换；表为空时视为概念需要刷新。
  - 库结构 v8（只加表）。release.py：7→8 升级，8→7 回退列入只加表白名单。
- **什么时候取**：20:00 采集跑完、刷新概念之后，补齐「到今天为止」看 N 天需要的涨停；08:00 晨报开工时再补一次缺的（受 09:05 截止约束）。还缺就当天板块线不跑，缺口摘要写「板块线没跑：涨停数据没取全」，主线照常。回放不联网，涨停从快照写入。
- **算法**：报告日 D，取 D 之前最近 N 个交易日。某只票 s、板块 b、某天 d：s 当天涨停，且 b 的全 A 成分里除 s 以外当天涨停的只数 ≥ minOthers、并占（全 A 成分数 − 1）≥ minShare，就记一次。辨识度 = 次数和最近一次的日期；按次数从多到少、最近一次从近到远、代码排序。次数为 0 的不进名单。
- **配置**：`sectors.recognition = {"lookbackDays": N, "hot": {"minOthers": k, "minShare": r}}`，三项都必须给，不设默认值。用户拍板前配置保持 pending。

### 3.2 承接股与材料（B12，sector-evaluation-v6）

- 候选：板块的池内成分加回流点名的池内公司，去掉当天主线名单；算辨识度，**只把次数 ≥1 的放进材料**，按辨识度排序。名单为空的事件不调模型，记 skipped，理由「板块里没有题材辨识度名单」。
- 材料每只：代码、名称、题材辨识度（板块热的日子涨停几次、最近一次哪天）、主营、流通市值、是否被消息点名。不给任何位置数据（前 1、5、20 日涨跌、上涨家数、前一日是否涨停）。
- 代码核对：承接股必须在名单里、不重复、最多 3 只；点名公司不再自动放在最前；按辨识度顺序展示。
- 提示词改动见 §4。

### 3.3 对板块取最窄（B13，sector-mapping-v6）

- 板块清单每行写「名称｜池内成分股数」，提示词加「对得越窄越好」一段，见 §4。

### 3.4 修 4.4.0 的 3 处缺陷（B14，sector-selection-v2）

1. 拆半合并误并：两半的事件不再按板块合并，原样拼起来（同一条消息只留在第一个事件里）。同一件事被拆到两半、对到同一板块的，由第 3 条在交付时处理。
2. 内容过滤整天落空：归并调用返回 `content_filter` 时，和输出过长一样对半各调一次；一半仍失败只用另一半，缺口照实写。
3. 同一板块一天推两次：交付前，判推的事件里有两个以上同一板块的，或超过 3 个的，都调用一次比较。提示词加「同一个板块最多选一个」，上限取「3」与「判推事件涉及的板块数」中小的那个；代码核对选中的板块不重复。

### 3.5 回放工具（B15）

- `replay` 加 `--limit-snapshot <json>`：把涨停写进工作库，只用报告日之前的；回放从不联网取涨停。
- `--sector-snapshot` 同时写入全 A 成分。

**sector-evaluation-v6** = v5 改三处：
1. B 路第②条 `②A 股创业板里有业务实打实对得上的公司，比如供应链、同类产品、客户关系；` 改为 `②这个板块的业务和海外这个行业实打实对得上，比如供应链、同类产品、客户关系；`
2. `不看板块和个股此前涨了多少、处在高位还是低位。` 之后接一句：`材料里的题材辨识度只说明市场炒这个题材时认谁，不是位置。`
3. 从 `承接股：从材料给出的名单里选 1 到 3 只` 起，到 `这时只能判「不推」。` 止的整段，替换为：

```
承接股：市场炒一个题材时，买的是它熟悉的那几只，不一定是业务最对口的。材料里的名单是这个板块的题材辨识度名单：近一段时间这个板块整体走热的那些天涨停过的成分股，按涨停次数从多到少、最近一次从近到远排好；因为别的原因涨停的没有算进来。
- 从名单最前面开始选 1 到 3 只，跳过和这件事完全扯不上的，不要越过前面沾得上边的票去挑后面的。
- 被消息点名的、身份类板块的成分股，也一样按名单顺序，不单独优先。材料写明是身份类板块的（例如参股券商），名单里每只都有这层身份，不要求主营相关。
- 不要因为找不到消息里那家公司的直接合作方就判不推：事件本身过关，就从名单里出票。名单里没有一只和这件事沾得上边，leaders 给空列表，这时只能判「不推」。
每只写两句：为什么是它（市场为什么认它，它和这件事是什么关系）；价格（条件式的定性判断，例如「明显高开不追」「回落企稳再看」，开盘前不知道开盘价）。
不推的事件也照样写出承接股，price 可以写空字符串。
```

材料里名单的抬头改为 `名单（题材辨识度名单：近 N 个交易日里板块整体走热的日子涨停过的成分股，已按辨识度排好，去掉了今天个股名单里的，共 X 只）：`，每只一行 `代码 名称｜题材辨识度：板块热的日子涨停 n 次，最近一次 MM-DD｜主营：…｜流通市值：…｜消息点名：是/否`。

**sector-selection-v2** = v1 在「比较时看：」一段之前加一行：`同一个板块最多选一个。`
