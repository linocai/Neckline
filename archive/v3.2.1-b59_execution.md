## 3. 修复边界与架构决定

### 3.1 公司检索：业务语义与程序结构分开

1. 建立共用的语义输入提取／词匹配函数，覆盖正文初读、研究范围与比较上下文。只读取标题、事实的业务文本值、当前相关命题／问题文本及显式公司提示；排除 JSON keys、内部 ID、枚举状态、时间戳、完整调查容器与序列化外壳。保留文本中的真实主体、时间、数量和限定条件，不在原始持久化层删字段。
2. 英文缩写按 Latin 字母／数字词边界匹配，大小写归一；不能让 AR 命中 summary、UPS 命中 upstream。中英混合的真实业务表达可命中（例如生成式 AI、UPS 电源），中文公司名、产品、子公司和关系实体继续按业务词匹配，不引入字数阈值或关键词得分门槛。
3. 显式池内提示与业务命中形成待判断集合，记录 `matchedTerms`／提示来源／字段引用；公司名或关键词未命中不能直接判背景。保留模型基于消息提出池内公司和本地业务检索词的能力，结果仍由模型说明合理关联；不用网络搜索全市场代替本地资料查找。
4. 公司资料返回 identity、必要业务摘要、相关字段及这些字段对应的来源／报告期／适用范围／缺口。不得无条件附带全部 `sources`、整个 raw evidence 路径内容或全部收入／关系列表；也不得切掉负面业务占比、关系未确认、交叉口径等会改变判断的限定语。原始完整草稿资料和来源状态保持。

### 3.2 按动作装配上下文，完整事实仍可回读

采用本地持久事实＋按动作投影，不引入向量库、额外供应商或服务器会话依赖。每个模型请求须独立可理解；本地缓存命中、引用 ID 或稳定前缀均不意味着供应商记住了旧内容。

| 动作 | 本轮必要输入 | 默认不输入 |
|---|---|---|
| plan_gaps | 事件关键命题、相关公司短摘要、已有适用事实／实质缺口 | 全公司资料、工具逐项历史、全文 |
| plan_queries | 开放问题及关联命题、当前缺口、已尝试路径的短结论和签名 | 已关闭问题全文、无关公司字段、旧搜索摘录 |
| assess_evidence | 尚未审读的证据／全文、受影响问题与命题、与之相关的已有事实及反证 | 无变化证据全文、其他问题资料、全部历史 |
| close_research | 当前比较所需事实、公司关联、实质未知／反证、路径可用状态 | 搜索原始结果列表、重复公司档案、已读全文 |
| compare_companies | 所有待比较公司与必要差异、共同事实一次、完整未知／反证、必要行情／历史案例 | 原始调查轮次、路径流水、无关公司档案 |

- 完整 1,089 公司池在程序侧按冻结快照校验；研究请求只带快照身份、候选公司及按需读取能力。标题阶段全标题覆盖与跨批归并保留，不以“省输入”删标题。所有读取、解码与范围校验共用程序持有的固定池，不能让缩短后的 payload 变成白名单真源。
- 本地保存命题／问题完整身份和原文；同一请求中事实正文只表达一次，其他块用引用关联。证据卡保存真实 sourceRef、时间、资格和必要片段；claims、sourceStatements、检索 query 不得重复整段文本。关闭问题保留短结果和恢复条件，仅在被当前问题引用或出现新证据时回读细节。
- 给研究响应增加可选的内部 `contextRequests`：本地公司业务检索、指定公司字段、指定命题／问题细节、真实来源段落。请求声明目的及关联问题，返回结果附快照／字段或 documentId／revision／定位及内容哈希。未知引用不能变成事实；重复读取同一版本复用本地结果，不自动外呼。
- 回读延续当前 action，不推进为“研究成功”或新机会；新证据资格仍由既有时点规则审核。压缩摘要不足、存在矛盾或需要原文限定条件时必须可回读，不通过截断、固定字符配额、删反证或模型不可见的引用来达成数字下降。
- 局部模型响应解码须在程序持有的完整状态上按 ID 合并、验证；禁止因为本轮未投影某个旧命题就视为不存在或允许覆盖。旧对象不可变字段、未知引用、草稿与已核事实的界限保持。
- 请求另存实际可见清单（命题、来源片段／可归因短结论、公司字段及版本）。程序能读取完整库只用于身份／一致性验证，不能把全部库存引用加入模型证据白名单；本轮未展示内容的来源须先回读，单独 ID 不足以新增支持关系或把事实升为已核实。该边界与固定池成员校验分开。

### 3.3 信息增量与同任务事实复用

- 问题身份由命题锚点、池内公司范围、欲查事实／阶段／适用时间形成，不能只依赖模型新造 questionId；查询身份由规范化问题身份、查询／目标来源／意图和当时已知证据形成。模型需引用现有缺口并说明新的来源线索及可能改变的判断，同义重述不自动形成新缺口。
- 程序可以确定的重复（更换 ID／排列、等价查询、同内容版本／转载源头、已执行来源路径）本地归并并记录复用／无新增原因，不报整事件失败；不因每条重复再请求一次模型修复。不能仅凭同域名或文字相似就丢掉新的否认、阶段变化、来源修订或独立反证。
- 只有新文档版本、新适用事实、实质状态变化或有效未尝试路径才触发对应审读／续查；0 条新证据不会再整包审读。没有可执行新路径时用现行收口语义说明未知，仍可进入有效条件比较；信息尚不能支持公司关联则保留真实 pending／放弃结果，不伪装为成功推荐。不得增加固定次数、来源数、token 或全文限额。
- 同 task 共享以来源版本和事实命题为单位；沿用现有 source document、claims、evidence links 和通用任务检查点，不另建整套研究存储。先复用正文初读已有共同命题，再复用同任务相关事件已经完成且适用的来源事实／检索结果／获准全文；各事件冻结自己实际读取的依赖清单。
- 来源共读 key 包含真实来源身份、revision／内容哈希和提取契约；同一 URL 的修订不得复用旧正文，转载不同 URL 保留各自来源链。搜索复用须包含规范化问题、冻结搜索参数和时间上下文；不把同 URL 的两个不同问题视为已回答。公司推断、相对排名、当日注意力、行情和机会身份不得跨事件缓存成结论。
- 共享不绕过截止资格：接收事件逐条校验消息截止、查证截止、来源发布时间精度和正文版本；未知、晚到、更正／否认保持各自状态。共享后仍须能说明原始出处，不能把转载累计为多源证实，也不能把新证据回填旧报告。
- 串行和现有并发下相同共享工作只占用一个已绑定的外部请求身份；在领取、响应持久化、事实入库、依赖冻结之间中断后，只恢复未完成部分。不能用临时进程内缓存作为恢复证据，也不能因租约切换重复付款或等待自己持有的共享工作。

### 3.4 推荐与机会身份分工

- v2 的有效公司比较决定 primary／alternative／tied／pending／excluded。新推荐仍须满足真实股票池、有效比较结构、证据引用与披露规则；“缺官方确认”“只有单一来源”“条件尚未成就”不得单独触发后置否决。角色和共享名次按 B70 语义保留。
- 推荐资格先于身份路由。无历史正式机会且已完成有效比较的首次公司事项，可由系统从当前真实事件事实及比较的两日理由构造 initial，沿用统一身份校验；不再花一次模型调用重新判断是否推荐，也不填造新事实或默认理由。
- 与历史有关的身份判断只处理 independent／material_stage／continuation 等职责：保留新事实、实质变化、两日理由及 relatedOpportunityId 校验。确定为同一已发布催化／阶段时复用原身份和窗口；仅在需要语义判断新阶段或独立催化时调用受限分类。有效推荐不能在此返回 background 或仅因未核实返回 needs_review；不得靠解析拒绝理由的关键词来强行改成 initial。
- pending／excluded 且无相关旧机会时直接保存相应研究结果，不调用机会分类。存在相关旧机会与新的重要反证／已核实否认时仍进入现行风险／撤回路径；相对吸引力下降不等于证据推翻，不能一律 invalidated，也不能因提前跳过非推荐角色丢掉旧机会撤回。
- 每日是否展示与是否创建机会分开：再次被有效比较选中可占当天卡片名额，continuation 仍沿用原窗口；已到期旧催化不重开。真正新阶段／独立催化才建新机会；重叠、同公司多催化、晨间更新、选择和 D1/D2 评价规则全部保持。
- 后置身份结构错误仍走受影响步骤的真实未完成状态和精确回复复验，不静默猜旧窗口，不把无效证据“容错”为事实；其他有效公司保留。已发布历史与原报告不按新逻辑重新分类。

## 4. 内部持久化、恢复与前后端契约

- 新上下文协议明确命名 `k10-v2-context-3.2.1`，在实际生产者创建新任务时冻结并进入模型请求／共享工作的缓存身份；它是工程协议版本，不是新策略参数或用户资料修订。不得重写旧执行配置或任务绑定来伪造兼容性，不激活旧任务。
- 实际输入哈希包含所用来源／资料版本、action、当前必要状态、提示协议和冻结模型端点／名称／参数；密钥不入哈希明文或回执。持久化 revision、墙钟、JSON 字段顺序、租约、重试次数不能使相同语义请求产生新付款身份。
- 同任务待执行请求须冻结自己的依赖清单，恢复时不因其他事件新写入共享库就更换已付请求输入。新证据在后续合法增量步骤处理；保存的原回复仍按原输入校验，不能拿新上下文套用旧回复。
- 使用 `k10_external_attempts` 统计物理请求，使用输入审计统计序列化输入；报告 action、唯一来源／资料字段、重复块字符、共读／局部读取／模型缓存复用和网络尝试。可在现有 JSON 诊断记录中增加分项清单，不扩展产品用户流程。离线 transport 的 token 占位值不能称为真实 token 节省。
- 对客户端仍输出完整 comparison、evidenceDisclosure、sourceRefs、opportunity identity／kind、窗口、选择、排名及缺行情状态。增量输入不能造成 API 只剩内部引用；客户端可查看的事实、来源和不确定性必须与持久化结果相符。若确需 DTO 调整，双端当前 Swift 同步并补实际响应解码；不能只改手写 fixture。

| 真实误召回 | JSON keys 含 upstream_relevance／summary／coverage／stage 不再召回 UPS／PS／AR／GE 公司；真实业务词、中英混排、代码／别名仍召回；无公司名的“亚马逊云科技生成式AI认证变化”仍召回 300002.SZ。 |
