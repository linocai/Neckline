### v1.5-① · 参考件三件套地基:生成 + 夹逼 + 落库(@builder)

**背景**:需求 9 主体。候选卡的「四件套」是 K1 时代的模板文案(`report/candidates.py` 的 `entry_plan_text` / `stop_loss_text` / `target_text`),在候选语义早已改成「过完安检、值得花注意力的票」之后,它既不是买入信号、又摆着"参考买点/参考止损/参考目标"的架子。本块把候选卡的输出层换成**三件 LLM 参考件**,并给它们**一条硬夹逼 + 一张成绩单表**。

#### ①-A 新模块 `neckline/report/reference_plan.py`(唯一实现)

- **输入集 = 信息卡产出(第〇原则同构的直接兑现)**:对每只候选调 `report/info_card.py::build_info_card(trade_date, code, ...)` 取 **60 日 K 线 + 快照七项 + 红黄牌 + 温和带 + 消息面 / 龙虎榜摘要 + 市场语境**,格式化成纯文本块喂 LLM。**不另起取数路径、不新增 TuShare 配额**。
  - **成本已知**:v1.4.1 年分区裁剪后生产实测单只 **冷 3.05s / 热 2.25s**;20 只 ≈ **45~60s**,计入 ②-D 时间账。
  - **可复用不重取**:`pipeline.build_report` 里 `attach_info_card_summaries` 已算过摘要位,但**60 日序列不在摘要里**,必须走 `build_info_card`;**别为了省这一次而把 60 日序列塞进报告快照**(v1.4-④-B 已定案:快照只存摘要位)。
- **哨兵阈值块(需求 9 第 3 点「喂给 LLM,使剧本与盘中自动警报同频」)** —— 全部**读单一源,不抄字面量**:
  - `report/candidates.py::invalidation_spec()` 四项(低开 `-2%` / 全天未翻红 / 收盘破 VWAP / 量比 `<0.8` 或 `>3.0`);
  - `sentinel/precall.py` 三个盘前常量:`PRECALL_GAP_UP_INVALIDATE`(高开作废 3%)、`PRECALL_AUCTION_VOL_HIGH_FRAC`(0.10)、`PRECALL_AUCTION_VOL_LOW_FRAC`(0.005);
  - 现役 `stop_pct`(`brain.active_config()`);
  - **明日涨跌停价**(见 ①-C)。
  - prompt 里写明:**这些是盘中会自动报警的机械阈值,你的剧本分支要与它们同频,不要给出与之矛盾的行动指引**。
- **prompt 硬约束(承 §2.7 + §2.0)**:自由叙述、禁分栏模板卡;**明写"你产出的是参考,不是指令;买卖与终选在用户;系统不代下单"**;**明写"不得给出止盈线/目标价的说法"**;搜索无结果必须明说、禁编造(承 `llm/judge.py` 既有信息边界三条)。

#### ①-B 一次调用产出「评语 + 三件套」(定死,不许拆成两次调用)

- **复用 `llm/judge.py::judge_candidate`**(duck-typed,可传 `system_prompt`;项目 CLAUDE.md 铁律「喂类候选对象给 LLM 审判一律复用它」)—— 新增一版 `REFERENCE_PLAN_SYSTEM_PROMPT`,**不另写调用 / 解析 / 降级链**。
- **输出格式 = 既有先例的最小扩展**:自由叙述(= 需求 9 第 4 条「其他评语保持现状」)→ 空行 → **`结论:通过|否决`**(既有机器可读标签,`_parse_verdict` 一字不改)→ 空行 → **一个 ```json 围栏块**,内容定死:

  ```json
  {"buy": {"low": 12.34, "high": 12.98, "why": "…"},
   "exit": {"low": 15.10, "high": 15.80, "why": "…"},
   "script": "…(明早开盘行动指引,带分支)",
   "veto_reason": null}
  ```
  - **否决时**:`buy`/`exit`/`script` 三个键置 `null`,`veto_reason` 写不买理由。
  - **解析姿势**:取**最后一个** ```json 围栏块;无围栏时容忍"末尾裸 JSON 对象";解析失败 → ①-D 的 `unavailable` 态,**叙述与结论标签照常保留**(绝不因为三件套解析失败而丢掉审判结论)。
  - **为什么允许一段 JSON**:承 `llm/judge.py` 模块头已论证过的口径 —— §2.7 禁的是**内容本身写成分栏卡片**,不是禁止一个机器可读收尾标记;三件套需要**数字**才能被夹逼校验与落库对拍,自然语言抠数字是脆的。**卡面展示的是数字 + `why` 的自然语言,不是把 JSON 摊给用户。**
- **风险否决的唯一判据 = 既有「结论:否决」标签**(**不新增第二个否决开关**,防两个源打架)。`verdict=否决` → 三件套**一律不展示**(即便模型给了数字也丢弃),不买理由取 `veto_reason`;`veto_reason` 缺失 → 置 `null`,卡面展示既有 narrative(它一定在),**不硬凑、不截断 narrative 假装是理由**。
- **verdict 仍不改变候选去留**(§2.3 v1.3 语义 + §2.0 第 3 条:机器不禁、人可复核)——否决票**照留在 20 只里、信息卡照给**,只是没有三件套。

#### ①-C 夹逼:唯一底线(防幻觉,一行判定)

- **明日涨跌停价**:`limit_derived.compute_intraday_limit_prices(pre_close=候选当日 close, board, is_st, trade_date=next_trading_day(报告日))`。
  - `board` / `is_st` 走 **`sentinel/universe.py::load_stock_meta`**(唯一源,退潮哨兵同款),**不自己判 ST 前缀、不自己分板块**。
  - `next_trading_day` 走 `neckline.calendar`。**`trade_date` 传的是明日**——ST 幅度有制度分界日(`MAIN_ST_REFORM_DATE`),传错日期会取错幅度。
  - ⚠ **`Candidate.close` 在报告日 T 上就是原始收盘价**:`data/adjust.py::apply_qfq` 的前复权基准 = **传入区间内最新一条** `adj_factor`,而面板区间恰好截到 T,故 `qfq(T) == close(T)`。**可以直接当明日 `pre_close` 用,不必反查原始表**(这条写进模块 docstring,免得后人来回改)。
- **判定(定死)**:`buy.low` / `buy.high` **两个数都必须落在 `[跌停价, 涨停价]` 闭区间内**,且 `0 < low <= high`。任一不满足 → **买入参考区间不显示**,`buy_clamp`(①-E 表列)记 `rejected_out_of_limit`(越界)或 `rejected_malformed`(缺数 / 非数 / low>high),**并如实落库**;LLM 压根没给这一件 → `absent`(**与被拦分开,「没给」和「给了被拦」是两件事**)。
  - **只夹逼买入区间,不夹逼离场区间** —— 离场说的是**本轮上涨的压力位**,可能几个交易日后才到,拿明日涨跌停去夹它是错的。离场只做格式合法性校验(`0 < low <= high`),不合法则不显示。
  - **算不出涨跌停(`pre_close<=0` / 查无 meta)→ 同样不显示买入区间**,`buy_clamp='rejected_no_limit'`。候选恒非次新(`intel_candidates.NON_NEW_MIN_DAYS=120`),**新股无涨跌幅豁免不适用**,不必为它写分支——但上面这条兜底分支要留。
- **止损价一笔带过(需求 9 第 1 点)**:`stop_price = round(close × (1 − stop_pct), 2)`,`stop_pct` **读现役 config**;它是**系统算的、不是 LLM 给的**,与买入参考区间同一行展示(例:「参考买入 12.34~12.98;按现价基准止损约 11.72(章程 −5%,以实际成交价为准)」)。**止损不再单列一条**(需求 9:−5% 是章程常量,不再每卡说教)。

#### ①-D 三态与诚实缺省(§3.8「没有」vs「没看」)

`ReferencePlan.status` 三值,**不许合并**:
- **`ok`** —— 审判通过 + 至少产出一件有效参考件(某一件被夹逼拦下时该件为 `null` + 各自 reason,整体仍 `ok`);
- **`vetoed`** —— 审判否决 → 三件套全 `null` + `veto_reason`(或 `null`,见 ①-B);
- **`unavailable`** —— LLM 未激活 / 调用失败 / JSON 解析失败 / 本块异常 → 三件套全 `null` + `unavailable_reason` 原文。**这是"没看",绝不能显示成"没有参考区间"。**

#### ①-E 落库:`reference_plans` 表(B2 = LLM 参谋成绩单原料)

- **新表**(`neckline/db.py::_SCHEMA` 里 `CREATE TABLE IF NOT EXISTS`,新表天然幂等,**不进 `_COLUMN_MIGRATIONS`**——同 `inquiry_log` / `industry_strength_daily` 先例):

  ```sql
  CREATE TABLE IF NOT EXISTS reference_plans (
      trade_date    TEXT NOT NULL,          -- 'YYYYMMDD'
      ts_code       TEXT NOT NULL,
      status        TEXT NOT NULL,          -- ok | vetoed | unavailable
      verdict       TEXT NOT NULL,          -- 既有审判标签:通过|否决|未激活
      close         REAL NOT NULL,          -- 当日收盘(参考件的锚,审计用)
      limit_up      REAL,                   -- 当时算的明日涨停价(NULL=算不出)
      limit_down    REAL,                   -- 当时算的明日跌停价
      buy_low       REAL, buy_high  REAL,   -- NULL = 未给 / 被拦(看 clamp_status)
      buy_clamp     TEXT NOT NULL,          -- ok|absent|rejected_out_of_limit|rejected_malformed|rejected_no_limit
      buy_why       TEXT,
      stop_price    REAL,                   -- 系统算的 close×(1-stop_pct),非 LLM 产出
      stop_pct      REAL,                   -- 产出该行时的现役 stop_pct(口径指纹)
      exit_low      REAL, exit_high REAL,
      exit_clamp    TEXT NOT NULL,          -- ok|absent|rejected_malformed
      exit_why      TEXT,
      script_text   TEXT,
      veto_reason   TEXT,
      provider      TEXT, model TEXT,
      degraded      INTEGER NOT NULL DEFAULT 0,
      degrade_reason TEXT,
      created_at    TEXT NOT NULL,
      PRIMARY KEY (trade_date, ts_code)
  );
  CREATE INDEX IF NOT EXISTS idx_reference_plans_code ON reference_plans(ts_code, trade_date);
  ```
- **写侧** `neckline/report/reference_plan_store.py`(同 `holding_store.py` / `news_alerts_store.py` 体例):`INSERT OR REPLACE` 幂等;依赖方向 **store → reference_plan 单向**;**只在 `save=True` 时写**(预览 / 单测不产生副作用,同 `holding_store` 惯例)。
- **`stop_pct` 是口径指纹**:将来回看"这条参考件是在哪版章程下生成的"靠它,别省。
- **对拍留口子(本版只落数据,不出报表)**:`P3-11`(打法 × 论点双维归因)接入时按 `buy_clamp` / 是否落在参考区间内 / 实际成交价 vs 参考区间分桶。**本版不写任何成绩单报表**,§七 P3-11 挂账 +1 维。
