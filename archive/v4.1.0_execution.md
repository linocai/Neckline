# 4.1.0 执行记录：KX 看板与推荐高亮

状态：**施工中**。用户 2026-10-19 晚确认方案，同晚说「开始工作流 v4.1.0，build 递增」。基线 `2269ea1`（线上 B120 `a95cc3e`）；目标：后端 4.1.0 B121，App 4.1.0 (121)。

## 1. 目标

App 顶层分成 **K10** 和 **KX** 两块，两块逻辑各自独立。

- **K10**：即现有的晨报（最新一期、详情原文、历史），不变。
- **KX**：KX 那 100 只股票池的实时行情看板，相当于为用户定制的迷你同花顺自选。不看 K 线和分时，只看用户在意的数字。另外，对话 Agent 推荐的票会在看板上置顶并高亮，热度按交易日衰减。KX 的消息面不在这次范围内。

## 2. 已定的决定（2026-10-19，用户）

1. **推荐怎么送到 Neckline**：在 KX MCP 新增「记录推荐」工具，KX 挑票规则里加一条「给出推荐后调用它」。KX 服务器（HZ）收到后，把股票代码转发给 Neckline 新增的接收接口。Agent 讨论 KX 时只需要连 KX 一个连接器；Neckline 的 MCP 保持纯只读。KX 只多出这一个对外转发的口子，代码在 KX 项目里改。
2. **衰减按交易日算**：被推荐的那个交易日加粗高亮并置顶；下一个交易日变淡，仍然置顶，但排在当天推荐的后面；再下一个交易日恢复普通样式。中途再次被推荐，就重新从当天算起。同一天推几次就累计几只（3、6、9 只……）。
3. **推荐归属哪个交易日**：交易日 15:00 之前收到的，归当天；15:00 之后或非交易日收到的，归下一个交易日。
4. **排序**：置顶区内，当天推荐的在前，按推荐时间从新到旧；前一交易日推荐的在后。普通区按涨跌幅从高到低。
5. **刷新**：后台不定时取数。打开页面时取一次；停留在页面上时，盘中每 60 秒续取一次；切走、锁屏或进入后台就停止。非交易时段打开只取一次。服务端缓存 60 秒，多个设备同时开着也只算一次。
6. **行情数据**：实时数据全部用麦蕊，由 Neckline 自己在 NB 上调用。日线统计用 TuShare，每天各取一次。不做分钟级数据和资金流向。
7. **股票池必须正确**：用户周末换池后，下周第一次打开看板，名单就要换好（具体做法见 §3.1）。
8. **两端都做**（iOS、macOS），App 大改，版本号 4.1.0。

## 3. 方案

### 3.1 股票池同步（NB）

- Neckline 在库里存一份 KX 名单：代码、名称、申万二级行业、名单版本号、核对时间。
- 每次请求看板时，先读 KX 的公开健康检查 `https://linotsai.top/kx/health`。它返回 `pool_version` 和 `pool_count`，不需要认证，也不调用麦蕊。结果缓存 60 秒。
- 版本号和本地不一致时，读一次 KX 的只读页面（`/kx/read/<KX_READ_KEY>?format=json`）拉新名单，校验代码格式、数量与 `pool_count` 一致、版本号一致后，原子替换。这只在换池时发生。`KX_READ_KEY` 只放在 NB 的环境配置里。
- KX 连不上时，照常显示上一份名单，并用一行小字写明「名单未能核对，最后核对 <时间>」。名单从来没同步成功过时，不出看板，如实说明原因。

### 3.2 行情取数（NB）

**实时（A 类，每次刷新）**：用麦蕊 `hsrl/ssjy_more`，每组最多 20 只，100 只分 5 组。每组结果缓存 60 秒，失败的组 10 秒后再试。某一组失败时，只把这一组的行标成「未取得」，其余照常显示。

| 字段 | 来源 |
|---|---|
| 最新价、涨跌幅、涨跌额、开盘、最高、最低、昨收、振幅、换手率、成交额、成交量（手） | 麦蕊 `p, pc, ud, o, h, l, yc, zf, tr, cje, v` |
| 开盘涨跌 | `o / yc − 1` |
| 现价在今日区间的位置 | `(p − l) / (h − l)`；`h == l` 时留空 |
| 距今日最高回撤 | `p / h − 1` |
| 报价时间 | 麦蕊 `t` |

**日线统计（B 类，每天一次）**：用 TuShare 的 `daily`（100 只、约 25 个交易日）和 `daily_basic`（市值），各取一次，缓存到下一个完整交易日。当天的日线发布之前，用上一个完整交易日的数据。

| 字段 | 算法 |
|---|---|
| 5 日涨跌、20 日涨跌 | 实时价相对 5 个、20 个交易日前的收盘价 |
| 20 日日均成交额 | 前 20 个完整交易日的成交额均值 |
| 量能倍数 | 今日成交额 ÷ 20 日日均成交额（盘中只是累计值，界面写明） |
| 总市值、流通市值 | 前一交易日的市值 × 实时价 ÷ 昨收 |
| 均线位置 | 实时价相对 5、10、20 日均线（均线用完整交易日的收盘价算），在上方还是下方 |

不复权，除权除息前后会失真，沿用晨报单票概览的说法。缺数据就留空并写明，不估算。

**调用量**：盘中停留 N 分钟，麦蕊约 5 ×（N + 1）次；TuShare 每天 2 次（不占 major_news 的额度）。麦蕊体验版的限速是每分钟 1,000 次，这里每分钟最多 5 次，再加上 KX 自己的调用，也远低于上限。

### 3.3 推荐接收（NB）

- **接口契约（KX 按此对接，改动须两边同步）**：
  - `POST https://nk.linotsai.top/api/v4/kx/picks`
  - 请求头：`Authorization: Bearer <KX_PICKS_TOKEN>`，`Content-Type: application/json`。
  - 鉴权：用 Bearer 密钥，常量时间比较。nginx 只放行 HZ 的出口 IP，作为第二道防线。两边的密钥由主会话在部署时生成并写入，不进 Git。
  - 请求体：`{"requestId": "<KX 生成的 UUID>", "pickedAt": "<带时区的 ISO 8601>", "stockCodes": ["000592", "600000"]}`。代码是 6 位数字，1–20 只，不能重复。
  - 响应：
    - `200 {"status": "recorded" | "duplicate", "requestId", "tradeDate", "stockCodes"}`
    - `400 {"status": "invalid", "reason"}`
    - `401 {"status": "unauthorized"}`
    - `409 {"status": "out_of_pool", "reason", "codes": [...]}`
    - `503 {"status": "pool_unverified", "reason"}`：名单从来没同步成功过。
  - 同一个 `requestId` 再次请求时，返回首次的结果并标 `duplicate`；如果请求体和首次不同，返回 400。
- **处理**：
  - 代码必须在当前名单里（先按 §3.1 核对名单），不在的整批拒绝，并写明是哪一只。
  - 同一个请求编号重复发送只记一次。
  - 按 §2.3 的规则算出归属的交易日后入库。
  - 日志记代码和时间，不记密钥。
- **高亮状态**：服务端用交易日历计算。看板的参考日是：今天是交易日就用今天（全天有效），否则用下一个交易日。
  - 归属日 ≥ 参考日：当天，加粗高亮。
  - 归属日 = 参考日的前一个交易日：变淡。
  - 其余：普通样式。
  - 同一只票取最近一次推荐。
- 交易日历沿用晨报用的 `static_holidays`（2027 年的休市表在 Backlog 里，必须在 2027-01-01 前补上）。

### 3.4 看板接口（NB）

- `GET /api/v4/kx/board`，和晨报接口一样用 Bearer 鉴权。
- **返回**：
  - 名单版本、名单核对时间、名单是否过期。
  - 报价时间、是否在交易时段、建议的刷新间隔。
  - 最后一次收到推荐的时间。
  - 每只股票一行：代码、名称、行业、A 类和 B 类字段、高亮状态（当天、变淡、普通）及最近一次推荐时间。
- 排序在服务端按 §2.4 排好，App 只负责显示。
- **库结构**：新增 KX 名单表、推荐表、日线统计缓存三张表，库结构升到 SCHEMA_VERSION 2。迁移随发布执行（release.py 会先做恢复点并还原校验）。

### 3.5 KX 改动（在 KX 项目会话里做，不在 Neckline 改）

- 新增 MCP 工具「记录推荐」，参数是股票代码。工具只接受当前池内的代码，收到后转发给 Neckline 的 §3.3 接口。
- 转发失败时，如实告诉 Agent「记录失败」，不能假装成功。请求编号由 KX 生成，重试不会重复记录。
- KX 下发给 Agent 的挑票规则里，加一句「给出推荐后调用记录推荐」。
- KX 按它自己的发布流程上线。新工具要在 ChatGPT、Claude、Grok 的手机端和电脑端实际调用验收。

## 4. 验收标准

- **名单同步**：换池（版本号变化）后，第一次请求就切到新名单。KX 连不上时，如实标「未能核对」。从来没同步成功过时，不出看板。
- **行情**：100 只按 5 组取数；某组失败只影响这一组；缓存 60 秒内不重复调用麦蕊；日线统计每天只取一次。用注入测试验证调用次数。
- **推荐接收**：签名、来源校验通过才入库；池外代码整批拒绝；重复请求只记一次；交易日归属覆盖 15:00 前后、周末、节假日；高亮按交易日衰减，覆盖当天、下一交易日、再下一交易日、中途再次推荐。
- **端到端**：KX 测试环境调用「记录推荐」→ 转发 → Neckline 入库 → 看板接口 → App 置顶加粗。用隔离库产出的真实看板响应，喂给当前 Swift 模型解码。
- **App**：三条构建全部通过，XCTest 核对通过数；有数据、无数据、名单未核对、盘中、收盘后五种状态都截图验收，和样图对照。
- **KX**：在 KX 项目里按它自己的规则测试和发布；新工具在三家客户端的手机端和电脑端实际调用验收。
- **全量**：后端全量测试全部通过才发布；每个上线 build 打 tag，并写进本记录。
