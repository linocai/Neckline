## 四、篮子族 DTO 逐字段(⑮ 要照着建 Swift 侧)

### 4.1 两类 DTO,决定 Swift 侧怎么写解码

| 类别 | 判据 | 本次涉及 | Swift 侧要求 |
|---|---|---|---|
| **A 类:每次响应重新拼装** | 服务端用 pydantic 默认值重构,新字段旧数据也会补全 | `BasketOut` / `TierOut` / `BasketVerificationOut` / `DroppedBasketOut` / `PositionPlanOut` / `ProfileOut` / `PackOut` / `EvalWeeklyOut` | 可用合成 `Codable` + `Optional`/默认值 |
| **B 类:写入当时冻住的历史快照** | 服务端升级**永不**给老快照补新键 | 🔴 **`BasketCardOut`**(← `basket_cards.card_json`)、🔴 **`BasketReviewOut.mech`**(← `basket_review_daily.mech_json`)、既有 `ReviewWeeklyResult` | **必须**手写 `init(from:)` + 全字段 `decodeIfPresent` |

> ⛔ B 类用合成 `Codable` 的后果:装了新 App 的用户翻看几周前的老卡 → **整张卡解不出**。
> 已做成断言(`test_frozen_snapshot_dtos_hand_write_init_from_decoder`,⑮ 落地后生效)。

### 4.2 `BasketCardOut`(33 个顶层键 + `members[]` 25 个键)

顶层:`specVersion` `version` `basketKey` `tradeDate` `nextTradeDate` `name` `driver`
`driverKind` `evidence[]` `evidenceStatus` `whyNow` `members[]` `roleConflicts[]` `tier`
`rankInTier` `rankMech` `mechScore` `tierBreakdown` `tierReason` `tierNote` `scripts`
`scriptsUnavailableReason` `verificationSpec` `verificationText` `invalidationSpec`
`invalidationText` `risks[]` `disclaimer` `fingerprint` `disciplineLabels[]` `narrative`
`llmStage` `degraded` `notes[]`

成员:`tsCode` `name` `roleLlm` `roleMech` `roleConflict` `reason` `isPrimary` `industry`
`industryLift` `liftReason` `primaryReason` `rsRank` `k4Tag` `mech` `entryZone`
`entryZoneClamp` `entryZoneUnavailableReason` `maxChase` `maxChaseClamp`
`maxChaseUnavailableReason` `exitReference` `exitReferenceClamp`
`exitReferenceUnavailableReason` `tags[]` `tagsAbsent[]`

**四条不许违反的解码/展示纪律**:

1. **`roleLlm` / `roleMech` 两说并存**:`roleConflict=true` 时**两个都显示**,
   ⛔ 不许挑一个当"正确答案"。
2. **三个参考件各带 `*Clamp` + `*UnavailableReason`**:夹逼拒收时值是 `null` 且原因非空,
   ⛔ 不许把 `null` 显示成 `0` 或空白了事。
3. **`exitReference` 不是止盈线**(§2.8-C 语义红线),文案里不许这么写。
4. **`disclaimer` 原样透传不改写**;`tags[]` 每处带「参考、非指令」且**四不**
   (不进排序 / 不进哨兵 / 不改去留 / 不加分)。

### 4.3 snake→camel 的转换纪律(**唯一转换点**)

`report/basket_daily.py::card_to_public_dict` 是 `basket_cards.card_json` → 契约的
**唯一**实现;报告快照(`reports.basket_daily_json`)与 `GET /baskets/{id}/card`
两条路共用它,⛔ 不各写一份。

| 做什么 | 不做什么 |
|---|---|
| 顶层 / 成员 / `fingerprint` 的**字段名**转 camel | ⛔ `tierBreakdown` 的键(**五维维度名**,与现役包权重键逐字对应)|
| `role_conflict` / `is_primary` 的 **0/1 整数 → 真 `Bool`**(Swift `Bool` 解 `0` 会失败)| ⛔ `verificationSpec` / `invalidationSpec` 的条件键(喂 ⑧ 哨兵的机器半份)|
| 缺键 → **该键不出现**(冻结快照体例)| ⛔ 缺键补 `null`(那是把「这版卡没这个概念」讲成「有概念但值空」)|

### 4.4 `BasketDailyOut` 三段的可得性位(⑮ 界面必须讲不同的话)

| 段 | 数组 | 可得性位 | 空数组 + `available=true` | `available=false` |
|---|---|---|---|---|
| ③ 今日篮子 | `baskets` | `basketsAvailable` | **今天真没有篮子**(合法输出,⑥-b-B)| 本次没取到 |
| ③b 未定档 | `droppedBaskets`(**默认空数组**)| `droppedBasketsAvailable` | **算过了、今日零溢出** | 本次没跑 ⑥ |
| ④ 昨日复盘 | `reviews` | `reviewsAvailable` | 昨日无篮子可复盘 | 本次没跑 ⑨ |

**`droppedBaskets[].reason` 两个码语义相反,⛔ 客户端不许合并成一句「未入选」**:

- `capacity_overflow` —— 分数够、位置满 →「**今天机会多到装不下**」
- `below_quality_line` —— 连 `tier3_min` 都没过 →「**今天没什么好货**」

**⛔ `droppedBaskets` 没有 `basketId`** —— 它没进 `baskets` 表,给一个 id 会让用户
以为点得进去。

## 十一、契约线 🔵 幂等键语义的文档化(⑭ 欠账,本节兑现)

> 契约线 review 登记:「**幂等键的语义边界未写进契约注释**:同键不同 payload
> (客户端 bug 复用键)会静默重放上一次的结果。」

**语义定死如下(已写进 `schemas.py::PositionOpenIn.idempotencyKey` 与
`app.py::open_position` 的 docstring,本节是它的完整版)**:

| 问题 | 答案 |
|---|---|
| 它防什么 | **「服务端已落库、响应没回到客户端 → 客户端重试」** 这一类重复。开仓是**不可逆记账**,重复一笔之后持仓哨兵、仓位纪律、周复盘对账全都建立在错的持仓上 |
| 键的粒度 | **一次开仓意图** = 一个键(UUID 即可)。**重试时必须复用同一个键**;换一笔仓必须换键 |
| 同键 + 同 payload | 重放上次结果,`replayed=true`,**不开第二笔仓** |
| 同键 + **不同** payload | ⚠ **同样重放上次结果**,`replayed=true` —— 服务端**不比对 payload**、**不报错**。这是**已知且刻意**的语义边界:客户端 bug 复用了键(比如把键做成了常量),第二笔不同的仓会被静默吞掉 |
| 为什么不比对 payload 报 409 | ① 幂等键的用途是"重试同一意图",而重试时 payload 本就应当逐字相同 —— 不同 payload 意味着客户端有 bug,而**在服务端为客户端 bug 造一条错误分支,只会把一个可测的 bug 变成一个要处理的错误码**;② 真要防,正确的做法是键里带 payload 指纹(客户端侧),不是服务端事后比对 |
| 不传键 | **不设防**(CLI / 老客户端 / 历史补录逐字节不变)|
| 库级保障 | `positions.idempotency_key` 上的**部分唯一索引**(NULL 不参与去重)—— 并发同键两条请求都查不到时,库级约束是最后一道闸;⚠ 该索引住 `_POST_MIGRATION_INDEXES`,脏库上建不上时**只 WARNING 并继续启动**(开机脚本无权替用户清数据),此时退化为应用层去重 |

**⑮ 客户端契约要求**:每次开仓生成新 UUID 存进本次请求的状态里,**重试复用**、
成功后丢弃;⛔ 不许把键做成设备级/会话级常量。
