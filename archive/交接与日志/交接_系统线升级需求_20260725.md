# 交接 memo:系统线升级需求(策略线 → 系统线,2026-07-25)

> 来源:策略线会话 2026-07-25 与用户长谈定案。本 memo 只列**系统线要施工的部分**,
> 按优先级排序。策略侧背景与研究计划见 `STRATEGY_LAB.md` §四(同日更新),不复述。
> 背景一句话:用户重定位系统为人机协作——**用户 = 唯一决策人**,系统 = 情报收集 +
> 机械分析 + 纪律执行 + 归因审计;机器不再替用户选股。

## 需求 1:仓位章程变更(高危区——碰纪律章程,建议完工后叫一次 review)

- 现行:单笔 2 万 / ≤5 只 / 敞口 60%(`strategy_versions` 现役 config)。
- 新纪律(用户 2026-07-25 定,深夜最终版):总资金 12-13 万分**三仓(钉死
  ≤3 只)**;**单仓 2-4 万弹性带**(用户按信心自定,不定死单一数字),敞口
  上限 12 万。学费实验期(首 30-50 笔)用户可自主偏向低档。
- **-5% 止损不变;止盈与时间退出按需求 6 新规执行**(回落 8% + 浮盈豁免时间
  退出,本条与需求 6 同批激活,勿按本行早期版本的"回落 5%"实现)。
- **生效时机:用户清掉现有两笔持仓后才切换,切换动作前需用户确认**(staged,
  不要立即改库)。
- 施工要点:唯一源是 `strategy_versions` 现役版本 config
  (`neckline.strategy.brain.get_active()`),哨兵/台账读库自动跟随;
  PROJECT_PLAN §2.1 章程文本同步改;禁止在任何新文件里抄一份常量。
- **新增熔断纪律(用户 2026-07-25 批准,数字已定)**:连续 3 笔止损 或
  单日亏损 ≥ 4000 元(约总资金 3%)→ 当日停止开新仓、次日只减不加,
  完成一次强制复盘后解锁。系统无法物理阻止下单,以哨兵强提醒 + 客户端
  状态标记 + 日志留痕实现;触发与解锁事件都要落库(归因要用)。
- **仓位分配(用户批准)**:三仓 = 2 仓「短线追击」+ 1 仓「呼吸试验」,
  决策日志打法标签与之对应。

## 需求 2:决策日志(预注册式交易日志,新功能)

- 每笔买入**下单前**必录七项:①为什么买 ②为什么这个入场价 ③目标价
  ④离场价格区间 ⑤论点标签(有限枚举:题材主线 / 情绪周期位 / 资金流向 /
  技术形态 / 消息)⑥证伪条件(出现什么情况说明看错,不到止损线也走)
  ⑦**应对方案**(推演 2-3 种次日走势情景,每种写触发条件与动作:买入/持有/
  减仓/放弃;次日复盘时勾选哪种情形兑现——情景树预注册,来源:用户研习的
  短线战法总结 `/Users/linotsai/Lino/whynotme/总结.md` §六)
  ⑧**打法标签**(有限枚举:短线追击 / 呼吸底仓试验——2026-07-25 用户定向
  双打法并存做 A/B,归因必须按打法分开统计)。
- 时间戳必须先于成交(防事后被结果污染——与研究铁律"预注册先行"同原理);
  挂钩 `positions.py` 台账,平仓后自动关联结果。
- 归因输出:按论点标签统计胜率 / 盈亏比,进 4D 周复盘引擎周报。
- 额外一栏:**挂单未成交追踪**(用户习惯挂低价等回踩;记录未成交票的后续
  走势,检验"逆向选择:专接下坠、错过起飞"假设)。

- 主线识别器改定位为**拥挤情报件**(K2 判决:板块层有效但无次日领先性——
  当情报展示,不当选股信号)。
- 板块资金流展示(`moneyflow_dc`,2023-09 起有数;v1 上线日 schema 漂移坑
  已修,落盘必须走 `write_table_day`)。
- 复盘情报字段清单(2026-07-25 补,规格来源同上述战法总结 §五/§八):
  涨幅榜 / 跌幅榜 / 涨停梯队 / 跌停榜 / 大盘量能、最强题材及其核心一二名、
  市值偏好与涨跌幅制度偏好(10/20/30cm 哪类受资金欢迎)、题材持续天数
  (区分 2-3 日持续题材 vs 一日游)。以上全部 EOD 数据可算;竞价/L2 盘口
  无数据,不做。
- 晚间消息面自动检查(战法总结 §5.6):持仓 + 自选票公告扫描(减持/立案/
  暴雷/监管),数据源待查(TuShare 公告接口覆盖与时效);可先以 LLM 联网
  搜索兜底(复用 openai_compat 带搜索调用,注意 read_timeout=90 的坑)。

## 需求 4(随本轮升级一并施工;用户已定:试验仓在升级完成后才开首笔):呼吸战法试验仓台账

- 背景:用户 2026-07-25 定向**双打法并存 A/B**——三仓中两仓跑「短线追击」
  (持有 1-3 日,判错即止损换票),一仓试验「呼吸战法」(板块中军底仓
  1-2 周 + 择机日内 T)。30-50 笔后按决策日志归因裁决胜者扩仓。
- 台账需支持:底仓与 T 仓分离记账、T 次数与费用逐笔落账、「先手」成本优势
  跟踪(当前持仓成本 vs 现价距离)。
- 费用地板:单次 T 规模过小会被 5 元最低佣金吃掉费率(2 万规模双边佣金 +
  卖出印花税 ≈ 20 元 ≈ 0.1%);按实际费用落账,供归因判断 T 是否正贡献。
- 细节等漏斗 v2 定稿 + 用户确认启动后再动工,本条先占位。

## 需求 8(2026-07-28,策略线裁定 v1.4 方向 = 系统线三选一里的 (b)):K4 正选漏斗完整规格

- **裁定背景**:系统线 v1.4 立项问"K4 打法指哪种"。策略线裁定:(a) 激活 DB
  K4 行无意义(config≡K1,advisory 已在被读);(c) 等新机械内核**否决有案底**
  (四战役 + 用户 2026-07-26 终裁底盘暂缓);**(b) 产品化,按本需求执行**。
- **语义红线(写进产品文案评审)**:排序 = **注意力优先级**,不是收益预测;
  排第一 ≠ 最会涨;终选权在用户;UI 禁止"推荐买入"类表述。
- **正选漏斗 = 需求 5 四步管线 + 本节排序与信息卡细化**:
  1. 域与安检照需求 5(热门板块成员 × 卫生线 × 趋势向上 → 红牌拦、黄牌标);
  2. **排序键(只用审计过方向的量,依次)**:① 行业强度排名(K2 验证的拥挤
     探测器)② 题材持续天数**升序**(第 1 天最新鲜;H6 单调证据;≥4 天已被
     红牌拦)③ 黄牌数升序(无牌靠前——注意这只是风险优先排序,无牌≠会涨,
     盲选第一期已验)。板块资金流强度作并列展示;**RS 线斜率/行业分歧度等
     未经审计的量只进信息卡展示,不进排序键**(排序键 = 有实测方向的量,
     这条纪律不许破)。
  3. **信息卡与考卷同构**(第〇原则,规格对齐
     `archive/交接与日志/交接_考官Agent_盲选训练规格_20260726.md` §三):K 线 + RS 线
     (相对大盘,60 日)+ 行业分歧线(60 日,行业真名)+ 快照数值 + 红黄牌
     + 温和带标注(当日 2-3%)+ 消息面/龙虎榜摘要(数据可得性由施工侦察,
     不可得如实缺省,禁止硬凑);
  4. 输出 20 只交用户终选;候选卡语义文案 = "过完安检、值得注意力"。
- 执行提示(exec_hint)产品化随本需求一并做:强票市价/小 δ 提示、挂低单

## 需求 9(2026-07-29 晚,**系统线会话用户口述定案**,非策略线交办):候选参考件三件套 —— LLM 参谋化

- **来源标注**:本条不是策略线交付,是**用户在系统线会话里当面口述并拍板**的产品
  需求(2026-07-29 晚,v1.5.0 立项同一会话)。规格权威 = 本节 + `PROJECT_PLAN.md`
  §五 v1.5.0 施工图;与需求 8 的关系 = **在需求 8 的正选漏斗之上换掉候选卡的
  "四件套"输出层**,漏斗四步与排序键三级**一字不动**。

- **第〇原则(用户原话精神,必须同时写进 PROJECT_PLAN §二)**:**LLM 的作用永远是
  参考,硬条款才是纪律。** 参考件**不触发任何机器动作**;纪律(−5% 止损 / 回落止盈
  8% / 时间退出 / 仓位 / 熔断)只住章程,只由 `strategy_versions` 现役行说了算。

- **候选卡四件套 → 三件套(全部 LLM 生成,卡面明示"参考")**:
  1. **买入参考区间** —— LLM 基于 60 日 K 线 + 昨日收盘等 EOD 数据推"若明日买入,
     适合的价格区间"。**不搞复杂机制**(用户原话),**唯一底线 = 生成的数字必须落在
     明日涨跌停价区间内,出界不显示**(防幻觉,一行夹逼)。具体止损价数字(0.95×)
     并进这一行**一笔带过**。
  2. **离场参考区间** —— LLM 判断本轮上涨的**压力位区间**("到这个区间可以考虑走
     不走")。**明示参考、非止盈线**;回落止盈 8% 纪律**一字不动**,仍是被动兜底。
     用户框架:**参考在上、纪律兜底**——"每只票都等回落 8% 才走,损失多少个 8%"。
     **止损独立条目删除**(−5% 是章程常量,不再每卡说教)。
  3. **明早证伪剧本** —— 面向 **T−1 晚阅读**的开盘行动指引,**带分支**(竞价掉进
     危险区 → 放弃;温和低开量能正常 → 观望;符合预期 → 按区间执行),LLM 按每票
     生成;**生成时把哨兵的结构化阈值喂给 LLM**,使剧本与盘中自动警报**同频不打架**。
     哨兵的机械结构化证伪条款**保留在水下**(它仍是盘中自动警报的唯一判据源,单一
     事实源不动),**卡面不再展示原始条款**。
  4. **LLM 其他评语保持现状**(自由叙述审判文字不变)。

- **风险否决**:LLM 审判认为该票风险大 → **三件套全无,只出不买理由**;**票与信息卡
  保留**(机器不禁、人可复核)。
- **20 只全覆盖**:每票**或出三件套、或出不买理由**(现只审 top 10 → **翻倍**)。
- **今日计划拆两块**:**持仓股** / **候选列表(每日 20 只)**。
- **语义红线更新**:参考件必须标注**"参考、非指令"**,终选权在用户;原红线
  "排序 = 注意力优先级,不是收益预测"**不变**。

- **配套(用户同批拍板,全部纳入 v1.5.0)**:LLM 预算重排(20 只全覆盖 + 三件套生成
  的 16:35 时间账)、**参考件落库**(买点 / 离场区间 / 剧本存表,将来与实际走势/成交
  对拍 = **LLM 参谋成绩单**,给 P3-11 归因供维度)、老模板退役清理(`candidates.py`
  的 entry_plan / 止损说教 / 目标模板做代码减法,**注意哨兵仍消费结构化证伪、别错删**)。
