# Neckline 4.0.0 Build117（B117）执行记录：MCP 登录后跳回客户端

2026-10-19（周一）上午。B116 上线后用户在 Claude 重新添加连接器，仍显示「连接校验失败」。线上基线 `v4.0.0-b116`（`ccc597b`），发布 `v4.0.0-b117`（`d4a630f`）。App、依赖、配置都没变。

## 1. 根因与修复

- 日志：两次尝试都是 `POST /login` 303（口令正确、授权码已签发），2–6 秒后又一次 `POST /login` 403，且没有任何 `/token` 请求。即登录已成功，但浏览器没有跳回 Claude 的回调。
- 根因：MCP 网关的 CSP 是 `form-action 'self'`。Chrome 把 form-action 也用在表单提交后的重定向上，303 跳到 `https://claude.ai/api/mcp/auth_callback` 被拦下，页面停在原处；用户再点一次，请求已被用掉，报 403。B116 修好 Origin 后这个问题才暴露。
- 修复：`/login` 的 CSP `form-action` 只多放行 OAuth 白名单认可的三个回调域名（`chatgpt.com`、`claude.ai`、`claude.com`），其他 MCP 路由不变。登录请求已用过或已过期时单独提示（400），不再和校验失败（403）混用。换令牌与续期时客户端可以不带 `resource`（授权码、刷新令牌签发时已绑定本服务，换令牌时再核对），带错仍拒绝，避免客户端续期不带 `resource` 时一小时后掉线。
