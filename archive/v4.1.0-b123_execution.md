# 4.1.0 B123 执行记录：KX 名单 schema 2 适配

快修。用户 10/24 转来 KX 的变更：KX 0.2.0 build 7 于 10/23 上线；从 10/26 08:00 起，名单由 DeepSeek 每个交易日 08:00 更新，每天 10～50 只，格式为 schema 2，带题材，不再有申万行业。Neckline 原来的 `parse_pool` 要求每行都有非空的 `sw_l2`，会拒收 schema 2，看板就会停在旧名单上。对外版本仍是 4.1.0，后端 build 递增到 B123；App 代码不变。

## 1. 改动（commit `f3abd83`，备用 Claude builder 施工）

- `kx/source.py`：按 `pool.schema_version` 分两种格式解析，只认整数 1 和 2，其他值一律拒收。
  - schema 1：要求 `sw_l2` 非空。
  - schema 2：要求 `theme` 非空且不超过 80 字，`first_seen` 是真实日期，`buyable` 是布尔值。
  - 两种格式都不读 `heat_day`：KX 是在读取时现算这个值的，而名单不变时 Neckline 不会重读。
- 库结构升到 **v3**：`kx_pool` 新增 `theme`、`first_seen`、`buyable` 三列。
  - `init_schema` 在一个事务里把 v1、v2 原地升到 v3；补列之前先查列是否已存在，所以降级后再升级不会报错。
  - release.py 的 `ADDITIVE_DOWNGRADES = {(2,1),(3,2),(3,1)}`，其余逻辑不变。
- 看板：每行新增 `theme`、`firstSeen`、`heatDay`、`buyable`；schema 2 时 `industry` 为 null；pool 元数据新增 `schemaVersion`。
  - `heatDay` 由 Neckline 按交易日历计算：从 `first_seen` 到行情交易日（`session.tradeDate`）的交易日数，两头都算。
- 示例响应（fixture）：重新生成了 sample、degraded，并同步到 App；新增 `kx_board_schema2.json`。
- `RELEASE_SET = v4.1.0-b123`。
