## 2. 已核实的事实（10/27）

- **DeepSeek 联网**：Chat Completions 的 `tools` 只支持 `function`，没有内置搜索。官方另有两条路：
  - 独立的 Search API：`POST https://api.deepseek.com/v1/tools/search`，参数 `query`（≤128 字，支持 `site:`、`after:`、`before:` 等）、`count`（1–50）、`need_content`。结果带 `title`、`url`、`summary`、`site_name`、`date`、`authority`。每千次成功请求 0.75 美元，100 QPS。同一账户还有 Fetch API（`/v1/tools/fetch`，取网页正文）。
  - Responses API（`POST /responses`）的 `web_search` 工具：只支持 `deepseek-v4-pro`。由模型决定搜几次，文档没写上限和计费。
  - 来源：api-docs.deepseek.com 的 `guides/search`、`api/create-chat-completion`、`api/create-response`、`news/news261017`。现役模型名 `deepseek-flash`（V4.1-Flash-1017）、`deepseek-v4-pro`。
- **巨潮翻页**：接口默认按公告时间倒序（`sortName=time`、`sortType=desc` 结果相同）。`seDate` 只能按整天给，所以 08:00 那次采集（从前一晚 19:00 起）也要把前一整天翻完。10/26 到 10/27 两天共 1,705 条，约 57 页，超过配置的 40 页上限。三季报类公告的时间戳是披露日的 00:00，只到日期，见 §4.2。
- **中创环保（300056）**：10/20 的漏收是采集覆盖缺口：三个来源都没有这条公告，金十只挑部分公告做快讯。B122 加了巨潮公告来源，端到端测试已证明这条会在 10/20 窗口里匹配到 300056。结论：已在 B122 处理，本次不再改。v5 下股东协议转让照常进候选。
- **第一周误收的类型**（10/22 晨报实例）：
  - 广和通「重大资产购买完成过户」被归为收购投资；
  - 工大科雅「协议转让完成过户」被归为股份转让；
  - 永福股份「诉讼进展暨收到款项」被归为一次性收益。
  - 7 例都是种类判错，规则本身没问题。
- **基线成本**（10/22 线上一期）：336 条点名消息、163 家，分类调用 23 次，117.5 秒，输入 22.6 万、输出 9.9 万 token，24 条入选。
- **运行约束**：
  - `neckline-v4-morning.service` 的 `TimeoutStartSec=30min`、`MemoryMax=900M`；
  - `requirements.txt` 里没有 PDF 库，新增依赖要在切换前另装到 NB 的 venv；
  - App 122 的 `MorningEntry.importance` 是必填字段，去掉后旧版 App 读不了新晨报。

## 4. 设计

### 4.1 一级初筛（`screening-v3`，分类合同 `screening-classify-v4`）

- **删除重要程度**：分类输出、`Event`、`select` 的排序与 `importanceMinimum`、晨报条目、`others`、网页、App、MCP 全部去掉。v4 旧晨报库里存的内容不改，API、MCP、网页输出时把重要程度剔掉。
- **按 v2 执行到位**：只改提示词和种类说明，选择规则的结构不变。
  - 新增不收的种类「交易进展」：协议转让或资产交易完成过户、补充协议、实施情况报告、诉讼进展。
  - 收紧以下种类的说明：
    - 控制权变更只算首次筹划，解除一致行动不算；
    - 一次性收益不含诉讼回款；
    - 股份转让只算首次签约或征集受让方，完成过户不算。
  - 7 个误收例子做成分类回归样本。
- **「由用户判断」类**（出售资产、股份转让、大额采购）：照常进候选，方向不限，由评估层判断。
- **候选**：每家公司一条，带上这家公司本期所有入选事件，排序不再看重要程度。
- **只有标题的定期报告**（D3）：初筛前先由代码从公告 PDF 读出主要会计数据，附在这条消息正文后面，让初筛能按 v2「同比增长才收」判断。读不出就如实写「未能读出数字」，照常交给模型。

### 4.2 巨潮翻页

- 按时间倒序翻页，翻到早于本次起点的公告就停，判为取全。
- 翻页上限保留，只防异常；具体数值按三季报高峰实测定。
- 回归测试：多页、跨天、翻页中途有新公告插入（只会重复，不会漏）、上限触发。
- 顺带核实 00:00 时间戳的含义：是前一晚发布、标成次日的公告，还是当天盘中发布、只标到日期。如果是后者，08:00 之后才采到的会落进已出报的窗口，要如实记为精度 `date`，交用户定怎么收。

### 4.3 公告 PDF 读取（新模块，纯代码）

- **用途**：从巨潮下载候选事件涉及的公告 PDF，提取正文、目录（标题层级）和开头。
- **结构化读数**：
  - 定期报告的「主要会计数据和财务指标」：本报告期与年初至报告期末的营收、归母净利、扣非净利及各自同比；
  - 非经常性损益合计；
  - 业绩预告和快报的区间与同比。
- **读不出时**：标「未能读出」，原文照常给模型。
- **PDF 库**：B0 用 10/22–10/27 的真实公告（三季报、预告、快报、收购、协议转让）比较 pypdf、pdfplumber、PyMuPDF，看文字和表格读得准不准、内存和速度。只读前几页，单份文件限大小，不能超出服务的 900M 内存上限。
- **缓存**：下载结果按公告编号缓存在运行目录，可复用，不进库。

### 4.4 二级数据准备（纯代码，不调模型，不剔除任何条目）

每条候选一个数据包，先整包落库，再调评估。续跑时用库里的包，保证请求不变、回执命中、不重复计费。

| 材料 | 来源与规则 |
|---|---|
| 原文 | 事件编号里有巨潮公告就用公告 PDF，没有就用新闻原文 |
| 同一事件的媒体报道 | 本期这家公司被归入同一事件的其他消息（已采到的，不外呼） |
| 公司快照 | TuShare `income`、`fina_indicator` 取最近一期营收、归母净利、扣非净利；`daily_basic` 取总市值、市盈率 TTM。财务数据只用公告日早于窗口起点的期次，防止看到未来数据 |
| 价格背景 | 复用 `market/tushare_daily`：此前 20 个交易日涨跌、相对 5/10/20 日均线的位置、日均成交额，截至上个交易日收盘 |
| 业绩类另算 | 同比和扣非来自 PDF 或预告、快报；单季环比按累计数相减（例如 Q3 单季对 H1 减 Q1，历史期取 TuShare）；一次性收益取非经常性损益合计；基数是上年同期金额。缺哪项就写缺，不估 |
| 长文 | 依次用：已采到的同一事件媒体报道；原文目录和开头；联网搜索（暂缓，见 D4）。截断字数用 10/22–10/27 的真实候选公告实测，写进配置并留下实测依据 |
| 联网（D4，暂缓） | 数据包留出 `search` 位置，本次 `evaluation.search` 为 null（不联网）。等工程做好再定接法，候选方案是代码对每条候选调一次 Search API，结果写进数据包 |

- **行情数据**：TuShare 行情接口只在 NB 上调用，本机绝不直连。数据源做成接口：线上直取，回放读 NB 导出的快照文件，两条路共用同一套按日期截取的逻辑。
- **外呼回执**：Search 是付费外呼，和模型调用一样落回执，相同请求不重复计费；结果不明的不自动重试。

### 4.5 三级评估（合同 `evaluation-v1`）

- 每条候选调用一次 DeepSeek（`deepseek-flash`，思考开），按 K10.md 第五节回答四个问题。
- **只给原则、不给数字门槛**：小基数、一次性收益、环比下降、透支都交模型判断。方向不明的重大消息，参考材料里媒体、券商和公司的说法。给用户的建议只写定性表述（如「明显高开不追」），不出现建议性的数字；新闻、公告、财报里的客观数字照常写。
- **输出 JSON**：
  - `title`：一句话标题，不超过 30 字；
  - `verdict`：推 或 不推；
  - `conclusion`：一两句；
  - `questions`：
    - `value {pass, text}`：①利好值多少；
    - `priced {pass, text}`：②市场已反映多少，pass=false 表示透支；
    - `money {text}`：③资金为什么买、为什么不买；
    - `price {text}`：④当前价格划不划算；
  - `risk`：一行；
  - `views[]`：每条 `{by: 媒体|券商|公司, name, text, ref}`。
- **代码校验**：
  - **一票否决**：①或②不过关，`verdict` 就只能是「不推」；自相矛盾的输出按无效处理，记为缺口，不推；
  - **观点来源**：`views.ref` 必须指向数据包里真实存在的消息、公告或搜索结果，指不到就删掉这条观点并计数，坏引用绝不变成事实；
  - 字段缺失或取值不合法同样记为缺口。
- **并发与收口时刻**：并发数写进配置。到收口时刻（D5）还没评完的条目记为缺口，名单照常交付。
- **存储**：推与不推的评估、连同数据包，一律存进新表 `evaluations`。不推的不显示，供复盘用。
