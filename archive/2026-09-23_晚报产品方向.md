# 21:00晚报：回到消息筛选与公司关联

2026-09-23。用户确认保存本轮讨论链路，作为后续修改方向，并补充“严格筛选、自由表达、允许零推荐”。本记录保存产品共识及其依据；当前仅讨论与记录，未进入新的正式工作流，未授权改代码、重跑报告、修改定时或发布。工程现状仍见根目录 `PROJECT_PLAN.md`。

## 用户要解决的问题

每天A股相关消息过多，用户没有时间和注意力逐条阅读。系统替用户从大量资讯中筛出值得注意的消息，深读后找到有客观联系或合理传导逻辑的股票池内公司，把公司、原始消息和关联理由一起交给用户。

用户自行决定如何理解、是否买入；最终上涨或下跌不单独决定这次筛选有没有完成职责。有依据且讲得通的推断即使判断失误，也不同于没有关联理由的推荐。系统的任务不以承诺短期上涨或完成报告数量为准。

两个核心价值：

1. 从海量标题里发现真正有意思、值得深入阅读的消息。
2. 深读后发现确有价值联系的池内公司，包括不显眼但讲得通的题材传导。

## 已确认原则

- **严格筛选，自由表达。** 消息价值与公司关联的入选要求应严格；让Agent自然表达理解和推理，不将分析变成大量强制字段、固定段落、必填话术或模板作业。此前讨论中的“发生了什么、为什么有关、哪些未知”是要讲清的内容，不是要求每次逐栏填空。
- **消息力度本身也要过关。** 有一条新消息、能找到相关公司，不自动等于值得推荐。无关紧要的变动、泛泛表态和牵强线索不应为占名额进入晚报。“力度”不擅自换算为金额、涨幅、评分、名次或其他未经用户决定的阈值。
- **“变化”是重要发现线索。** 用户重视非日常重复、与公司经营或重要项目有关、可能带来后续变化的事情。标题值得深读与读完值得推荐是两次不同判断；深读后发现力度不足而放弃，是正常完成筛选，不是前一步失败。
- **消息价值不由篇幅决定。** 短快讯可以包含重要变化，长文也可能只是旧事分析或背景堆叠。深读指理解原始内容、阶段与影响，需要时追查出处，不意味着必须寻找或生成长文。
- **关联可以直接，也可以经过推理。** 允许业务影响、供需、技术路线、替代关系、题材传导等合理路径，不要求已签订单或官方确认；必须把支撑事实与推断讲清楚，不能只靠行业、产品或概念相似就推荐。
- **允许放弃一整条消息。** 消息即使有价值，若找不到有价值关联的池内公司，也可以结束这条线索，不强找替代标的。
- **30家是注意力上限。** 合适多少就交付多少，零家公司也是用户明确接受的正常筛选结果。不能为填满名额降低消息力度或关联要求；执行失败、来源缺失与正常零推荐仍须如实区分。
- **理由随推荐交付。** 在用户第一次选择前，就展示关联解释并提供可读的原始消息。不能把关键理由留到用户选择后才补，也不能把模型摘要当作原件。
- **先判断值得推荐，再安排阅读顺序。** 同组相对最接近主题，不自动获得推荐资格；主推、备选等称呼不能使没有独立理由的公司成为正式推荐。
- **时效要解释。** 区分报道时间与事情发生、首次公开、实质进展的时间。旧事项若仍值得看，须说明当前价值；重新转载本身不等于新的机会。不擅自新增固定消息年龄门槛。

## 已认可的晚报链路

**21:00收集消息 → 标题初筛 → 深读原文、理解消息价值与增量 → 在固定池里寻找可能关联的公司 → 结合资料判断传导关系、必要时补查 → 保留值得交付的消息与公司组合 → 同公司合并、安排阅读顺序、最多30家 → 原始消息与关联解释随晚报交给用户。**

- 标题阶段保留值得追查但尚不确定的线索；不因标题未直接出现池内公司就机械丢弃。初筛留下不表示最终推荐。
- 正文或关系调查表明消息力度不足、没有有价值的池内关联时，正常结束相应线索。只有必要缺口才继续读资料或搜索。
- 已知事实、关系推理、支撑材料和未知项应在后续整理中得到保留；表达可以是自然文章，不要求为每项另设固定栏位。
- 同公司多条有效消息一起考虑；一条牵强消息不因与另一条有效消息绑定而自动变成有效催化。
- 上述顺序是业务判断顺序，不等于每一步都要新建Agent、模型调用或工程关卡。优先复用已跑通的采集、阅读、搜索、证据保存与交付能力。
