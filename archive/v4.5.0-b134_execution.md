## 1. 背景与用户裁定（2026-11-22）

- 原计划的 K10 4.5.0 草案已确认永久放弃，工作区于启动前重置回 `main`（`da41042`），并清理本机残留临时文件；本次正式以 **Neckline 4.5.0 (B134)** 交付 **KX V4** 升级。
- `KXMarketTool` V4（`0.5.0` build 13，`schema_version: 5`）已于 2026-11-22 在 HZ 上线，继续复用既有只读接口 `/kx/read/<访问码>?format=json`（凭据仍在 NB `/opt/neckline/.env` 的 `KX_READ_KEY`，KX 零回调）。
- 用户确认的四项关键决定：
  1. **面板与交互**：严格对齐已确认 HTML 样图的「Neckline 看板」标签页（不搬入「一周验证报告」），不显示买卖建议、不记录持仓与收益；情绪派系胶囊与搜索栏均为**直接过滤**；龙虎榜买卖前五明细在 **macOS 默认展开（可折叠）**、**iOS 默认折叠（点摘要条展开）**。
  2. **盘中彻底静默**：删除 V3 的盘中高频轮询、集合竞价标签与五档封单逻辑，白天只安静展示最近一次 20:00 盘后整理快照（保留手动刷新）。
  3. **20:00 盘后仅推 iPhone**：交易日 `20:02～20:45`（北京时间）由 NB `neckline-v4-kx-watch.timer` 触发轮询，检测到当日确认更新即推一条轻量 `NKDIGEST`，上游失败/协议不兼容/超时未更新推 `NKIMPORTANT`；Mac 永不推送；iOS 点 KX 推送自动关闭旧个股详情、切到 KX Tab 并刷新。
  4. **协议契约**：严格校验 `schema_version == 5`，见未知 schema 明确报错拒绝硬解；退役所有 V3 代码与夹具，不留兼容层。

## 2. 变更范围

### 2.1 后端（`Backend/`）

- **库结构 v8 → v9**（`neckline/morning/db.py`）：
  - 新增 `kx_board_cache`、`kx_watch_state`、`kx_push_log` 三张表（只加表，降级到 v8 时保留不删）。
  - 新增 `write_immediate()`（`BEGIN IMMEDIATE` 事务上下文），用于 KX 快照单调落库、超时状态原子校验与推送占位。
  - `_kx_version_rank` 依次比较看板版本（`as_of` / `generated_at` / `board_version`）与回执新鲜度（非空 `refresh` / `refresh.date` / `refresh.finished_at` / `confirmed` / `checked_at`），保证下一交易日沿用旧板的 `failed` 回执胜过上一交易日的 `updated`，同时同版本 `refresh=None` 绝不擦除有效回执。
- **KX V4 投影、缓存与接口**（`neckline/kx/{source,project,board,api}.py`）：
  - 严格校验 `schema_version == 5`；白名单字段落库（丢弃 `change_reason` 等无关自由文本），全面脱敏上游 URL 与访问码；所有可空指标（`y_open_mean`、`ma10`、`lbc`、`lhb` 等）保持 `null` 不兜底为 0。
  - 退役 `neckline/kx/days.py` 与全部 V3 夹具；新增真实脱敏 V4 样本与 5 份跨端夹具（`kx_board_v4.json`、`kx_board_v4_partial.json`、`kx_board_v4_stale.json`、`kx_board_v4_elim.json`、`kx_board_unavailable.json`）。
  - `/api/v4/kx/board` 支持 `?refresh=1` 手动刷新（10 秒防抖，含空缓存失败场景），普通访问优先复用 SQLite 持久快照（10 分钟静默窗口，跨进程重启有效）。
- **20:00 盘后轮询与仅推 iPhone**（`neckline/kx/{watch,cli}.py`、`neckline/push/apns.py`、`deploy/neckline-v4-kx-watch.{service,timer}`）：
  - 完成判定严格核对 `as_of == 当日`、`refresh.result == "updated"`、`refresh.as_of == 当日` 与 `refresh.pool_version == version`。
  - `PushResult.dispatched` 区分本地未外呼故障（缺凭据/密钥不可读/缺 `h2`）与已外呼传输异常（`status=0` 保留 `sending` 不重发）；4xx 永久拒绝记 `permanent:` 跨重启不重发且保留失败计数；`429/500/502/503` 在 20:45 前冻结事件仅重试失败设备；逐设备外呼前核对 20:45 截止线。
  - `neckline-v4-kx-watch.service` 采用最小权限：仅加载 `/opt/neckline/.env` 并显式传 `--db /opt/neckline/data/v4.db`，不读取 `/etc/neckline/v4.env`。
- **发布脚本**（`scripts/release.py`）：
  - 支持 schema `9 ↔ 8..1` 升降级白名单。
  - 目标 `schema >= 9` 时预检强制核验 `neckline-v4-kx-watch.timer` 与 `.service` 均为 `LoadState=loaded`；先通过新版本 `health` 后再 `enable --now` 并正向校验 `active + enabled`；回退到 `schema < 9` 时 `disable --now` 并校验停用；停服与回滚等待 `KX_WATCH_JOB` 离开 `active/activating/reloading/deactivating`。

## 5. NB 部署与回退步骤（待用户放行后执行）

### 5.1 首次升级前置（B133 → B134 必须先装新 systemd 单元）

1. 将本次提交打包：`python Backend/scripts/release.py build --release v4.5.0-b134 --commit <sha> --out <暂存目录>`，上传至 NB `/opt/neckline/releases/v4.5.0-b134/`。
2. 在 NB 以 root 安装两份新单元并重载（不要手动提前启动，交给 `release.py` 在 health 通过后自动 `enable --now`）：
   - `/etc/systemd/system/neckline-v4-kx-watch.service`（`0644 root:root`）
   - `/etc/systemd/system/neckline-v4-kx-watch.timer`（`0644 root:root`）
   - `systemctl daemon-reload`
3. 预检：`sudo python3 /opt/neckline/releases/v4.5.0-b134/release.py switch --release v4.5.0-b134 --previous v4.4.1-b133 --check-only`（确认 `preflight: ok`、`schemaBefore: 8`、`schemaTarget: 9`、`schemaAction: upgrade`）。
4. 正式切换：`sudo python3 /opt/neckline/releases/v4.5.0-b134/release.py switch --release v4.5.0-b134 --previous v4.4.1-b133`。
5. 上线后核对：
   - `curl -s http://127.0.0.1:8002/api/v4/health` 确认 `releaseSet == "v4.5.0-b134"`、`db == "ready"`、`kxBoard == true`；
   - `systemctl is-active neckline-v4-kx-watch.timer && systemctl is-enabled neckline-v4-kx-watch.timer` 均为 `active` / `enabled`；
   - 带鉴权请求 `/api/v4/kx/board` 确认返回 `schemaVersion: 5` 且首份快照落库；
   - 本地覆盖安装 macOS 4.5.0 (134) `.app`（用 `ditto`），用户以 Xcode 安装 iPhone 4.5.0 (134)。

### 5.2 回退步骤（B134 → B133）

使用 **B134 的 `release.py`** 执行回退：
`sudo python3 /opt/neckline/releases/v4.5.0-b134/release.py switch --release v4.4.1-b133 --previous v4.5.0-b134`
脚本会自动停服并等待 `neckline-v4-kx-watch.service` 退出、将库结构由 v9 降回 v8（保留新建三表不覆盖业务数据）、还原 B133 代码与 wheel、执行 `systemctl disable --now neckline-v4-kx-watch.timer` 并核对 B133 `health`。
