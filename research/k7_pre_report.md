## §0 预注册:总纲与共享设定

### 0.1 审计对象 = 注意力价值,不是买入期望(与 K1–K4 战役的根本区别)

K7 = 首个为 V2 篮子引擎原生设计的策略包(声明式配置,插槽只管 ①驱动种子生成规则
与 ③Tier 机械分维度/权重)。本战役审计 Tier 五维中两个维度的**方向与定义**:

- H10 → `leader_clarity`(龙头结构清晰度):簇内头名是否真的比后排更值得占注意力位;
- H11 → `driver_freshness`(驱动新鲜度):题材生命周期阶段化后,哪个阶段的成员更值得看。

**判决的量是「关注价值」**:后续窗口的机会量(MFE、涨停触达)、风险量(MAE、跌停暴露)、
相对延续(close 口径,不受可买性截断)。**不是**「买入期望」(组合级 PF/净收益——那是
K1–K3 已判死的域)。结论只进 Tier 排序与 seeds 关注池定义,**永不变成买点**;语义红线
(排序=注意力优先级,非收益预测)全程适用。

**雷区合规(新证据声明)**:
- H10 紧邻 K2 坟(主线识别器「板块层无次日领先性」)。新证据 = K2 测的是**板块层**
  (强板块次日是否继续强),本假设测**簇内成员角色层**(同一热簇内,龙头 vs 后排的
  相对延续)——K2 从未测过该维度;且判据量从买入期望换成注意力价值。
- H11 紧邻 K2 坟 + H6(题材持续天数票层单调减分)。新证据 = H6 测的是 persist_days
  单调性(线性标量),本假设测**阶段化结构定义**(启动/发酵/过热/分歧回调/退潮五态,
  含梯队断板与涨停家数信息)——特别是「分歧回调」态(二池「后发制人」命题)在 H6 的
  标量框架里根本不存在。
- 若条件化/角色化后仍无区分 → 坟界扩大,如实记录,维度建议降权或删除。

### 0.3 判分口径(全战役统一,新特征只进研究缓存)

- **close 口径前向**(注意力主口径,不受可买性截断):
  `fwd_c_ret_d = close(T+d)/close(T) − 1`(per ts_code,d ∈ {1,3})。
- **MFE/MAE**(可交易子集,`fwd_buyable` 过滤,锚 T+1 开盘):
  `MFE_3 = max(high[T+1..T+3]) / fwd_entry_open − 1`;
  `MAE_3 = min(low[T+1..T+3]) / fwd_entry_open − 1`。
- **机会密度**:`P(MFE_3 ≥ +5%)`、`P(持有3日内任一日收盘涨停)`(fwd_lu_hold3)。
- **左尾**:`fwd_ld_next` / `fwd_ld_hold3`(次日/3 日内收盘跌停率,k4p_common 既有)。
- 参考件:既有 open 口径 `hold_table`(净收益/PF)照常附表,**只作透明参考,不进判决**。

### 0.4 判决规则(硬门,预注册后不改)

1. **样本内定参、样本外验证**:主判在样本内选定义档,样本外方向一致才算过。
2. **2026 方向一致性硬门**(生存门禁的注意力版):样本内结论在 2026 分段**反向**
   → 该维度/该池不进 K7 包(登记待观察,不删档)。
3. 敏感性 ±1 格:结论只在单一参数格成立 = 过拟合信号,判不过。
4. 诚实否定是合格交付;n 薄(全期事件 < 500)如实标注、降置信。

## §1 H10 · 龙头结构:簇内头名 vs 后排跟风(预注册定义)

**命题**(小热巴/二池共同骨架):热簇内的高辨识度核心(龙头)比后排跟风更值得
占注意力位——延续更强、机会更大,或至少风险结构更优。

**定义**:
- **簇** = `(trade_date, industry)`,当日域内涨停家数 ≥ 3(涨停含一字,簇身份识别
  需要完整梯队;敏感性:阈值 {3, 5})。
- **簇成员** = 该行业当日涨停的域内票(base_expr,不剔一字——一字恰恰常是龙头)。
- **龙头三定义**(样本内选主,tie-break 定死保证可复现:指标降序 → amount 降序 →
  ts_code 升序):
  - L1 连板高度:`consec_limit_up_days` 簇内最大;
  - L2 成交额:当日 `amount` 簇内最大;
  - L3 RS20:`ret_20d` 簇内最大。
- **后排** = 簇内其余成员。
- **配对量**(主判):per 簇日,`龙头 fwd_c_ret_3 − 簇内其余成员 fwd_c_ret_3 中位数`。
  报 mean / median / 正差占比 / n 簇。次判:两组各自 MFE/MAE/涨停触达/跌停暴露
  (可交易子集单列,并如实报两组 fwd_buyable 率——龙头更常一字买不进,这本身是结论)。

**判决**:三定义至少一个「样本内配对差 > 0 且样本外同向且 2026 同向」→ `leader_clarity`
方向确认,采最稳者写进 K7 建议;全不过 → 维度否决,建议 Tier 权重中该维清零。

## §2 H11 · 题材生命周期阶段(预注册定义)

**命题**(二池「后发制人」+ 小热巴「题材轮动预判」):题材有阶段结构;「分歧回调」
段的成员(尤其其中已证明强势者)比「启动/发酵」段追入更值得关注;「过热/退潮」段
应降权——若成立,`driver_freshness` 不应是 persist_days 的单调函数,而是阶段函数。

**行业日频状态定义**(强度日/persist 复用 H6:行业当日成员 ret_1d 中位数 ∈ 全行业
top 20%〔quantile 0.80,主判;敏感性 0.85/0.70〕,成员数 ≥5;persist = 连续强度日数):
- 另算两个梯队量:`lu_cnt` = 行业当日域内涨停家数;`fail_rate` = 昨日该行业涨停成员
  今日未涨停占比(断板率,昨日涨停家数 ≥2 才算,否则 null)。
- **五态**(per 行业日,互斥,从上往下第一个命中):
  1. **启动**:强度日 且 persist = 1;
  2. **发酵**:强度日 且 persist ∈ [2,3];
  3. **过热**:强度日 且 persist ≥ 4;
  4. **分歧回调**:非强度日 且 过去 2 日内有强度日 且 `lu_cnt ≥ 1`;
  5. **退潮**:非强度日 且 过去 5 日内有强度日 且 `lu_cnt = 0`;
  6. 其余 = 无题材态(对照)。

**事件** = 各态的域内成员股(base_expr + 非一字事件日 + industry 非空)。

**统计**:
- 成员层:各态 fwd_c_ret_1/3、MFE_3/MAE_3、涨停触达、跌停暴露(样本内/外/2026);
- 板块层:各态行业中位数前向 1/3 日;
- **特别对拍(二池命题直接检验)**:「分歧回调态 × 强势资格成员」(limitup_count_20d
  ≥ 2 或 ret_20d ≥ 0.25)vs「启动/发酵态全体成员」——前者机会密度更高且左尾不劣
  = 后发制人成立。

**判决**:五态间注意力量存在有序区分且 2026 同向 → `driver_freshness` 采阶段化定义
(具体打分序按数据写);无区分 → 维持 H6 persist_days 原判,阶段化不进包。

## §4 判决汇总与 K7 建议

| 假设 | 判决 | 依据 |
|---|---|---|
| **H10 龙头结构** | **过——`leader_clarity` 方向确认,主定义 = 簇内 RS20 头名度** | L3 十二格均值全正、样本外/2026 增强、双簇阈稳;L2 否决;L1 不作头名主定义、降级为「双尾标注」(涨停触达 1.5× 同时次日跌停 3×) |
| **H11 阶段化** | **过——`driver_freshness` 采阶段函数,但注记 regime 敏感** | 发酵态样本外/2026 全场最优(三敏感格一致);过热双尾最重(A2 再确认);**排序随 regime 翻转(样本内启动>发酵),权重低配 + 评价引擎前向校准** |
| 后发制人对拍 | 部分成立,只进标注 | 「分歧回调×强势」机会密度全场最高但次日跌停 1.5× 于同强势追入,是风险结构切换不是风险消除 |

**给 K7 包 / 系统线 ⑥ 施工的三条具体建议(待用户过堂)**:
1. `leader_clarity` 机械分主输入 = 簇内 RS 头名度(`leader_structure_daily` 的 RS 排名
   列正好是它);连板高度不进头名主定义,改作「双尾」情报标注(篮子卡风险节)。
2. `driver_freshness` 不用 persist_days 单调升序,改五态打分;**当前 regime 建议序:
   发酵 > 启动 > 分歧回调 > 无题材/退潮 > 过热**;此维权重低配(regime 敏感),交评价
   引擎按 pack_version 前向校准。
3. K4-pack 的 `intel_rank_priority` 用 `industry_persist_days` 升序(第 1 天最新鲜)
   ——在 2025-26 regime 下已非最优(2-3 天带更好);**B3 黄牌(题材 2-3 天减分)与本
   结论在当前 regime 冲突**,是否调整属红黄牌语义变更,单列给用户拍板,不随包顺手改。
