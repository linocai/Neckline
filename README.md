## 消息与报告

- 采集独立于研究：自然日北京时间08:00、20:00，包含周末和节假日；金十与TuShare分别记录覆盖、失败和水位。采集不调用研究LLM、不产生推荐。
- 金十仅接快讯列表、文章目录、文章正文、快讯搜索和文章搜索。无标题短快讯直接进入理解，合集中的独立事项可读取；金十报道和真正公告原件明确区分。
- 晚报在对应交易日前一自然日21:00开始；晨报交易日08:30开始、09:20前提供可读结果。报告读取冻结的已存资料，未采到的尾段如实披露，不例行补采。
- 晚报最多30家，允许零推荐；严格判断消息价值和真实公司关联，允许有依据的间接传导，由Agent自然解释，不增加强制评分表。
- 晨报并行复核昨晚全部公司及原理由的隔夜变化，同时发现隔夜新机会。历史背景或反证按问题读取，不能扩大新发现业务时间窗。
- 已存消息、原文、公司资料和核验足够时直接判断；金十正文通过金十取得。只有关键缺口可能改变判断时，才针对性调用金十或Tavily。不凑来源、不机械搜索；空结果与来源缺失不是安全证明。
- 同一事件跨来源合并研究并保留原件，转载数量不是独立证据；旧消息重采不变成新消息，真实新进展不误删。发布时间、采集时间与可确认事件时间分开显示。

正式推荐使用固定1,089公司池及D1/D2观察窗口；后续查看、重复推荐或用户操作不重开旧窗口。未排序材料只读，不是正式推荐或D1/D2样本。资料来源与缺口必须真实，失败、处理中、零推荐分别呈现。

## 配置与运维

代码在`App/`和`Backend/`；服务入口`https://nk.linotsai.top`，API前缀`/api/v1/`。除健康接口外均需Bearer鉴权，凭据不得进入Git或日志。

新起点数据库只能通过`Backend/`中的以下入口建立：

```bash
.venv/bin/python -m neckline.k10.cli initialize-fresh --db <明确的新文件路径>
```

命令只创建不存在的新空库，不接收旧库、不自动登记策略、不打开开关。只读API不会进行迁移。随后顺序为：重新登记已批准固定资料 → 显式登记策略/执行/采集配置 → 绑定策略 → 从官方重新取得交易日历 → 校验无scan时的实际API配置响应。

固定资料源为研究侧`research/K10-v2初始股票池_20260909.json`与`artifacts/output/k10-company-profiles-v2-20260909/`。仅离线显式导入，核验固定hash与1,089家公司集合，保留`local_draft_awaiting_user`来源状态；运行期只读取新库。

本版生产使用策略`k10-v2-production@1`、执行`k10-v2-execution-production@1`和采集`k10-collection-production@1`，策略快照`k10-v2-20260909`。修订号由新库登记返回，不能照抄旧版本revision2。参数未配置时不得使用默认值。

`/opt/neckline/.env`与`/etc/neckline/k10.env`合并后，`DB_PATH=K10_DB_PATH=/opt/neckline/data/neckline.db`、`PARQUET_DIR=K10_PARQUET_DIR=/opt/neckline/data/parquet`。API、worker、晨晚报、采集及行情服务必须共同绑定；readiness核对实际配置内容，不能仅检查HTTP200。当前官方交易日历覆盖2026–2027。

恢复集位于`/opt/neckline/releases/v3.6.1-b93/recovery`，仅包含当前不可变制品、明确绑定和经过完整性/恢复演练的新起点快照。任何新业务写入后不得整库覆盖，先核对并保留新写及外呼状态。旧数据恢复入口已退役，禁止回退旧业务库。

生产与本地旧业务存储、本次远端暂存均已清理；未运行正式报告或真实模型/搜索/APNs试跑。发布成功不代表已证明新报告产出，实际报告应在用户明确配置并恢复后观察。
